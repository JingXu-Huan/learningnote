### Collection 接口注释中文翻译

------

这是**集合层次结构**中的根接口。一个集合代表一组对象，称为它的**元素**。有些集合允许重复元素，有些则不允许。有些集合是有序的，有些是无序的。具有明确定义的[元素遍历顺序](https://chatgpt.com/c/SequencedCollection.html#encounter)的集合，通常是 `SequencedCollection` 接口的子类型。

JDK 并**不提供该接口的直接实现**：它只提供了更具体子接口（如 `Set`、`List`）的实现。这个接口通常用于在需要**最大通用性**的场景中传递和操作集合。

> 🧺 若实现的是**包**（Bag）或**多重集**（Multiset，允许重复但无序），则应该**直接实现**此接口。

------

#### 构造器约定

所有通用的 `Collection` 实现类（通常通过其子接口间接实现 `Collection`）都应提供两个“标准”构造器：

1. 无参构造器：创建一个空集合。
2. 带 `Collection` 参数的构造器：复制传入集合中的所有元素，生成相同内容的新集合。

⚠️ 虽然接口中不能强制要求构造器，但 Java 平台库中的通用集合实现都遵循了此约定。

------

#### 可选操作说明

某些方法被标记为**可选操作**。如果集合不支持某个操作，应在相应方法中抛出 `UnsupportedOperationException`。这种方法会在接口说明中标注为“可选操作”。

------

#### 元素约束限制

某些集合对元素的内容有**限制**，例如：

- 不允许 `null` 元素；
- 限制元素类型。

尝试添加不合格的元素时，通常会抛出 `NullPointerException` 或 `ClassCastException`。甚至在仅进行查询时也可能抛出异常，或者返回 `false`，行为因实现而异。

------

#### 线程安全（同步策略）

每个集合可以自行决定其**同步策略**。若集合被一个线程修改，而另一个线程在访问它，且没有明确的同步协议，可能会出现**未定义行为**。这包括直接调用方法、作为参数传递或在遍历时使用迭代器。

------

#### equals 与 hashCode

许多集合方法依赖 `Object.equals(Object)`，例如 `contains(Object o)` 的规范为：

> 如果集合中至少有一个元素 `e` 满足 `(o == null ? e == null : o.equals(e))`，则返回 `true`。

这不意味着一定会调用 `equals`，实现可以先比较 `hashCode` 进行优化（因为不同 hashCode 的对象一定不相等）。

------

#### 自引用集合的异常风险

一些集合操作（如 `clone()`、`equals()`、`hashCode()`、`toString()`）在遇到**自引用**（即集合直接或间接包含自身）时可能会抛出异常。大多数实现不处理这种情况。

------

### 👁 视图集合（View Collections）

大多数集合自己管理元素存储。但**视图集合**不存储元素，它们依赖**底层集合（backing collection）**。

例如：

- `Collections.checkedCollection`
- `Collections.synchronizedCollection`
- `List.subList`
- `Map.entrySet`

视图集合的修改会影响到底层集合，反之亦然。虽然 `Iterator` 本身不是集合，但它们也可能修改底层集合或观察其变化。

------

### 🚫 不可修改集合（Unmodifiable Collections）

某些方法属于“修改器方法（mutator methods）”，它们改变集合的元素。若集合不支持这些操作，应抛出 `UnsupportedOperationException`。

例如，一个不支持 `add` 方法的集合：

- 若调用 `addAll`，传入一个空集合，理论上无影响；
- 但**建议仍然抛异常**，避免程序员误以为操作成功。

**不可修改集合**中的所有修改器方法都应抛出异常。其派生出的任何视图集合也必须不可修改。

⚠️ 注意：不可修改 ≠ 不可变！如果集合中的元素是可变对象，那么集合整体还是**可变的**！

------

### 🔒 不可修改视图集合（Unmodifiable View Collections）

这种集合是不可修改的**视图**，其所有查询操作会委托到底层集合，但修改操作会抛出异常。

适用于：向外暴露内部集合但不希望它被修改。

**注意：\**底层集合若被改变，视图集合也会变化。因此，它仍然不是严格的不可变集合。但如果底层集合本身不可变，那么这个视图集合就\**可以视为不可变**。

------

### 🗃 可序列化性（Serializability）

集合的可序列化性是**可选**的，所以接口本身没有声明实现 `Serializable`。但大多数实现类都支持序列化，例如 `ArrayList`、`HashMap` 等。

一些内部类如不可修改集合的实现类不是 `public`，其序列化行为需查看对应方法说明。

要注意：集合中的元素必须也支持序列化，整个集合才能真正可序列化——所以集合是**条件可序列化**。

此外，`SortedSet` 和 `SortedMap` 使用的 `Comparator` 也必须可序列化，否则整个集合不可序列化。

------

### 🌱 总结一句话

这是 Java 集合框架的核心接口，承载了灵活性、通用性、性能优化、安全性与约定规范等多重设计理念，是一颗名副其实的“接口之根” 🌳。
