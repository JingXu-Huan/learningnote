# 动态数据源使用教程
## 使用开源方案 dynamic-datasource-spring-boot-starter

> 它可以让你在运行时切换不同数据库，例如：主库（master）从库（slave）用户库（user）日志库（log）

## 使用步骤：

1. 引入依赖

SpringBoot2：

```xml
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>dynamic-datasource-spring-boot-starter</artifactId>
    <version>4.3.1</version>
</dependency>
```
SpringBoot3:
```xml
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>dynamic-datasource-spring-boot3-starter</artifactId>
    <version>4.3.1</version>
</dependency>
```

2. 在YAML中配置多个数据源：
```yaml
spring:
  datasource:
    dynamic:
      primary: master # 默认数据源
      strict: false

      datasource:
        master:
          url: jdbc:mysql://192.168.1.10:3306/master_db
          username: root
          password: 123456
          driver-class-name: com.mysql.cj.jdbc.Driver

        slave:
          url: jdbc:mysql://192.168.1.11:3306/slave_db
          username: root
          password: 123456
          driver-class-name: com.mysql.cj.jdbc.Driver
```
---
3. 使用
> 支持方法级，类级的数据源切换


* 方法级动态数据源 

```java
@Service
public class UserService {

    @DS("slave")
    public List<User> list() {
        return userMapper.selectList(null);
    }
}
```
执行时切换到slave库。
* 类级
```java
@Service
@DS("slave")
public class UserService {
}

```
整个类都走 slave。

## 多数据源的事务控制

多数据源场景里，事务控制要先分清两种模式：

1. **Spring 原生多数据源**：自己配置多个 `DataSource`，再分别配置多个 `DataSourceTransactionManager`。
2. **dynamic-datasource 路由数据源**：底层还是一个路由 `DataSource`，事务通常绑定到当前线程选中的那个数据源。

不管是哪一种，**`@Transactional` 本质上都只能保证“一个事务绑定一个数据源连接”**。也就是说：

- 同一个 `@Transactional` 方法里，尽量不要中途再切换到另一个数据源。
- 事务一旦开始，Spring 通常会把当前线程与当前数据源的连接绑定起来，后续操作会沿用这条连接。
- 如果你在同一个事务里先查 `master`，再切到 `slave` 去写，很多时候并不会得到你想要的“跨库统一回滚”。

### 1. Spring 原生多数据源怎么配事务

如果你是手动声明多个数据源，那么通常要给每个数据源配一个事务管理器，再用 `@Transactional(transactionManager = "xxxTxManager")` 指定它。

```java
@Configuration
public class DataSourceConfig {

  @Bean
  @Primary
  public DataSource masterDataSource() {
    return DataSourceBuilder.create().build();
  }

  @Bean
  public DataSource slaveDataSource() {
    return DataSourceBuilder.create().build();
  }

  @Bean
  public PlatformTransactionManager masterTxManager(
      @Qualifier("masterDataSource") DataSource dataSource) {
    return new DataSourceTransactionManager(dataSource);
  }

  @Bean
  public PlatformTransactionManager slaveTxManager(
      @Qualifier("slaveDataSource") DataSource dataSource) {
    return new DataSourceTransactionManager(dataSource);
  }
}
```

对应的业务方法要显式指定事务管理器：

```java
@Service
public class UserService {

  @Transactional(transactionManager = "masterTxManager")
  public void writeMaster(User user) {
    userMapper.insert(user);
  }

  @Transactional(transactionManager = "slaveTxManager")
  public void writeSlave(UserLog log) {
    userLogMapper.insert(log);
  }
}
```

这里的核心点是：**方法用哪个事务管理器，就只会管理哪个数据源上的连接**。`@Qualifier` 的作用是从 Spring 容器里精准拿到对应的 `DataSource`，避免多个同类型 Bean 冲突。

### 2. dynamic-datasource 场景怎么理解

如果你用的是 `dynamic-datasource-spring-boot-starter`，一般不需要自己给每个库手写一堆事务管理器，因为它已经帮你做了路由。

但要记住：

- `@DS("master")` 只是决定当前线程访问哪个库。
- `@Transactional` 只是决定这个库上的事务怎么提交或回滚。
- 一旦事务开启，再在同一个方法里切到别的库，行为通常不会像“跨库原子事务”那样工作。

### 3. 推荐做法

1. **一个事务只操作一个数据源**

```java
@Service
@DS("master")
public class OrderService {

  @Transactional
  public void createOrder(Order order) {
    orderMapper.insert(order);
    orderDetailMapper.insert(order.getDetails());
  }
}
```

2. **把不同数据源的操作拆成多个服务方法**

主流程负责编排，具体落库由各自的数据源服务独立完成。这样代码更清晰，但它不是一个真正的跨库原子事务。

3. **如果必须跨库强一致**

这已经不是普通本地事务能解决的范围了，需要上分布式事务方案，比如：

- Seata
- TCC
- Saga
- 手动补偿

### 记忆点

- `@DS` 负责“选哪个数据源”。
- `@Transactional` 负责“这个数据源上的事务怎么提交/回滚”。
- `transactionManager` 负责“这个事务到底绑定哪个数据源”。
- **两个数据库想一起原子提交**，不能只靠 `@Transactional`。
