# 😎🤷‍♂️聊聊自定义线程池

那七个核心参数都是什么？

```java
new ThreadPoolExecutors(
	...
);
```

**注意**：当核心线程数量满了之后，新提交的任务并不会直接去创建线程，而是会在阻塞队列中等待。

当队列满了之后，再有新的任务提交才会去开启临时的线程。

**但请注意：使用无界队列 `LinkedBlockingQueue`会导致临时的线程永远不会被创建。**

## 1️⃣核心线程数量`corePoolSize`

## 2️⃣最大线程数量`maximumPoolSize`

## 3️⃣空闲线程最大存活时间`keepAliveTime`

## 4️⃣时间单位`TimeUnit`

## 5️⃣任务队列`workQueue`

```java
new LinkedBlockingQueue<>();
new ArrayBlockingQueue<>(3); //可指定容量
```

## 6️⃣创建线程工厂

```java
Executors.defaultThreadFactory();
```

## 7️⃣任务拒绝策略

当**核心线程，临时的线程，阻塞队列**全满时，会触发任务的拒绝策略。

```java
new ThreadPoolExecutor.AbortPolicy(); //默认策略：丢弃任务并抛出RejectedExecutionException异常
new ThreadPoolExecutor.DiscardPolicy(); //丢弃任务，但是不抛出异常
new ThreadPoolExecutor.DiscardOldestPolicy(); //抛弃队列中等待最久的任务 然后把当前任务加入到队列中
new ThreadPoolExecutor.CallerRunsPolicy(); //调用任务的 run() 方法绕过线程池直接执行
```

## 😍如果说，我们不想丢弃任务怎么办？

我们可以将多余的任务做任务持久化，自定义拒绝策略。

将任务持久化到`mq`或者是`MySQL`中。

重写`afterExecute`方法。

```java
@Override
protected void afterExecute(Runnable r, Throwable t) {
    // 执行完任务后的自定义操作，如记录日志、失败重试、持久化等
}
```
