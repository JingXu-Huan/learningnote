## String（字符串）

### 概述

Redis 最基本的数据结构，**二进制安全**（可以存储图片、序列化的 Java 对象等），value 最大可存储 **512MB**。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `SET key value` | 设置值 | `SET name "Tom"` |
| `GET key` | 获取值 | `GET name` |
| `SETNX key value` | key 不存在时设置（等价 `SET key value NX`） | `SETNX lock "001"` |
| `SETEX key seconds value` | 设置值并指定过期时间 | `SETEX token 3600 "abc123"` |
| `MSET key1 v1 key2 v2...` | 批量设置 | `MSET a 1 b 2 c 3` |
| `MGET key1 key2...` | 批量获取 | `MGET a b c` |
| `INCR key` | 数值 +1 | `INCR count` |
| `INCRBY key step` | 数值 +step | `INCRBY count 10` |
| `DECR key` | 数值 -1 | `DECR count` |
| `APPEND key value` | 追加值 | `APPEND name "_new"` |

### 应用场景

- **缓存**：把数据库查询结果序列化为 JSON 存储
- **计数器**：文章阅读量、点赞数
- **分布式锁**：`SETNX + EXPIRE`（或 `SET key value NX EX 10`）
- **Session 共享**：用户登录信息

### 底层实现

Redis 3.2 之前使用 `SDS`（Simple Dynamic String），3.2 之后根据长度分为 `sdshdr5/8/16/32/64`。

## Hash（哈希）

### 概述

**field-value 键值对**的集合，适合存储对象。相比 String 存储序列化对象，Hash 可以对单个字段独立操作。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `HSET key field value` | 设置 hash 字段 | `HSET user:1 name "Tom" age 18` |
| `HGET key field` | 获取 hash 字段 | `HGET user:1 name` |
| `HMSET key f1 v1 f2 v2...` | 批量设置字段（已废弃，推荐 HSET） | `HMSET user:1 name "Tom" age 18` |
| `HMGET key field1 field2...` | 批量获取字段 | `HMGET user:1 name age` |
| `HGETALL key` | 获取所有字段和值 | `HGETALL user:1` |
| `HKEYS key` | 获取所有字段名 | `HKEYS user:1` |
| `HVALS key` | 获取所有值 | `HVALS user:1` |
| `HLEN key` | 获取字段数量 | `HLEN user:1` |
| `HEXISTS key field` | 判断字段是否存在 | `HEXISTS user:1 name` |
| `HINCRBY key field step` | 字段数值 +step | `HINCRBY user:1 age 1` |
| `HDEL key field1 field2...` | 删除字段 | `HDEL user:1 name age` |

### 应用场景

- **对象存储**：`user:100` → `{name: "Tom", age: 18, city: "Beijing"}`
- **商品信息**：商品 ID → `{name, price, stock, description}`
- **配置缓存**：系统配置项

### 底层实现

Redis 7.0 使用 `listpack`（紧凑列表）替代了 `ziplist`（压缩列表），当哈希字段数少、每个字段值短时使用紧凑列表，否则使用 `hashtable`。

## List（列表）

### 概述

**双向链表**，支持从两端插入/弹出元素。特点是**有序、可重复**。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `LPUSH key value...` | 左侧（头部）插入，返回列表长度 | `LPUSH list a b c` |
| `RPUSH key value...` | 右侧（尾部）插入 | `RPUSH list d e f` |
| `LPOP key` | 左侧弹出 | `LPOP list` |
| `RPOP key` | 右侧弹出 | `RPOP list` |
| `LRANGE key start stop` | 范围获取（含 stop=-1 表示末尾） | `LRANGE list 0 -1` |
| `LINDEX key index` | 按索引获取元素（0 为第一个） | `LINDEX list 2` |
| `LLEN key` | 获取列表长度 | `LLEN list` |
| `LINSERT key BEFORE/AFTER pivot value` | 在 pivot 元素前/后插入 | `LINSERT list BEFORE "b" "x"` |
| `LREM key count value` | 删除 count 个 value（count=0 全部删除） | `LREM list 2 "a"` |
| `LSET key index value` | 按索引设置值 | `LSET list 0 "new"` |
| `LTRIM key start stop` | 裁剪保留指定范围 | `LTRIM list 0 9` |

### 应用场景

- **消息队列**：`LPUSH + BRPOP`（或 `RPUSH + BLPOP`）实现轻量级队列
- **最新消息**：朋友圈最新 N 条动态，`LPUSH + LTRIM` 限制长度
- **历史记录**：用户操作历史，`LPUSH + LTRIM 0 99` 保留最近 100 条
- **数据栈**：先入后出场景

### 底层实现

快速列表（`quicklist`）：由多个 `ziplist` 节点组成的双向链表，兼顾内存效率和查询性能。

## Set（集合）

### 概述

**无序、唯一**的字符串集合，底层是 `hashtable`，查询/插入/删除复杂度 **O(1)**。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `SADD key member...` | 添加成员（已存在忽略） | `SADD tags java spring mybatis` |
| `SREM key member...` | 删除成员 | `SREM tags java` |
| `SMEMBERS key` | 获取所有成员 | `SMEMBERS tags` |
| `SISMEMBER key member` | 判断是否为成员 | `SISMEMBER tags java` |
| `SCARD key` | 获取成员数量 | `SCARD tags` |
| `SRANDMEMBER key count` | 随机获取 count 个成员（不删除） | `SRANDMEMBER tags 3` |
| `SPOP key count` | 随机弹出 count 个成员（会删除） | `SPOP tags 2` |
| `SMOVE source dest member` | 从 source 移动成员到 dest | `SMOVE tags vip_tags java` |
| `SUNION key1 key2...` | 并集 | `SUNION tags1 tags2` |
| `SINTER key1 key2...` | 交集 | `SINTER tags1 tags2` |
| `SDIFF key1 key2...` | 差集（key1 有 key2 没有） | `SDIFF tags1 tags2` |
| `SUNIONSTORE/SINTERSTORE/SDIFFSTORE` | 将运算结果存入新 key | `SINTERSTORE result key1 key2` |

### 应用场景

- **标签系统**：用户标签、文章分类
- **去重统计**：访问 IP 记录（`SADD + SCARD`）
- **抽奖**：`SRANDMEMBER` 随机抽奖
- **关注/粉丝集合**：共同关注（`SINTER`）

## ZSet（有序集合）

### 概述

**每个元素关联一个分数 score**，按 score 排序，支持范围查询。特点：**唯一、有序**。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `ZADD key score member` | 添加成员及分数 | `ZADD leaderboard 100 "Tom"` |
| `ZSCORE key member` | 获取成员分数 | `ZSCORE leaderboard "Tom"` |
| `ZRANGE key start stop` | 按索引升序获取（withscores 可带分数） | `ZRANGE leaderboard 0 9` |
| `ZREVRANGE key start stop` | 按索引降序获取 | `ZREVRANGE leaderboard 0 9` |
| `ZRANGEBYSCORE key min max` | 按分数范围升序获取 | `ZRANGEBYSCORE leaderboard 80 100` |
| `ZREVRANGEBYSCORE key max min` | 按分数范围降序获取 | `ZREVRANGEBYSCORE leaderboard 100 80` |
| `ZRANK key member` | 获取升序排名（0 为最低分） | `ZRANK leaderboard "Tom"` |
| `ZREVRANK key member` | 获取降序排名 | `ZREVRANK leaderboard "Tom"` |
| `ZINCRBY key step member` | 分数 +step | `ZINCRBY leaderboard 10 "Tom"` |
| `ZCARD key` | 获取成员数量 | `ZCARD leaderboard` |
| `ZCOUNT key min max` | 统计分数范围内的成员数 | `ZCOUNT leaderboard 80 100` |
| `ZREM key member...` | 删除成员 | `ZREM leaderboard "Tom"` |
| `ZUNIONSTORE dest n key1 key2...` | 并集存储 | `ZUNIONSTORE result 2 zset1 zset2` |
| `ZINTERSTORE dest n key1 key2...` | 交集存储 | `ZINTERSTORE result 2 zset1 zset2` |

### 应用场景

- **排行榜**：`ZADD` 添加分数，`ZREVRANGE` 获取 Top N
- **延时队列**：分数为执行时间戳，`ZRANGEBYSCORE` 获取到期任务
- **实时排序**：热搜榜单、热门商品排序
- **权重队列**：用户活跃度排序

### 底层实现

同时使用 `ziplist`（元素少时）和 `skiplist + hashtable`（元素多时）。跳表保证有序，Hashtable 保障 O(1) 的分数查询。

## Bitmap（位图）

### 概述

Redis 的 Bitmap 是 String 类型的扩展，支持按位操作。**每一位（bit）只存储 0 或 1**，可以用极小的空间存储大量状态信息。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `SETBIT key offset value` | 设置某位的值（0 或 1） | `SETBIT user:login:2024 10086 1` |
| `GETBIT key offset` | 获取某位的值 | `GETBIT user:login:2024 10086` |
| `BITCOUNT key` | 统计位为 1 的数量 | `BITCOUNT user:login:2024` |
| `BITCOUNT key start end` | 统计指定字节范围的 1 数量 | `BITCOUNT user:login:2024 0 10` |
| `BITOP AND/OR/XOR/NOT dest key...` | 位运算 | `BITOP AND result key1 key2` |
| `BITPOS key bit start end` | 查找第一个指定值的位 | `BITPOS user:login:2024 0` |
| `BITFIELD key GET/SET/INCRBY` | 位域操作（批量位操作） | `BITFIELD bits GET u8 0` |

> offset 从 0 开始，位偏移量。`SETBIT` 和 `GETBIT` 的 offset 可超过字节边界。

### 应用场景

- **用户签到**：`SETBIT sign:2024:user:100 16 1`（2024年第17天签到）
- **在线状态**：用户 ID 作为 offset，1=在线，0=离线（上限 2^32 用户）
- **活跃用户统计**：`BITCOUNT` 统计当日活跃数
- **布隆过滤器**（简化版）：多 bit 数组叠加

### 存储计算

假设统计 1 亿用户的登录状态：`(100000000 / 8) / 1024 / 1024 ≈ 12MB`

| 用户规模 | Bitmap 占用 |
| --- | --- |
| 1 万 | 1.25KB |
| 100 万 | 125KB |
| 1 千万 | 1.25MB |
| 1 亿 | **12.5MB** |

## HyperLogLog

### 概述

**概率算法**，用于**极小空间**统计集合中**不重复元素的数量**（基数），标准误差约 **0.81%**。不存储实际元素，只存储概率统计数据。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `PFADD key element...` | 添加元素 | `PFADD uv:2024:06:16 "user1" "user2"` |
| `PFCOUNT key...` | 估算基数（可传多个 key 合并） | `PFCOUNT uv:2024:06:16` |
| `PFMERGE dest key1 key2...` | 合并多个 HyperLogLog 到 dest | `PFMERGE uv:month uv:2024:06:16 uv:2024:06:17` |

### 应用场景

- **UV 统计**：网站日活/周活/月活独立访客数
- **推荐系统**：统计点击/曝光去重人数
- **实时看板**：大屏数据实时统计

### 存储计算

每个 HyperLogLog 只占 **12KB**，无论统计多少元素。

| 方式 | 100 万用户空间 | 10 亿用户空间 |
| --- | --- | --- |
| Hash/Set | ~100MB | ~100GB |
| HyperLogLog | **12KB** | **12KB** |

> 实际使用中，如果允许 1% 以内的误差，HyperLogLog 是最优解。

## GEO（地理坐标）

### 概述

Redis GEO 基于 **ZSet** 实现，存储地理位置坐标（经度、纬度），支持计算两点间距离、范围内成员等操作。

### 常用命令

| 命令 | 说明 | 示例 |
| --- | --- | --- |
| `GEOADD key longitude latitude member` | 添加坐标 | `GEOADD cities 116.40 39.90 "Beijing"` |
| `GEOADD key (longitude latitude member)...` | 批量添加 | `GEOADD cities 121.47 31.23 "Shanghai" 113.26 23.13 "Guangzhou"` |
| `GEOPOS key member...` | 获取成员坐标 | `GEOPOS cities "Beijing"` |
| `GEODIST key member1 member2 [unit]` | 计算距离（unit: m/km/mi/ft） | `GEODIST cities "Beijing" "Shanghai" km` |
| `GEORADIUS key longitude latitude radius unit [OPTIONS]` | 查询范围内成员 | `GEORADIUS cities 116.40 39.90 100 km WITHDIST ASC` |
| `GEORADIUSBYMEMBER key member radius unit [OPTIONS]` | 以某成员为中心查询范围 | `GEORADIUSBYMEMBER cities "Beijing" 100 km` |
| `GEOHASH key member...` | 获取 geohash 字符串（11位） | `GEOHASH cities "Beijing"` |

### OPTIONS 选项

| 选项 | 说明 |
| --- | --- |
| `WITHDIST` | 返回距离 |
| `WITHCOORD` | 返回坐标 |
| `COUNT n` | 限制返回数量 |
| `ASC / DESC` | 升序/降序 |
| `STORE key` | 结果存入指定 key（须配合 `GEORADIUS` 使用） |
| `WITHHASH` | 返回 52 位 geohash 原始值 |

### 应用场景

- **附近的人/商铺**：LBS 应用查询周边商家
- **配送范围**：骑手位置与店铺距离计算
- **城市距离**：两城市间距离查询
- **打卡地点校验**：判断用户是否在指定范围内

### 注意事项

- `GEOADD` 会覆盖已有成员的坐标
- 超过两极和日期变更线（经度 ±180°）的坐标无法存储
- 删除成员用 `ZREM`（因为底层是 ZSet）

## 总结对比

| 数据结构 | 特点 | 典型场景 | 复杂度 |
| --- | --- | --- | --- |
| String | 二进制安全，简单 KV | 缓存、计数器、锁 | O(1) |
| Hash | field-value，适合对象 | 对象存储、配置 | O(1) |
| List | 有序、可重复，双向链表 | 队列、消息流、历史记录 | O(1)~O(N) |
| Set | 无序、唯一，hashtable | 标签、好友、抽奖 | O(1) |
| ZSet | 唯一、有分数、可排序 | 排行榜、延时队列 | O(log N) |
| Bitmap | 位操作，状态压缩 | 签到、在线状态、UV | O(1) |
| HyperLogLog | 概率算法，基数统计 | UV 统计、去重计数 | O(1) |
| GEO | 地理位置，距离计算 | 附近的人、距离查询 | O(log N + M) |

> M 为返回的成员数量
