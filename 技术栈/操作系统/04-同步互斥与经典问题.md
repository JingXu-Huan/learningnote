# 04 同步、互斥与经典问题

[返回教程目录](操作系统教程.md) · [下一章：死锁](05-死锁与银行家算法.md)

## 本章目标

识别共享资源上的竞态，区分互斥和同步，理解信号量与条件变量，并推演经典协作问题。

## 1. 为什么共享数据会出错

共享计数器初始为 10，两位工作人员都要让它增加 1。

可能发生：A 读到 10；B 也读到 10；A 写回 11；B 写回 11。最终结果是 11，而期望是 12。

这里的问题是“读、计算、写回”作为整体没有得到保护。**单核也可能出现竞态**：任务在操作中途切换，就能产生上述交错。

竞态条件意味着结果依赖任务交错顺序。临界资源是需要协调访问的共享资源；临界区是访问它的那段执行过程。

## 2. 互斥与同步

- **互斥**：同一时刻限制进入临界区的任务数量，典型情况只允许一个。
- **同步**：任务按所需顺序协作，例如消费者必须等到生产者提供数据。

“不能同时修改库存”是互斥；“库存为空时先等补货”是同步。一个场景可以同时需要两者。

教材常要求临界区管理满足：空闲让进、忙则等待、有限等待，以及适用阻塞方案中的让权等待。自旋锁会忙等，因此不能把“所有正确锁都让出 CPU”作为统一标准。

## 3. 常见同步工具

| 工具 | 解决的主要问题 | 关键理解 |
| --- | --- | --- |
| 互斥锁 Mutex | 保护临界区 | 通常具有所有权，由持锁者释放 |
| 自旋锁 | 很短临界区的等待 | 等待时反复检查，消耗 CPU |
| 计数信号量 Semaphore | 管理一定数量的资源或许可 | 可用于资源计数和事件同步 |
| 条件变量 | 等待共享状态变为符合条件 | 要配合锁和条件检查使用 |
| 读写锁 | 协调读者和写者 | 多读者可并行，写者需独占；公平性依实现而异 |
| 原子操作 | 不可分割的特定更新 | 一个变量的原子更新不等于整个业务事务原子 |

睡眠式锁适合较长等待；自旋适合临界区很短、持锁者有机会在其他核继续运行等情况。普通业务开发应优先使用成熟库，不能仅凭“自旋不用切换”判断它总是更快。

## 4. 信号量的 P / V 含义

P（wait / acquire）表示申请一个许可：有许可则继续，没有则等待。V（signal / release）表示归还许可或发出通知，必要时唤醒等待者。

两种常见表示方法：

- 非负计数模型：计数表示可用许可，等待者另行排队。
- 教材负值模型：P 后计数可为负，负值的绝对值表示等待者数量。

不要混用两种模型。考试如果要求具体 P/V 推演，按老师采用的定义计算。

## 5. 生产者与消费者：不用代码理解顺序

设缓冲区能放 N 个产品，需要三类协调信息：

| 名称 | 初值 | 作用 |
| --- | --- | --- |
| empty | N | 空位置数量 |
| full | 0 | 已有产品数量 |
| mutex | 1 | 保护缓冲区的互斥许可 |

生产者的动作顺序：**申请一个空位置 → 获取缓冲区互斥许可 → 放入产品 → 释放互斥许可 → 通知有一个产品。**

消费者的动作顺序：**等待一个产品 → 获取缓冲区互斥许可 → 取出产品 → 释放互斥许可 → 通知空出一个位置。**

为什么先申请空位置，再获取互斥许可？

如果缓冲区已满，生产者先持有 mutex，再等待 empty，消费者就无法获得 mutex 来取走产品。生产者等待消费者腾位置，消费者等待生产者放锁，形成死锁。

真实系统还要处理取消、异常和退出时许可的归还；期末经典题通常先假设每个动作正常完成。

## 6. 条件变量：通知不等于条件已经永远成立

线程等待“队列非空”时，应在持锁情况下检查条件。条件不满足，则进行等待：释放相关锁并进入等待；被唤醒后重新取得锁，再检查条件。

为什么必须重新检查？因为可能有伪唤醒，也可能另一个消费者先取走产品。通知只是“情况可能有变化”，共享状态本身才决定能否继续。

**休眠一秒不等于正确同步。** 系统负载变化会使任务时序改变，固定延时不能保证先后关系。

## 7. 读者写者与哲学家

### 读者写者

多个读者可以一起读取，但写者需要独占。问题不仅是“是否互斥”，还包括公平性：读者不断进入可能使写者饥饿；一直优先写者也可能让读者长期等待。

### 哲学家进餐

每人都先拿左边筷子，再等右边筷子，可能形成一个循环等待圈。

可行思路：按统一编号顺序取筷子；限制同时尝试取筷子的人数；或由协调者一次批准获取两支。每种方案都应检查是否有饥饿，不能只证明“不会死锁”。

## 8. 线程安全的业务边界

假设“检查库存大于 0”和“库存减 1”分别都是线程安全的操作，把两步放在一起仍可能超卖。因为两个人都可能通过检查，再分别扣减。

应保护的是完整业务不变量：**库存不能变负**。操作系统锁、数据库事务、分布式协调各有作用范围，不能互相直接替代。

### 拓展：优先级反转

低优先级任务 L 持有锁，高优先级任务 H 等待该锁；中优先级任务 M 不断抢占 L，使 L 无法尽快释放锁，H 也被拖延。这叫优先级反转，不等于前面的循环死锁。

优先级继承可让持锁者临时继承等待者的较高优先级，促使它完成临界区并释放资源；具体支持取决于同步机制与系统。

## 自测与答案

1. 初值为 3 的计数信号量一定只能让一个任务进入吗？
2. 单核系统是否需要互斥？
3. 条件变量被唤醒后能否直接认定队列非空？
4. 生产者先持锁再等空位有什么风险？

**答案**：①不是，可以管理三个许可；②需要，任务仍可交错；③不能，应持锁重新检查；④缓冲区满时可能阻止消费者腾位置，导致死锁。
