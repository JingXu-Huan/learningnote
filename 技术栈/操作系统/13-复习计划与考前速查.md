## 1. 从零开始的三周路线

每天可安排 60～90 分钟；已有基础可合并相邻天。只剩少量时间时，使用后面的七天路线。

| 时间 | 内容 | 当天产出 |
| --- | --- | --- |
| 第 1～2 天 | 01 全景、02 进程线程 | 状态图，概念比较表 |
| 第 3～4 天 | 03 调度 | 独立完成 FCFS、SJF、SRTF、RR 各一题 |
| 第 5～6 天 | 04 同步 | 讲清计数器竞态，写出生产者消费者动作顺序 |
| 第 7 天 | 复盘第一周 | 合上笔记做各章自测，整理错因 |
| 第 8～9 天 | 05 死锁 | 一个安全序列和一次请求判断 |
| 第 10～11 天 | 06 内存 | 地址转换、页表容量、TLB 时间各一题 |
| 第 12～13 天 | 07 虚拟内存 | 一张三算法推演表，解释抖动 |
| 第 14 天 | 复盘第二周 | 用自己的话讲“程序怎样访问一个地址” |
| 第 15 天 | 08 文件系统 | 索引计算、链接与持久化比较 |
| 第 16 天 | 09 I/O | 磁盘算法路径表，I/O 模型比较 |
| 第 17 天 | 10 后端场景 | 写出一个故障假设与证据清单 |
| 第 18 天 | 11 模拟卷 | 限时完成，按主题归纳失分 |
| 第 19 天 | 专项修补 | 改变题目数字，重新做薄弱主题 |
| 第 20 天 | 12 面试问答 | 录音或口述 10 道题，检查是否能接追问 |
| 第 21 天 | 综合验收 | 模拟面试 + 复述核心计算方法 |

每天的顺序：理解 30 分钟 → 手算 / 画图 20 分钟 → 口述 10 分钟 → 根据错误补读。时间比例可以调整，但不要把整段时间都花在划线和阅读。

## 2. 期末七天冲刺

| 天数 | 主要任务 | 必须会的题 |
| --- | --- | --- |
| 第 1 天 | 基础与进程 | 概念辨析、状态转换 |
| 第 2 天 | CPU 调度 | 时间线、周转、等待、响应 |
| 第 3 天 | 同步与死锁 | 信号量初值和顺序、四条件 |
| 第 4 天 | 银行家与内存 | Need、Work、安全请求、地址转换 |
| 第 5 天 | 虚拟内存 | 页面置换、缺页率、平均时间 |
| 第 6 天 | 文件与 I/O | 索引容量、SCAN / LOOK 路径 |
| 第 7 天 | 模拟与错题 | 90 分钟模拟卷，再修正步骤 |

冲刺时先对照老师的考试范围删减。时间不足，优先完成覆盖主要题型的一轮练习，不必先读全部拓展内容。

## 3. 公式速查

| 项目 | 公式或过程 | 使用条件 |
| --- | --- | --- |
| 周转时间 | 完成 − 到达 | 单位统一 |
| 带权周转 | 周转 / 服务时间 | 先逐个求，再平均 |
| 响应时间 | 首次运行 − 到达 | 首次服务，不是最终完成 |
| 等待时间 | 周转 − CPU 服务时间 | 纯 CPU、无 I/O 阻塞的经典题 |
| 银行家剩余需求 | Need = Max − Allocation | 按分量相减 |
| 安全性推演 | Need ≤ Work 后，Work += Allocation | 只选尚未完成的进程 |
| 虚拟页号 | ⌊虚拟地址 / 页大小⌋ | 按字节编址时，页大小用字节 |
| 页内偏移 | 虚拟地址 mod 页大小 | 页号、页框号从 0 开始时 |
| 物理地址 | 页框号 × 页大小 + 偏移 | 页表映射有效且权限允许 |
| 偏移位数 | log₂(页大小) | 页大小为 2 的整数幂，按字节编址 |
| 单级页表大小 | 虚拟页数 × 页表项大小 | 完整单级页表模型 |
| 缺页率 | 缺页次数 / 引用次数 | 初次装入也计缺页 |
| 平均访问时间 | Σ(路径概率 × 该路径总耗时) | 先画路径，防止遗漏或重复加时间 |
| 索引块地址数 | 块大小 / 块地址大小 | 整数且单位相同 |
| 磁头移动量 | Σ\|下一位置 − 当前位置\| | 包括题目要求计入的端点与回绕 |

单位：1 KiB=1024 B，1 MiB=1024 KiB，1 GiB=1024 MiB；1 ms=10⁶ ns。GB 和 GiB 的含义不同，按题目定义转换。

## 4. 最容易失分的十二件事

1. 把并发说成同一时刻真正执行。
2. 把阻塞解除直接画到运行，漏掉就绪。
3. 把一次系统调用说成必然切换进程。
4. 调度题只看完成时刻，忘记减到达时刻。
5. 抢占后忘记记录剩余服务时间。
6. 生产者消费者先持 mutex 再等资源，形成相互等待。
7. 银行家试分配后忘记同时更新 Available、Allocation、Need。
8. 安全性推演误把 Max 或 Need 加回 Work。
9. 把 TLB 未命中、缺页和页面置换当成一件事。
10. FIFO 命中后误改页面进入顺序，或 LRU 命中后忘记改最近访问顺序。
11. 混淆 SCAN 与 LOOK，或遗漏 C-SCAN 回绕约定。
12. 文件容量题把索引块容量当成用户数据容量，或把索引开销遗漏。

## 5. 闭卷验收清单

- [ ] 能画出五状态模型并解释每个箭头。
- [ ] 能说出进程与线程共享什么、各自拥有什么。
- [ ] 能做至少一题有不同到达时刻的抢占式调度。
- [ ] 能解释单核为什么仍有竞态。
- [ ] 能写出生产者消费者的初值和动作顺序。
- [ ] 能给出死锁四条件及一种对应的预防方法。
- [ ] 能独立找到安全序列，判断一次请求。
- [ ] 能算页号、偏移、物理地址和页表容量。
- [ ] 能解释 TLB 未命中与缺页的区别。
- [ ] 能独立推演 FIFO、LRU、OPT。
- [ ] 能做磁盘路径与索引容量计算。
- [ ] 能解释写入成功、缓存和持久化之间的关系。
- [ ] 能解释多路复用是就绪通知，而非自动完成业务。
- [ ] 能针对“CPU 不高但慢”提出证据驱动的排查步骤。

勾选条件是能独立说或做，不是觉得自己看懂了。

## 6. 错题记录模板

| 题目主题 | 原始推理 | 错因 | 正确步骤 | 换数字后是否会做 |
| --- | --- | --- | --- | --- |
| 示例：银行家 | 资源够就批准 | 漏了安全性检查 | 先检需求，再检可用，再试分配与安全性 | 待验证 |

把错因分成概念、边界、顺序、单位或计算。这样下一次复习能直接修正方法，而不是重复看完整章节。

## 7. 进一步核对与阅读

以下均为教材作者或官方文档入口。可以只读概念解释，跳过实现代码；本教程已在相应章节链接具体概念来源。

- [OSTEP：Operating Systems: Three Easy Pieces](https://pages.cs.wisc.edu/~remzi/OSTEP/)：免费在线教材，按 CPU / 内存虚拟化、并发与持久化等主题组织。
- [Microsoft：进程与线程](https://learn.microsoft.com/en-us/windows/win32/procthread/about-processes-and-threads)：核对 Windows 进程资源与线程概念。
- [Microsoft：虚拟地址空间](https://learn.microsoft.com/en-us/windows/win32/memory/virtual-address-space)：核对地址隔离与映射概念。
- [Linux：内存概念](https://cdn.kernel.org/doc/html/latest/admin-guide/mm/concepts.html)：核对缺页、页面缓存与内存回收。
- [Linux fork 手册](https://man7.org/linux/man-pages/man2/fork.2.html)：核对进程创建与写时复制。
- [Linux fsync 手册](https://www.man7.org/linux/man-pages/man2/fsync.2.html)：核对文件同步与目录项持久化的边界。
- [Linux epoll 手册](https://man7.org/linux/man-pages/man7/epoll.7.html)：核对就绪事件和触发模式。
- [Java Thread.State 文档](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Thread.State.html)：核对 JVM 线程状态，避免与操作系统状态混淆。

考试答案优先使用老师采用的概念和模型；讨论面试与工程时，明确平台和接口条件。把这两种表达对应起来，才能既会做题，也能解释实际系统。
