## 26.1 什么是路由收敛

拓扑或策略变化后，设备需要发现变化、传播信息、重新选择路径并更新转发表。

当受影响设备形成相对稳定、可用的路由状态时，可以说相关路由已经收敛。

收敛不是“所有设备时钟同时跳到一个新状态”。网络中的设备可能先后完成更新。

## 26.2 为什么切换期间可能短暂中断

假设某条链路断开：

1. 连接这条链路的设备先发现故障。
2. 其他设备尚未收到变化，仍使用旧下一跳。
3. 更新逐渐传播，各设备重新计算。
4. 新路由安装到数据面，流量恢复或明确不可达。

期间可能出现丢包、短暂环路或黑洞。

控制面算好了路径，也还需要把结果落实到实际转发状态。

## 26.3 路由环路

简单例子：

```text
R1：到 N 走 R2
R2：到 N 走 R1
```

发往 N 的分组在两者之间循环，TTL 不断减少，最后被丢弃。

TTL 能限制单个分组循环多久，但不能修复错误路由。

## 26.4 路由黑洞

黑洞指流量被送到无法继续到达目标的地方并被丢弃。它可能来自：

- 路由指向失效下一跳。
- 汇总路由覆盖了实际不可达的子网。
- 去程或回程缺少必要路由。
- 策略明确丢弃。

有的黑洞是故障，有的是管理员故意配置的丢弃路由，用于阻断流量或防止汇总形成环路。

## 26.5 汇总路由如何引发问题

假设 R1 对上游 R0 通告 `10.0.0.0/16`，但 R1 当前实际只知道 `10.0.1.0/24`。

上游发来访问 `10.0.2.10` 的流量：

- R0 根据 `/16` 把它交给 R1。
- R1 没有匹配的具体子网路由。
- 如果 R1 的默认路由又指向 R0，两者可能来回转发。

一种常见做法是在汇总设备上为汇总前缀配置丢弃路由：

```text
10.0.1.0/24 → 真实下游
10.0.0.0/16 → 丢弃
0.0.0.0/0 → R0
```

访问 `.1/24` 时，更具体路由生效；访问该汇总内其他未知子网时，丢弃项比默认路由更具体，防止返回上游。

**丢弃项避免错误循环，并不能把原本不存在的子网变成可达。**

## 26.6 非对称路由

去程和回程走不同路径，称为非对称路由。

它本身不一定是故障，普通 IP 路由允许这种情况。

但如果路径经过依赖连接状态的防火墙、NAT 或其他设备，非对称流量可能导致状态缺失和丢弃。

排查时不能只看客户端 traceroute，还应检查回程路由和相关状态设备。
