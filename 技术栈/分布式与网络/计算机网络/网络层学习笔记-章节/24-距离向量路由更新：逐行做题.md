## 24.1 先明确题目的模型

基础距离向量题通常给出：

- 当前路由表：目的网络、距离、下一跳。
- 某个邻居通告的目的网络及距离。
- 本设备到这个邻居的开销。

收到邻居 X 的通告后：

```text
经 X 到目的网络的候选距离
= 本设备到 X 的开销 + X 通告的距离
```

如果题设用 RIP 的简化跳数模型，并规定每次跨越相邻路由器增加 1，那么候选距离就是通告距离加 1。

**“加 1”来自题设中的单位开销，不能推广为所有路由算法都加 1。**

## 24.2 常见更新规则

在单条选中路由、没有额外策略的基础模型中：

| 情形 | 常见处理 |
|---|---|
| 原表没有这个目的网络 | 有效候选可作为新路由加入 |
| 原下一跳就是这次通告的邻居 | 更新该邻居对应的距离，即使变大 |
| 原下一跳是其他邻居，候选更短 | 用新候选替换原路由 |
| 原下一跳是其他邻居，候选更长 | 通常保留原路由 |
| 距离相同 | 按题设或协议规则处理，基础题常保留原项 |
| 当前下一跳通告不可达 | 不能继续把原项当作正常可用路由 |

真实实现可能保存多条候选、运行计时器并支持等价路径。做题时应先确认题目采用的简化规则。

## 24.3 为什么“同一个下一跳变远”也要更新

假设 A 原来认为：

```text
到 N 的距离是 3，下一跳 B
```

现在 B 通告自己的路径变长，A 算出的经 B 距离变成 6。

如果 A 因为“6 不如 3”就拒绝更新，仍然保留距离 3，相当于继续信任一条已经过时的信息。

原来的 3 本来就是建立在 B 的旧通告上。B 已经改变信息，A 必须更新这个来源对应的结果。

如果 A 还保存其他邻居的有效候选，再比较它们，可能改用更好的备选路径。

## 24.4 完整例题

路由器 A 当前表：

| 目的网络 | 当前距离 | 当前下一跳 |
|---|---:|---|
| N1 | 2 | B |
| N2 | 5 | C |
| N3 | 4 | D |
| N4 | 3 | B |

B 发来的通告：

| 目的网络 | B 通告的距离 |
|---|---:|
| N1 | 4 |
| N2 | 2 |
| N3 | 6 |
| N4 | 16，不可达 |
| N5 | 1 |

题设：A 到 B 开销为 1，不可达度量为 16，超过 16 的候选按 16 处理。

第一步：把 B 的通告换算成 A 经 B 的候选。

| 目的网络 | 候选距离 | 候选下一跳 |
|---|---:|---|
| N1 | 5 | B |
| N2 | 3 | B |
| N3 | 7 | B |
| N4 | 16，不可达 | B |
| N5 | 2 | B |

第二步：逐项比较。

| 目的网络 | 更新后的状态 | 原因 |
|---|---|---|
| N1 | 距离 5，下一跳 B | 原下一跳就是 B，更新该来源 |
| N2 | 距离 3，下一跳 B | 原来经 C 为 5，新候选更短 |
| N3 | 距离 4，下一跳 D | 原来经 D 更短，保留 |
| N4 | 经 B 的路由标记不可达 | 原路径失效，不可继续正常使用 |
| N5 | 距离 2，下一跳 B | 新目的网络，加入有效候选 |

N4 可能暂时保留为不可达条目，用于传播失效信息并等待清理；不能简单认为收到不可达就总是立即删除所有相关状态。[12]

## 24.5 另一个容易混淆的地方

假设：

```text
10.0.0.0/8 的距离是 2
10.1.0.0/16 的距离是 8
```

收到发往 `10.1.2.3` 的分组时，普通查表应使用 `/16`。不能因为 `/8` 距离 2 更小，就跨前缀比较后选它。

**先为各个前缀选好路由，再对业务分组进行最长前缀匹配。**
