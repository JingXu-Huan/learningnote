## 8.1 ARP 解决什么问题

在 IPv4 以太网中，知道下一跳 IP 后，还需要下一跳 MAC。

ARP，即地址解析协议，用来完成：

```text
当前链路上的 IPv4 地址 → 对应的 MAC 地址
```

ARP 工作在本地链路范围。它通常直接封装在以太网帧中，不装在 IP 数据报里。

教材对 ARP 的层次归属可能采用不同口径；理解它服务于 IP 与链路层交接，比背一个绝对层号更重要。

## 8.2 一次典型 ARP 过程

假设 A 要把帧发给同一以太网中的 B：

1. A 先查 ARP 缓存。
2. 缓存没有对应条目，A 广播 ARP 请求：“谁拥有 B 的 IP？”
3. B 收到请求，通常单播返回自己的 MAC。
4. A 缓存映射，构造帧并发送。

ARP 请求的以太网目的 MAC 是 `ff:ff:ff:ff:ff:ff`。

## 8.3 同网段与跨网段时解析谁

| 通信场景 | 通常需要 ARP 解析的对象 |
|---|---|
| 同一 IPv4 以太网子网直接通信 | 目的主机 IP |
| 通过默认网关访问远端 | 默认网关 IP |
| 路由器向另一个以太网转发 | 出口链路上下一跳 IP |

**访问远端服务器时，主机通常不会在本地 ARP 查询远端服务器的 MAC。**

## 8.4 ARP 的限制与安全问题

- 普通路由器不转发 ARP 广播。
- ARP 缓存会过期或更新。
- 传统 ARP 缺少身份认证，可能受到 ARP 欺骗影响。
- 代理 ARP 是特殊机制，不改变 ARP 通常服务于本地链路这一基本理解。
- IPv6 使用 NDP，不使用 ARP。
