## 9.1 首部长度与总长度

IPv4 首部最短 20 字节，含选项时最长 60 字节。

IHL 字段以 **4 字节**为单位：

```text
IHL = 5  → 20 字节
IHL = 6  → 24 字节
IHL = 15 → 60 字节
```

总长度字段是 16 位，表示**首部加负载的总字节数**，上限为 65535 字节。

```text
IP 负载长度 = 总长度 - 首部长度
```

## 9.2 关键字段

| 字段 | 作用 | 记忆重点 |
|---|---|---|
| Version | 标识 IP 版本 | IPv4 的值为 4 |
| IHL | IPv4 首部长度 | 单位 4 字节 |
| DSCP／ECN | 服务分类、拥塞通知相关 | 来自历史服务类型字段的演进 |
| Total Length | 整个 IP 数据报长度 | 单位字节，包含首部 |
| Identification | 辅助分片重组 | 同一原始数据报的分片具有相应关联标识 |
| Flags | 控制／说明分片 | DF、MF |
| Fragment Offset | 分片负载在原负载中的位置 | 单位 8 字节 |
| TTL | 限制分组的存活范围 | 路由器转发时减小 |
| Protocol | 指明上层协议 | TCP=6，UDP=17，ICMP=1 |
| Header Checksum | 检测首部差错 | 只覆盖 IPv4 首部 |
| Source Address | 源 IPv4 地址 | 32 位 |
| Destination Address | 目的 IPv4 地址 | 32 位 |
| Options | 可选功能 | 增加首部长度 |

## 9.3 TTL 为什么需要

如果路由配置错误产生环路，分组可能在几个路由器之间不停循环。

TTL 能让分组在有限次转发后被丢弃，避免无限循环消耗网络资源。

虽然名字是 Time To Live，实际常按跳数理解。路由器转发时至少减 1；减到 0 时丢弃，并在符合规则时返回 ICMP 超时消息。

这里的“一跳”指路由转发，不是每经过一台二层交换机就消耗一个 TTL。

## 9.4 协议号不是端口号

```text
IPv4 Protocol = 6：IP 负载交给 TCP
TCP Destination Port = 443：交给监听该端口的应用端点
```

**协议号选择上层协议，端口号在 TCP／UDP 等协议内区分应用。**

## 9.5 首部校验和为什么逐跳更新

路由器改变 TTL，IPv4 首部就变化，首部校验和需要随之更新。

这不意味着路由器必须扫描全部应用数据重新计算校验和；实现可以采用增量更新。

首部校验和不覆盖 IP 负载，也不能提供加密或身份认证。
