## 21.1 为什么路由器不使用 MAC 地址进行互联网路由

IP 前缀能表达网络层位置并支持聚合，而以太网 MAC 主要承担本地链路交付。不同网络还可能采用不同链路技术。

如果仅凭普通 MAC 地址为每个终端维护全球路由，缺少 IP 前缀这种网络聚合结构，难以扩展。

## 21.2 同网段通信一定不经过路由器吗

在普通直连以太网场景中，它通常不经过路由转发；但帧可能通过家用路由器设备内部的交换模块。

**经过“路由器这台设备”和经过“网络层路由功能”是两个概念。**

代理 ARP、特殊路由、隧道和隔离策略也可能改变简单场景。

## 21.3 路由器知道完整路径吗

转发通常只需要知道下一跳和出口。链路状态协议可能提供较广的拓扑信息，但数据面不要求每个分组携带完整路径。

## 21.4 每个 IP 分组都走同一条路径吗

不保证。路由变化和负载分担会改变路径。

许多 ECMP 实现按流哈希，以减少同一流乱序，但不能把它当成 IP 层的顺序保证。

## 21.5 TTL 减到 0 之后谁重传

路由器丢弃分组并可能返回 ICMP 超时。IP 不重传；TCP 或应用可以按照自己的机制重试。若根本问题是路由环路，重试本身未必能解决。

## 21.6 网关一定是 .1 吗

不是。常规子网中任意合适的可分配地址都可配置给网关接口，`.1` 或末尾地址只是常见习惯。

## 21.7 /24 是不是 24 台主机

不是。它表示 24 位网络前缀，剩余 8 位，共 256 个地址，常规可分配 254 个。

## 21.8 IP 地址以 .0 或 .255 结尾就不能分配吗

不能只看最后一字节。

例如 `192.168.1.0/23` 是 `192.168.0.0/23` 内的普通地址，不是这个 `/23` 的网络地址；`192.168.0.255` 也不是该块的广播地址。

是否为网络／广播地址，要结合前缀判断。

## 21.9 ARP、DNS、NAT 的区别

| 机制 | 主要解决的问题 |
|---|---|
| DNS | 域名对应哪些记录，如 IP 地址 |
| ARP | IPv4 本地链路下一跳的 MAC 是什么 |
| NAT／NAPT | 通过设备时如何转换地址／端口 |
| 路由 | 发往目标前缀的流量下一跳在哪里 |

## 21.10 ping 通了为什么网页仍打不开

ping 只验证相应 ICMP 交互。网页还涉及 DNS、TCP／QUIC、TLS、端口开放和应用服务。

## 21.11 NAT 会改变哪些信息

取决于转换类型，可以改变源／目的 IP，NAPT 还可能改变端口等，并更新受影响的校验和。普通路由转发则通常保持源、目的 IP 不变。

## 21.12 IPv6 能完全消除访问控制问题吗

不能。即使地址可被路由，仍需考虑防火墙、服务监听、访问策略和网络路径。

## 21.13 二层交换机和路由器的核心区别

- 普通二层交换机：依据目的 MAC 等信息在二层范围内转发帧。
- 路由器：依据网络层地址等信息跨网络转发分组。
- 三层交换机：可以同时具备交换与 IP 路由功能。

不能单凭设备外壳或名字判断某个分组使用的是哪一种转发功能。
