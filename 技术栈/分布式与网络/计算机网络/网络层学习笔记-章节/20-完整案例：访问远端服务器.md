## 20.1 场景

假设：

```text
客户端：192.168.1.10/24
默认网关：192.168.1.1
网关外侧示例地址：198.51.100.7
服务器示例地址：203.0.113.20
服务器 TCP 端口：443
```

以下采用客户端直连、网关执行 NAPT、普通 IPv4 路由的简化模型；文档示例地址不是可实际访问的公网服务。

## 20.2 按步骤理解

**第一步：获得目标 IP。**

如果输入域名，应用通常先通过 DNS 等方式获得目标 IP。DNS 是应用层协议，不是网络层的地址解析协议 ARP。

**第二步：形成要发送的分组。**

在 TCP HTTPS 场景中，会先发送建立 TCP 连接所需的报文。网络层将 TCP 段封装在 IP 数据报中。

**第三步：客户端查路由。**

服务器不在本地 `/24` 子网中，假设没有更具体路由，则选择默认网关 `192.168.1.1`。

**第四步：获取第一跳 MAC。**

客户端查询网关的 ARP 缓存映射，必要时发送 ARP 请求。

**第五步：发送第一跳以太网帧。**

| 字段 | 第一跳内容 |
|---|---|
| 源 MAC | 客户端 MAC |
| 目的 MAC | 网关 LAN 接口 MAC |
| 源 IP | 192.168.1.10 |
| 目的 IP | 203.0.113.20 |

**第六步：网关处理并向外转发。**

网关执行路由查找、TTL 处理及 NAPT 等操作，按照出口链路要求重新封装。

NAPT 后，源端点可能从 `192.168.1.10:50000` 变成 `198.51.100.7:40001`。

**第七步：沿途路由器逐跳转发。**

每台路由器依据自己的转发信息选择下一跳；它不必掌握整个通信的应用内容。

**第八步：目标网络交付。**

最后一跳路由器若通过以太网直接连接目标网络，会解析目标主机 MAC 并发送帧。

**第九步：目标主机上交数据。**

目标主机处理 IP，再根据协议号交给 TCP，TCP 再按端口和连接信息交给相应应用端点。

**第十步：回复返回。**

服务器按自身路由发送回复。到达 NAT 网关后，设备依据映射状态把目的端点还原为内网客户端端点。

去程与回程不保证经过完全相同的路由路径。

## 20.3 一个需要记牢的关系

**远端目的 IP 决定路由方向；当前下一跳决定当前链路的目的 MAC。**
