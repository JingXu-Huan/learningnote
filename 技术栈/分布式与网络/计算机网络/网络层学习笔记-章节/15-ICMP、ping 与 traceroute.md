## 15.1 ICMP 的作用

ICMP，即互联网控制报文协议，用于差错报告和网络诊断。

ICMPv4 封装在 IPv4 数据报中，IPv4 协议号为 1。它不使用 TCP／UDP 端口。

ICMP 报告问题，但不会自动把 IP 变成可靠协议。

## 15.2 常见 ICMPv4 报文

| 类别 | 报文 | 用途 |
|---|---|---|
| 查询／应答 | Echo Request | ping 请求 |
| 查询／应答 | Echo Reply | ping 应答 |
| 差错 | Destination Unreachable | 目的不可达等 |
| 差错 | Time Exceeded | TTL 耗尽、重组超时等 |
| 差错 | Parameter Problem | 首部参数问题 |
| 控制 | Redirect | 特定条件下提示更合适的下一跳 |

通常不会对 ICMP 差错报文再生成 ICMP 差错，广播／组播和非首分片等情形也有差错反馈限制，避免引发反馈风暴。

## 15.3 ping 如何工作

1. 发送 ICMP Echo Request。
2. 目标允许响应时返回 Echo Reply。
3. 发送方统计往返时间、丢包等。

**ping 的时间是 RTT，即往返时间，不是单程延迟。**

ping 成功说明相应 ICMP 交互可达，并不保证 HTTPS、数据库等应用正常。

ping 失败也不一定说明主机关闭：目标或中间设备可能过滤 ICMP。

## 15.4 traceroute 如何发现路径

核心是逐步增加 TTL／Hop Limit：

1. TTL=1，通常在第一个路由器耗尽，收到超时反馈。
2. TTL=2，通常在第二个路由器耗尽。
3. 逐渐增大，直到目标或停止条件。

不同实现的探测报文不同：

- 常见 Unix traceroute 使用 UDP 探测。
- Windows tracert 通常使用 ICMP Echo。
- 也有使用 TCP 的方式。

终点如何被识别，取决于探测类型。例如 UDP 探测可能收到端口不可达，ICMP 探测可能收到 Echo Reply。

## 15.5 如何理解星号和路径变化

- `*` 常表示探测超时，没有收到对应反馈。
- 原因可能是过滤、限速、丢包或设备不回应。
- 中间跳没有回应，不代表它没有转发后续业务流量。
- ECMP、路由变化和回程差异可能影响结果。
- 每一跳显示的 RTT 包含去程与该设备回复的回程，不能直接相减来精确得到链路延迟。
