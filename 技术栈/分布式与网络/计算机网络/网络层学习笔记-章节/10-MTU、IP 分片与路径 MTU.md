## 10.1 MTU 是什么

MTU，即最大传输单元，表示某接口／链路能够承载的最大网络层分组大小。

普通以太网常见 MTU 是 1500 字节，但不是所有网络都相同。

当以太网 MTU 为 1500 时，通常意味着：

```text
IP 首部 + IP 负载 <= 1500 字节
```

以太网首部和帧尾不计入这个 IP MTU。

## 10.2 为什么需要分片

一个 IP 数据报可能在较大 MTU 的链路上发送，却遇到较小 MTU 的出口链路。

在 IPv4 中，如果允许分片，源主机或沿途路由器可以把数据报拆成多个分片。[1]

常规 IP 转发中的分片由最终目的主机重组，不是每经过一个路由器都先重组再拆分。

## 10.3 DF、MF 与片偏移

- `DF=1`：禁止分片。若数据报超过出口 MTU，路由器不能把它拆开转发。
- `MF=1`：后面还有分片。
- `MF=0`：没有后续分片；可能是最后一个分片，也可能是未分片数据报。
- 片偏移：当前分片负载在原始负载中的位置，单位 8 字节。

**除最后一个分片外，分片负载长度必须是 8 的整数倍。**

重组不能只看 Identification，还需要结合源地址、目的地址、协议等识别对应数据报。

## 10.4 分片计算例题

已知：

- 原 IPv4 数据报总长度：4000 字节。
- 首部：20 字节，无选项。
- 出口 MTU：1500 字节。
- 允许分片，假设各分片首部都是 20 字节。

第一步：求原始负载长度。

```text
4000 - 20 = 3980 字节
```

第二步：求普通分片最大负载。

```text
最大负载 = floor((1500 - 20) / 8) × 8
         = 1480 字节
```

第三步：分配负载并计算偏移。

| 分片 | 负载长度 | 分片总长度 | 片偏移字段 | MF |
|---|---:|---:|---:|---:|
| 1 | 1480 | 1500 | 0 | 1 |
| 2 | 1480 | 1500 | 1480/8 = 185 | 1 |
| 3 | 1020 | 1040 | 2960/8 = 370 | 0 |

检查：

```text
负载合计：1480 + 1480 + 1020 = 3980
分片总长度合计：1500 + 1500 + 1040 = 4040
```

比原来的 4000 多出 40 字节，是因为从一个首部变成了三个首部。

## 10.5 分片的代价

- 每个分片增加首部开销。
- 接收方需要保存状态并等待重组。
- 任一必要分片丢失，整个原数据报就无法完整重组。
- TCP 可能重传相关数据，IP 本身不重传丢失分片。
- 防火墙、NAT 等设备可能对分片施加限制。

因此，实际通信通常希望避免不必要的 IP 分片。

## 10.6 路径 MTU 与 PMTUD

路径 MTU，即一条路径上各链路 MTU 中的最小值。

传统 IPv4 路径 MTU 发现的一种方式：

1. 发送带 `DF=1` 的数据报。
2. 某路由器发现分组太大，丢弃并返回 ICMP“需要分片”消息。
3. 发送方根据反馈减小分组大小。

若相关 ICMP 被过滤，可能出现“小包正常、大包卡住”的路径 MTU 黑洞。还有通过探测和上层确认实现的其他 MTU 发现机制。

IPv6 的重要差异是：**中间路由器不分片**。过大的分组会引发 ICMPv6 Packet Too Big 反馈；需要分片时由源节点处理。[2]

## 10.7 MTU 与 MSS 的区别

- MTU：最大网络层分组大小。
- MSS：一个 TCP 段承载的最大 TCP 数据字节数，不包括 TCP 和 IP 首部。

在 MTU=1500、IPv4 首部 20 字节、TCP 首部 20 字节且没有额外开销的简化条件下：

```text
MSS = 1500 - 20 - 20 = 1460
```

IP／TCP 选项、隧道封装和路径 MTU 等会影响实际可发送的数据大小。
