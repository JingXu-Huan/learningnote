## 1.1 从“相邻设备”到“跨网络通信”

链路层负责一段链路上的数据传输。例如，同一个以太网中的主机通过交换机交换帧。

但互联网由大量不同的网络连接而成。你的电脑和远端服务器可能隔着家庭网络、运营商网络、骨干网络和数据中心网络。

**网络层要解决的是：如何把分组从源主机，经由多个网络，送到目的主机。**

它的主要工作包括：

- **寻址**：用 IP 地址标识网络中的接口，帮助确定目的位置。
- **路由选择**：学习网络可达性，计算或选择路径。
- **分组转发**：根据当前转发表，决定分组下一跳和出口。
- **适应不同链路**：处理 MTU 差异等问题。
- **控制与诊断**：借助 ICMP 等协议报告差错。

## 1.2 网络层在协议栈中的位置

| 层次 | 代表内容 | 主要回答的问题 | 常见数据单位 |
|---|---|---|---|
| 应用层 | HTTP、DNS | 应用需要交换什么信息？ | 应用消息 |
| 传输层 | TCP、UDP | 数据交给哪个应用？如何提供传输服务？ | TCP 段、UDP 数据报 |
| 网络层 | IPv4、IPv6、ICMP | 数据送往哪台主机、走哪个网络？ | IP 分组／IP 数据报 |
| 链路层 | 以太网、Wi-Fi | 当前链路上如何传输？ | 帧 |
| 物理层 | 光、电、无线信号 | 比特如何变成信号？ | 比特 |

封装关系可以写成：

```text
以太网帧 = 以太网首部 + IP 数据报 + 帧尾
IP 数据报 = IP 首部 + IP 负载
IP 负载可能是 TCP 段、UDP 数据报或 ICMP 报文等
```

**IP 地址用于网络层定位，端口用于传输层区分应用。**

## 1.3 路由选择和转发的区别

| 对比项 | 路由选择 Routing | 转发 Forwarding |
|---|---|---|
| 要做什么 | 决定有哪些可用路径，选择合适路径 | 对已经到来的分组决定出口与下一跳 |
| 关注范围 | 网络拓扑、可达性和策略 | 当前设备上的分组处理 |
| 典型依据 | 静态配置、OSPF、BGP 等 | 转发表、目的 IP 等 |
| 所属平面 | 控制平面 | 数据平面 |

可以理解为：**路由选择负责形成“导航信息”，转发负责依据导航信息处理每一个分组。**

## 1.4 IP 提供什么服务

IP 提供**无连接、尽力而为**的交付服务。[1]

- 无连接：发送 IP 分组前，不需要先建立一条 IP 连接。
- 尽力而为：网络尝试转发，但不保证一定到达。
- 不保证顺序：不同分组可能经过不同路径或受到不同延迟影响。
- 不保证不重复：上层不能依赖 IP 提供去重保障。
- 不直接提供端到端重传、流量控制与可靠交付。

**“不可靠”描述的是服务保证，而不是说 IP 经常损坏数据。**

TCP 可以在 IP 之上通过确认、重传、排序等机制提供可靠字节流。使用 UDP 的应用也可以自行实现可靠性机制，例如 QUIC。
