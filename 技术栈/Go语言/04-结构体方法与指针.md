# 04：结构体、方法与指针

> 预计：45～60 分钟<br>
> 本章目标：用 struct 建模业务数据，理解方法为什么有值接收者和指针接收者。

------

## 1. struct 是什么

Go 没有 Java 那种 class。业务数据通常由 <code>struct</code> 表示：

~~~go
type Alert struct {
    ID       int64
    DeviceID string
    Level    string
    Resolved bool
}
~~~

它可以看作一个简单的 Java POJO，但 Go 不强制要求构造器、getter、setter。

## 2. 为 struct 添加方法

~~~go
func (a *Alert) Resolve() error {
    if a.Resolved {
        return errors.New("告警已经处理")
    }
    a.Resolved = true
    return nil
}
~~~

这里的 <code>*Alert</code> 是指针接收者。它表示方法操作的是原对象，因此 <code>a.Resolved = true</code> 会真实修改调用方持有的数据。

## 3. 一个可运行例子

~~~go
package main

import (
    "errors"
    "fmt"
)

type Alert struct {
    ID       int64
    DeviceID string
    Level    string
    Status   Status
}

type Status string

const (
    StatusOpen     Status = "open"
    StatusResolved Status = "resolved"
)

func NewAlert(id int64, deviceID string, level string) Alert {
    return Alert{
        ID:       id,
        DeviceID: deviceID,
        Level:    level,
        Status:   StatusOpen,
    }
}

func (a *Alert) Resolve() error {
    if a.Status == StatusResolved {
        return errors.New("告警已经处理")
    }
    a.Status = StatusResolved
    return nil
}

func main() {
    alert := NewAlert(1, "dorm-1-101", "high")
    if err := alert.Resolve(); err != nil {
        fmt.Println("处理失败：", err)
        return
    }
    fmt.Printf("%+v\n", alert)
}
~~~

## 4. 什么时候用指针接收者

优先使用指针接收者的情况：

- 方法需要修改对象。
- struct 较大，复制成本高。
- struct 内含 <code>sync.Mutex</code> 等不可复制的字段。

值接收者适合小型、只读的值对象。实际项目中，同一个类型的方法接收者尽量保持一致。

## 5. Java 对照

| Java | Go |
| --- | --- |
| class | struct |
| 实例方法 | 带接收者的方法 |
| this | 接收者变量，例如 a |
| new Alert() | Alert{}、&Alert{} 或构造函数 |
| setter 修改字段 | 指针接收者方法修改字段 |

## 6. 动手练习

1. 给 Alert 增加 <code>Message</code> 字段。
2. 把 <code>Resolve</code> 改成只允许 open → resolved。
3. 再调用一次 <code>Resolve</code>，确认会得到错误。

## 7. 常见坑

- 方法要修改对象却使用值接收者，修改只发生在副本上。
- 不要复制含 Mutex 的 struct。
- Go 倾向组合而不是继承；下一步先学集合，再学接口和组合。
