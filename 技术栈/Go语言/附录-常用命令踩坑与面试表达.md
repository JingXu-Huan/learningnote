## 2. 最容易踩的坑

1. <code>:=</code> 声明新变量，<code>=</code> 给已有变量赋值。
2. nil slice 可以 append，nil map 不能直接写入。
3. map 遍历顺序不稳定，也不是并发安全的。
4. 导出的字段首字母必须大写，JSON 默认编码才看得到。
5. 普通业务失败返回 error，不要随手 panic。
6. <code>defer</code> 后进先出，循环里使用要谨慎。
7. goroutine 不会自动停止；要结合 Context、channel 和 WaitGroup。
8. channel 通常由发送方关闭。
9. Context 是取消和超时控制，不是业务参数袋。
10. Go 更重视简单、显式、可读，不需要照搬 Java 的所有分层和设计模式。

## 4. 面试表达模板

### 为什么从 Java 转 Go

> 我已经具备 API、数据库、缓存和工程化基础，转 Go 的重点不是重学后端问题，而是掌握显式错误处理、组合式设计、Context 和并发治理。我会先用标准库完成一条 REST + MySQL + 测试链路，再按需求选择 Gin、Redis 或 gRPC。

### Go interface 和 Java 有什么不同

> Java 通常显式 implements 接口；Go 只要方法集满足接口就自动实现。实际设计里我会让接口保持小、靠近使用方，使业务层依赖能力而不是具体实现，也方便测试时替换 fake。

### 为什么要传 context.Context

> Context 用来沿调用链传递取消和超时。HTTP Handler 从 r.Context() 开始向 Service、Repository 和下游调用传递，客户端断开或超时后，下游调用就能及时停止，避免无效工作和 goroutine 泄漏。
