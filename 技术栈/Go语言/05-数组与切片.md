# 05：数组与切片

> 预计：45～60 分钟<br>
> 本章目标：理解 array 与 slice 的区别，能用 slice 保存一组业务数据。

------

> 本章涉及 Alert、StatusOpen 的示例，沿用第 04 章中的定义。若单独复制运行，请把对应的类型定义一起放入同一个 package。

## 1. array 和 slice 不一样

~~~go
fixed := [3]int{1, 2, 3} // array：长度属于类型的一部分
ids := []int64{101, 102} // slice：动态序列，项目中更常用
~~~

Java 开发中最常见的集合是 <code>List</code>；在 Go 里，最接近它的是 slice，而不是 array。

| 类型 | 特点 | 常见用途 |
| --- | --- | --- |
| array | 长度固定，长度是类型的一部分 | 少量固定长度的数据 |
| slice | 长度可变，支持 append | 列表、批量查询结果、请求数据 |

## 2. append 与 make

~~~go
alerts := make([]Alert, 0, 10)

alerts = append(alerts, Alert{
    ID:       1,
    DeviceID: "dorm-1-101",
    Level:    "high",
})
~~~

<code>make([]Alert, 0, 10)</code> 表示：

- 当前长度是 0。
- 预留容量 10。
- 后续可以继续 append。

nil slice 也可以直接 append：

~~~go
var alerts []Alert
alerts = append(alerts, Alert{ID: 1})
~~~

## 3. 遍历与修改

~~~go
for _, alert := range alerts {
    fmt.Println(alert.ID, alert.Level)
}

for i := range alerts {
    if alerts[i].ID == 1 {
        alerts[i].Level = "medium"
    }
}
~~~

第一种写法拿到的是元素副本，适合只读；要修改 slice 中的元素，按索引访问更稳妥。

## 4. copy：不要意外共享可变数据

slice 是对底层数组的一段描述。把 slice 赋给另一个变量，不等于复制元素：

~~~go
source := []int{1, 2, 3}
target := make([]int, len(source))
copy(target, source)

target[0] = 99
fmt.Println(source) // [1 2 3]
~~~

业务层返回内部 slice 时，必要时应复制一份，避免调用方随手修改内部状态。

<code>copy</code> 只复制当前这一层元素。如果 Alert 内部将来含有 slice、map 或指针字段，复制 Alert 后这些内部引用仍可能共享；这种场景需要按字段继续复制。

## 5. 一个小练习：筛选未处理告警

~~~go
func OpenAlerts(alerts []Alert) []Alert {
    result := make([]Alert, 0)
    for _, alert := range alerts {
        if alert.Status == StatusOpen {
            result = append(result, alert)
        }
    }
    return result
}
~~~

这段代码会在后面的小项目中反复出现：遍历、判断、把满足条件的数据 append 到新 slice。

## 6. 动手练习

1. 创建三个 Alert，放入 slice。
2. 使用 <code>range</code> 输出每条告警。
3. 写一个函数，只返回 high 级别的告警。
4. 把函数返回结果改为新 slice，确保不会影响原 slice。

## 7. 常见坑

- <code>append</code> 可能扩容并换底层数组，不要假定两个 slice 永远共享数据。
- 空 slice 不等于一定是 nil；多数业务场景下两者都可遍历、都可 append。
- 不要依赖 slice 容量做业务判断。
