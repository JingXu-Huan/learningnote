## 1. 安装与依赖管理原则

### 1.1 先建立虚拟环境

在 Windows PowerShell 中：

~~~powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
~~~

退出环境使用：

~~~powershell
deactivate
~~~

如果 PowerShell 执行策略阻止激活，也可以直接调用虚拟环境中的解释器：

~~~powershell
.\.venv\Scripts\python.exe -m pip install requests
~~~

不要依赖“当前终端碰巧指向哪个 pip”。使用 `python -m pip` 能确保安装目标与运行解释器一致。

### 1.2 按用途安装

本章示例可按需安装，不要一次性把所有库塞进每个项目：

~~~powershell
python -m pip install requests httpx
python -m pip install "pydantic>=2" pydantic-settings python-dotenv
python -m pip install pytest
python -m pip install "sqlalchemy>=2" alembic
python -m pip install numpy pandas
python -m pip install beautifulsoup4 lxml
python -m pip install typer rich
python -m pip install "pwdlib[argon2]" "pyjwt[crypto]"
~~~

数据库还需要匹配驱动，例如：

~~~powershell
python -m pip install psycopg
python -m pip install "psycopg[binary]"
python -m pip install asyncpg
~~~

- `psycopg`：PostgreSQL 同步或异步驱动，部署方式按官方说明选择。
- `asyncpg`：SQLAlchemy 异步 PostgreSQL 常见驱动。
- SQLite 驱动包含在 Python 标准库中，适合学习和轻量场景。

### 1.3 记录、锁定和升级

应用项目需要可复现依赖。无论使用 `pip-tools`、Poetry、PDM、uv 还是其他工具，都应满足：

1. 明确“直接依赖”和“传递依赖”。
2. 提交依赖声明和锁文件，不提交整个虚拟环境。
3. 在 CI 中从锁定结果全新安装。
4. 通过自动化工具定期检查安全公告和新版本。
5. 先测试再升级，不盲目在生产执行 `pip install -U`。

库项目与应用项目的锁定策略不同：库通常声明兼容范围，应用通常锁定完整解析结果。

## 2. HTTP 客户端：Requests 与 HTTPX

### 2.1 如何选择

| 需求 | 推荐 |
| --- | --- |
| 普通同步脚本、简单服务调用 | Requests |
| 同一套 API 兼顾同步与异步 | HTTPX |
| FastAPI 异步路由中发并发请求 | 复用 `httpx.AsyncClient` |
| 需要 HTTP/2 | HTTPX 并安装对应 extra |
| 只需标准库且需求很小 | `urllib.request` |

两者都成熟。选择应由调用模型决定，而不是“异步一定更高级”。

### 2.2 Requests：简洁的同步请求

~~~python
import requests

def fetch_user(user_id: int) -> dict:
    response = requests.get(
        f"https://api.example.com/users/{user_id}",
        headers={"Accept": "application/json"},
        timeout=(3.05, 10),
    )
    response.raise_for_status()
    return response.json()
~~~

`timeout=(连接超时, 读取超时)` 不是整个下载的绝对总时长。生产代码应始终设置超时，并捕获 `requests.exceptions.RequestException`：

~~~python
import requests

try:
    payload = fetch_user(1)
except requests.Timeout:
    print("上游请求超时")
except requests.HTTPError as exc:
    print("上游返回错误状态", exc.response.status_code)
except requests.RequestException as exc:
    print("网络请求失败", exc)
~~~

多个请求应复用 `Session`，以共享连接池、Cookie 和公共请求头：

~~~python
import requests

with requests.Session() as session:
    session.headers.update({"User-Agent": "learningnote/1.0"})
    first = session.get("https://api.example.com/a", timeout=10)
    second = session.get("https://api.example.com/b", timeout=10)
    first.raise_for_status()
    second.raise_for_status()
~~~

### 2.3 HTTPX：同步和异步客户端

同步用法：

~~~python
import httpx

timeout = httpx.Timeout(10.0, connect=3.0)

with httpx.Client(
    base_url="https://api.example.com",
    timeout=timeout,
    follow_redirects=False,
) as client:
    response = client.get("/users/1")
    response.raise_for_status()
    user = response.json()
~~~

异步用法：

~~~python
import asyncio
import httpx

async def fetch_users() -> list[dict]:
    timeout = httpx.Timeout(10.0, connect=3.0)
    async with httpx.AsyncClient(
        base_url="https://api.example.com",
        timeout=timeout,
    ) as client:
        responses = await asyncio.gather(
            client.get("/users/1"),
            client.get("/users/2"),
        )
        for response in responses:
            response.raise_for_status()
        return [response.json() for response in responses]

asyncio.run(fetch_users())
~~~

不要在高频循环或每个 Web 请求中反复创建客户端；应在应用生命周期中复用客户端并在关闭时释放。流式下载使用 `client.stream(...)`，并限制内容大小。

### 2.4 HTTP 客户端共同安全边界

- 超时、重试、退避和熔断是不同概念；重试只适合可安全重放的请求。
- 对 POST 等非幂等操作重试要使用幂等键或业务去重。
- 不要把用户给出的任意 URL 交给服务端请求，防止 SSRF；校验协议、域名、端口和解析后的 IP。
- 默认不记录 Authorization、Cookie、查询参数中的密钥或完整响应体。
- 自动跟随重定向可能绕过最初的域名检查，应逐跳校验。
- `response.json()` 成功不代表 HTTP 成功，先 `raise_for_status` 或检查状态码。
- TLS 校验不要为了“临时解决证书问题”长期关闭。

## 3. 数据校验：Pydantic v2

Pydantic 根据类型标注校验并转换外部数据，常用于 API 请求、配置、消息和任务输入。它保证的是“校验后的模型符合声明”，并不保证原始输入本来就是目标类型。

### 3.1 模型、字段与约束

~~~python
from typing import Annotated

from pydantic import BaseModel, ConfigDict, Field

PositiveScore = Annotated[int, Field(ge=0, le=100)]

class UserCreate(BaseModel):
    model_config = ConfigDict(
        extra="forbid",
        str_strip_whitespace=True,
    )

    username: Annotated[str, Field(min_length=3, max_length=30)]
    score: PositiveScore = 0
    tags: list[str] = Field(default_factory=list)

user = UserCreate.model_validate(
    {"username": "  jingxu  ", "score": "95"}
)
print(user.username)
print(user.model_dump())
~~~

要点：

- 可变默认值明确使用 `Field(default_factory=list)`。
- `extra="forbid"` 可发现调用方拼错或多传的字段。
- Pydantic 默认可能进行安全的类型转换；需要严格输入时使用严格模式或 `StrictInt` 等类型。
- `Annotated` 能把类型与约束组合起来并复用。

### 3.2 Pydantic v2 常用 API

| 目的 | v2 API |
| --- | --- |
| 从 Python 数据校验 | `Model.model_validate(data)` |
| 从 JSON 字符串校验 | `Model.model_validate_json(text)` |
| 转为 Python 字典 | `model.model_dump()` |
| 转为 JSON 字符串 | `model.model_dump_json()` |
| 生成 JSON Schema | `Model.model_json_schema()` |
| 复制并更新 | `model.model_copy(update={...})` |
| 配置模型 | `model_config = ConfigDict(...)` |
| 字段校验器 | `@field_validator` |
| 跨字段校验器 | `@model_validator` |

旧教程中的 `parse_obj`、`dict()`、`json()`、`copy()`、`class Config` 和 `@validator` 属于 v1 风格，新代码应使用上表 v2 API。

### 3.3 自定义校验

~~~python
from pydantic import BaseModel, field_validator, model_validator
from typing_extensions import Self

class TimeRange(BaseModel):
    start: int
    end: int

    @field_validator("start", "end")
    @classmethod
    def must_be_non_negative(cls, value: int) -> int:
        if value < 0:
            raise ValueError("时间点不能小于 0")
        return value

    @model_validator(mode="after")
    def start_must_precede_end(self) -> Self:
        if self.start >= self.end:
            raise ValueError("start 必须小于 end")
        return self
~~~

校验器应保持确定性，避免网络请求和数据库查询。业务唯一性等 I/O 校验放在服务层；否则模型构造会变慢、难测试且语义不稳定。

如果希望只依赖 Python 3.11+，`Self` 可从 `typing` 导入；本章为了兼容 Python 3.10 使用 `typing_extensions`，Pydantic 会安装它。

### 3.4 校验错误

~~~python
from pydantic import ValidationError

try:
    UserCreate.model_validate({"username": "x", "unknown": True})
except ValidationError as exc:
    for error in exc.errors():
        print(error["loc"], error["type"], error["msg"])
~~~

对外 API 不应直接暴露所有内部错误上下文，尤其不要回显秘密字段。FastAPI 会把请求模型错误转换为结构化响应，仍应统一设计错误格式。

## 4. 测试：pytest

pytest 使用普通 `assert`、自动发现和 fixture 机制，适合单元测试、集成测试和 API 测试。

### 4.1 第一个测试

~~~python
def add(a: int, b: int) -> int:
    return a + b

def test_add() -> None:
    assert add(2, 3) == 5
~~~

运行：

~~~powershell
python -m pytest
python -m pytest -q
python -m pytest tests/test_math.py::test_add
~~~

### 4.2 参数化

~~~python
import pytest

@pytest.mark.parametrize(
    ("raw", "expected"),
    [
        ("0", 0),
        ("42", 42),
        ("-3", -3),
    ],
)
def test_parse_integer(raw: str, expected: int) -> None:
    assert int(raw) == expected
~~~

参数化比复制多个近似测试更清晰，而且每组数据会独立报告。

### 4.3 fixture 与资源清理

~~~python
from collections.abc import Iterator
from pathlib import Path

import pytest

@pytest.fixture
def config_file(tmp_path: Path) -> Iterator[Path]:
    path = tmp_path / "settings.json"
    path.write_text('{"debug": true}', encoding="utf-8")
    yield path
    # tmp_path 由 pytest 管理；这里可释放其他资源

def test_read_config(config_file: Path) -> None:
    assert '"debug": true' in config_file.read_text(encoding="utf-8")
~~~

fixture 通过参数名注入。使用 `yield` 可在测试结束后清理数据库事务、客户端或临时服务。

### 4.4 异常、替换环境和日志

~~~python
import logging
import os

import pytest

def required_port() -> int:
    return int(os.environ["PORT"])

def test_invalid_port(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.setenv("PORT", "invalid")
    with pytest.raises(ValueError):
        required_port()

def test_log_message(caplog: pytest.LogCaptureFixture) -> None:
    logger = logging.getLogger("demo")
    with caplog.at_level(logging.WARNING, logger="demo"):
        logger.warning("quota is low")
    assert "quota is low" in caplog.text
~~~

常用内置 fixture：

- `tmp_path`：独立临时目录。
- `monkeypatch`：临时修改环境变量、属性和当前目录。
- `capsys`：捕获标准输出和错误输出。
- `caplog`：捕获日志。
- `request`：读取当前测试上下文，谨慎使用。

### 4.5 测试边界

- 优先测试公开行为，而不是私有实现细节。
- 外部 HTTP、时钟和随机源应通过依赖边界替换，不要让单元测试依赖真实网络。
- 数据库集成测试应隔离数据并保证回滚或重建。
- 异步测试通常搭配 `pytest-asyncio` 或 AnyIO 插件；按照插件当前文档配置事件循环模式。
- 覆盖率是线索，不是目标；高覆盖率不能替代边界、失败路径和并发行为测试。

## 5. 数据库：SQLAlchemy 2.x 与 Alembic

### 5.1 Core、ORM 与驱动的关系

- 数据库驱动负责协议连接，例如 psycopg、asyncpg。
- SQLAlchemy Core 提供 Engine、连接、事务和 SQL 表达式。
- SQLAlchemy ORM 把 Python 类映射到表，通过 Session 管理对象和事务。
- Alembic 管理数据库结构随版本演进。

SQLAlchemy 不会消除 SQL 知识，也不会自动解决索引、事务隔离、N+1 查询和锁竞争。

### 5.2 SQLAlchemy 2.x 声明式模型

~~~python
from sqlalchemy import String, create_engine, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column

class Base(DeclarativeBase):
    pass

class User(Base):
    __tablename__ = "user_account"

    id: Mapped[int] = mapped_column(primary_key=True)
    username: Mapped[str] = mapped_column(String(30), unique=True, index=True)
    display_name: Mapped[str | None] = mapped_column(String(100))

# 学习片段使用内存数据库，脚本重复运行不会残留上一次的数据。
# 真实应用使用持久数据库时，仍要依靠唯一约束并处理重复写入冲突。
engine = create_engine("sqlite:///:memory:", echo=False)
Base.metadata.create_all(engine)

with Session(engine) as session:
    with session.begin():
        session.add(User(username="jingxu", display_name="景旭"))

with Session(engine) as session:
    statement = select(User).where(User.username == "jingxu")
    user = session.scalars(statement).one()
    print(user.display_name)
~~~

这是 2.x 风格：

- 使用 `DeclarativeBase`、`Mapped[...]` 和 `mapped_column` 声明模型。
- 使用 `select(Model)` 构造查询。
- 使用 `Session.scalars` / `Session.execute` 执行。
- 使用事务上下文自动提交或回滚。

不要在新代码中照搬 `session.query(User)` 作为主要查询风格，它属于旧式 Query API。

### 5.3 Session 和事务边界

`Session` 不是全局缓存，也不适合在并发任务之间共享。典型 Web 请求使用一个短生命周期 Session：

~~~python
from collections.abc import Iterator
from sqlalchemy.orm import Session, sessionmaker

SessionFactory = sessionmaker(bind=engine, expire_on_commit=False)

def get_session() -> Iterator[Session]:
    with SessionFactory() as session:
        yield session
~~~

原则：

- 一个事务完成一个明确业务单元。
- 捕获异常后需要回滚，事务上下文能简化处理。
- 不要在持有数据库事务时执行缓慢网络调用。
- ORM 对象离开 Session 后可能出现延迟加载问题；API 输出应在明确边界转换。
- 查询列表要分页并限制最大页大小。
- 对重复查询观察 SQL，识别 N+1 并选择合适加载策略。

### 5.4 异步 SQLAlchemy

只有在整个调用链和驱动都支持异步时才使用异步引擎：

~~~python
from sqlalchemy import select
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

async_engine = create_async_engine(
    "postgresql+asyncpg://user:password@localhost/app",
    pool_pre_ping=True,
)
AsyncSessionFactory = async_sessionmaker(
    async_engine,
    expire_on_commit=False,
)

async def find_user(username: str) -> User | None:
    async with AsyncSessionFactory() as session:
        statement = select(User).where(User.username == username)
        return await session.scalar(statement)
~~~

同步驱动不会因为放进 `async def` 就变成异步。FastAPI 的路由选择与阻塞调用桥接见下一章和并发章节。

### 5.5 Alembic 初始化与迁移

安装后在项目根执行：

~~~powershell
python -m alembic init migrations
~~~

在 `migrations/env.py` 中导入模型并设置：

~~~python
from app.models import Base

target_metadata = Base.metadata
~~~

常用命令：

~~~powershell
python -m alembic revision --autogenerate -m "create user table"
python -m alembic upgrade head
python -m alembic current
python -m alembic history
python -m alembic downgrade -1
python -m alembic check
~~~

`--autogenerate` 是“生成候选迁移”，不是“自动保证正确”。每次都要审查：

- 升级和降级是否完整。
- 列重命名是否被误判为先删后加。
- 数据迁移、非空约束和默认值顺序是否安全。
- 索引、外键、枚举、数据库特有类型是否正确。
- 大表 DDL 是否长时间锁表。

生产迁移要先备份、评估锁影响并演练回滚。`Base.metadata.create_all` 适合测试或初始学习，不能替代正式迁移历史。

## 6. 数值与表格：NumPy 和 Pandas

### 6.1 NumPy：同类型多维数组

~~~python
import numpy as np

temperatures = np.array([20.5, 21.0, 23.5, 19.0], dtype=np.float64)
normalized = (temperatures - temperatures.mean()) / temperatures.std()
hot = temperatures[temperatures >= 21.0]

matrix = np.arange(12).reshape(3, 4)
column_sums = matrix.sum(axis=0)

print(normalized, hot, column_sums)
~~~

关键概念：

- `ndarray` 通常存储同一种 `dtype`，便于连续内存和向量化运算。
- `shape` 描述维度，`axis` 指定沿哪个维度聚合。
- 广播让兼容形状的数组无需显式循环即可运算。
- 切片常返回“视图”，修改它可能影响原数组；需要独立数据时显式 `copy()`。
- 向量化能减少 Python 层循环，但不意味着所有 `np.vectorize` 都会变快。
- 整数可能溢出，浮点有精度误差，必须了解 `dtype`。

数据很小、逻辑分支很多时，普通列表和循环可能更清晰，不必引入 NumPy。

### 6.2 Pandas：带标签的表格数据

~~~python
import pandas as pd

frame = pd.DataFrame(
    {
        "city": ["郑州", "郑州", "北京"],
        "usage": [12.5, 15.0, 9.0],
    }
)

summary = (
    frame.assign(high=frame["usage"].ge(12))
    .groupby("city", as_index=False)
    .agg(
        average_usage=("usage", "mean"),
        high_count=("high", "sum"),
    )
)

print(summary)
~~~

读取数据时尽量声明类型和需要的列：

~~~python
import pandas as pd

frame = pd.read_csv(
    "usage.csv",
    usecols=["device_id", "timestamp", "usage"],
    dtype={"device_id": "string", "usage": "float64"},
    parse_dates=["timestamp"],
)
~~~

常见坑：

- 不要逐行 `iterrows` 实现可向量化的运算。
- 链式赋值可能产生歧义，选择 `loc` 或 `assign`。
- 缺失值语义依赖 dtype；`None`、`NaN` 和 `pd.NA` 不完全相同。
- 大 CSV 可用 `chunksize` 分块，但超大数据还要考虑数据库、Polars、DuckDB 或分布式方案。
- Pandas 不是事务数据库，不适合承担并发写入和在线查询服务。

## 7. HTML 解析：Beautiful Soup

Beautiful Soup 负责解析和查询 HTML/XML，网络下载由 Requests 或 HTTPX 完成。

~~~python
import requests
from bs4 import BeautifulSoup

response = requests.get(
    "https://example.com",
    headers={"User-Agent": "learningnote-study/1.0"},
    timeout=10,
)
response.raise_for_status()

soup = BeautifulSoup(response.text, "html.parser")
title = soup.title.get_text(strip=True) if soup.title else None
links = [
    anchor.get("href")
    for anchor in soup.select("main a[href]")
]

print(title, links)
~~~

解析器选择：

| 解析器 | 安装 | 特点 |
| --- | --- | --- |
| `html.parser` | 标准库自带 | 无额外依赖，普通 HTML 足够 |
| `lxml` | `pip install lxml` | 通常更快，对 HTML/XML 支持好 |
| `html5lib` | `pip install html5lib` | 更接近浏览器容错规则，但较慢 |

注意：

- 不要用正则表达式解析任意 HTML。
- 动态页面的数据可能由 JavaScript 请求产生；先检查真实 API，再考虑浏览器自动化。
- 遵守 robots、网站条款、版权、隐私和访问频率限制。
- 设置超时、并发上限、缓存和指数退避。
- 外部链接仍有 SSRF 与重定向风险。
- DOM 结构会变化，选择器应有测试和失败监控。

## 8. 命令行体验：Typer 与 Rich

### 8.1 Typer：基于类型标注的 CLI

~~~python
from pathlib import Path
from typing import Optional

import typer

app = typer.Typer(no_args_is_help=True)

@app.command()
def count(
    path: Path = typer.Argument(..., exists=True, dir_okay=False),
    encoding: str = typer.Option("utf-8", help="文本编码"),
    limit: Optional[int] = typer.Option(None, min=1),
) -> None:
    lines = path.read_text(encoding=encoding).splitlines()
    typer.echo(len(lines) if limit is None else min(len(lines), limit))

if __name__ == "__main__":
    app()
~~~

运行：

~~~powershell
python cli.py --help
python cli.py .\example.txt --limit 10
~~~

Typer 适合多子命令、类型化参数和自动帮助。一个只有两三个参数的脚本，标准库 `argparse` 已经足够。

### 8.2 Rich：终端样式、表格和进度

~~~python
from rich.console import Console
from rich.table import Table

console = Console()
table = Table(title="服务状态")
table.add_column("服务")
table.add_column("状态")
table.add_row("api", "[green]healthy[/green]")
table.add_row("worker", "[yellow]starting[/yellow]")
console.print(table)
~~~

Rich 适合人类阅读的终端输出，不要把带颜色和布局的文本作为机器协议。需要管道消费时提供 JSON、CSV 或纯文本模式，并检测非交互终端。

## 9. 配置：python-dotenv 与 pydantic-settings

### 9.1 python-dotenv：给小脚本加载 `.env`

~~~python
import os
from dotenv import load_dotenv

load_dotenv()

database_url = os.environ["DATABASE_URL"]
debug = os.getenv("DEBUG", "false").lower() == "true"
~~~

`load_dotenv` 默认不覆盖已经存在的环境变量，这通常符合“部署环境优先”的预期。

### 9.2 pydantic-settings：类型化应用配置

Pydantic v2 将设置管理拆为独立包 `pydantic-settings`：

~~~python
from functools import lru_cache

from pydantic import SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        env_prefix="APP_",
        extra="ignore",
    )

    database_url: str
    jwt_secret: SecretStr
    debug: bool = False
    workers: int = 4

@lru_cache
def get_settings() -> Settings:
    return Settings()

settings = get_settings()
print(settings.workers)
print(settings.jwt_secret)  # 不会直接显示明文
~~~

对应 `.env`：

~~~dotenv
APP_DATABASE_URL=postgresql+psycopg://app:password@localhost/app
APP_JWT_SECRET=replace-with-a-long-random-secret
APP_DEBUG=false
APP_WORKERS=4
~~~

`.env` 是本地开发便利工具，不是秘密保险箱：

- 把 `.env` 加入 `.gitignore`，提交不含真实秘密的 `.env.example`。
- 生产环境优先平台密钥服务、容器 secret 或受控环境变量。
- 配置在应用启动时校验，失败应快速退出。
- 不把整个 Settings 对象或环境变量打印进日志。
- 密钥轮换时考虑旧令牌、连接池和多实例发布顺序。

## 10. 密码哈希与 JWT 选型

### 10.1 密码哈希库怎么选

| 场景 | 建议 |
| --- | --- |
| 新项目，希望简单采用推荐参数 | `pwdlib[argon2]` |
| 需要直接控制 Argon2 参数 | `argon2-cffi` |
| 兼容已有 bcrypt 哈希 | `bcrypt` |
| 老项目已经使用 Passlib | 先评估迁移，不为新项目默认引入 |
| 普通摘要、文件校验 | 标准库 `hashlib`，但不用它裸存密码 |

使用 pwdlib：

~~~python
from pwdlib import PasswordHash

password_hash = PasswordHash.recommended()

stored_hash = password_hash.hash("correct horse battery staple")
assert password_hash.verify(
    "correct horse battery staple",
    stored_hash,
)
~~~

实际系统还应：

- 只存密码哈希，不存可逆密文。
- 使用库生成随机盐，不自行设计盐格式。
- 登录失败返回统一错误，避免泄露用户是否存在。
- 配置登录限速、多因素认证和异常检测。
- 成功登录时检测旧参数并逐步重新哈希。
- 给密码设置合理最大字节长度，防止资源消耗攻击。

### 10.2 JWT 库怎么选

| 需求 | 建议 |
| --- | --- |
| 应用内签发、验证普通 JWT | PyJWT |
| RSA/ECDSA/EdDSA 等算法 | `pyjwt[crypto]` |
| 完整 OAuth 2.0 / OpenID Connect 客户端或服务端 | Authlib 或成熟身份平台 |
| 仅需要随机会话标识 | 服务端 session + `secrets`，不必用 JWT |

PyJWT 示例：

~~~python
from datetime import datetime, timedelta, timezone

import jwt

ALGORITHM = "HS256"
ISSUER = "https://api.example.com"
AUDIENCE = "learningnote-web"

def create_access_token(user_id: int, secret: str) -> str:
    now = datetime.now(timezone.utc)
    payload = {
        "sub": str(user_id),
        "iss": ISSUER,
        "aud": AUDIENCE,
        "iat": now,
        "exp": now + timedelta(minutes=15),
    }
    return jwt.encode(payload, secret, algorithm=ALGORITHM)

def decode_access_token(token: str, secret: str) -> dict:
    return jwt.decode(
        token,
        secret,
        algorithms=[ALGORITHM],
        issuer=ISSUER,
        audience=AUDIENCE,
        options={"require": ["exp", "iat", "iss", "aud", "sub"]},
    )
~~~

安全要点：

- JWT 默认是签名而非加密，载荷可被读取，不能放密码或隐私数据。
- 验证算法白名单必须由服务端固定配置，不能信任令牌头中的 `alg` 来决定。
- 验证签名之外，还要验证 `exp`、`iss`、`aud` 和业务所需的 `sub`。
- HMAC 密钥应高熵且足够长；多服务验证常考虑非对称密钥和 `kid` 轮换。
- Access Token 保持短期；刷新、撤销、登出和密钥轮换需要额外设计。
- 浏览器存储位置涉及 XSS 与 CSRF 权衡，不能由 JWT 库自动解决。
- 不要手写密码算法、JWT 编码或签名验证。

## 11. 场景选择矩阵

| 场景 | 首选 | 备选 / 说明 |
| --- | --- | --- |
| 简单同步 HTTP | Requests | HTTPX 同步客户端也可以 |
| 异步 HTTP / FastAPI 出站请求 | HTTPX AsyncClient | 复用客户端 |
| 外部数据校验与序列化 | Pydantic v2 | 简单内部记录可用 dataclass |
| 单元与集成测试 | pytest | 标准库 unittest 适合零依赖需求 |
| SQL 表达式与 ORM | SQLAlchemy 2.x | 简单 SQLite 可直接 sqlite3 |
| 数据库结构迁移 | Alembic | 必须审查生成脚本 |
| 数组和向量计算 | NumPy | 小数据使用内置容器 |
| 表格清洗与分析 | Pandas | 在线事务查询仍用数据库 |
| HTML/XML 解析 | Beautiful Soup | 高性能 XPath 可直接用 lxml |
| 类型化复杂 CLI | Typer | 简单脚本用 argparse |
| 终端美化 | Rich | 机器输出保持 JSON/纯文本 |
| 小脚本加载 `.env` | python-dotenv | 不提供类型校验 |
| 类型化应用配置 | pydantic-settings | 生产秘密来自专用设施 |
| 新项目密码哈希 | pwdlib + Argon2 | 兼容旧库需迁移计划 |
| JWT 签发验证 | PyJWT | OAuth/OIDC 用 Authlib / 身份平台 |

## 12. 依赖治理与常见坑

### 12.1 先问“标准库够不够”

以下需求通常无须第三方库：

- 简单 CLI：`argparse`。
- JSON / CSV：`json` / `csv`。
- 单次并发：`concurrent.futures` / `asyncio`。
- 路径与临时文件：`pathlib` / `tempfile`。
- 小型 SQLite 工具：`sqlite3`。

但“零依赖”也不是绝对目标。成熟第三方库能减少协议、安全和兼容性错误，关键是收益大于维护成本。

### 12.2 评估一个依赖

引入前检查：

1. 项目是否仍维护，发布和安全响应是否正常。
2. 官方文档、类型标注和测试是否完善。
3. 许可证是否满足项目要求。
4. Python 版本与操作系统是否兼容。
5. 传递依赖和二进制体积是否可接受。
6. 能否把依赖隔离在适配层，未来替换成本多大。
7. 这个功能自己实现是否会涉及协议、加密或大量边界情况。

### 12.3 不要混用不同代际教程

- Pydantic v2：使用 `model_validate`、`model_dump`、`ConfigDict`、`field_validator`。
- SQLAlchemy 2.x：使用 `select`、`Session.execute/scalars`、`Mapped`。
- 异步库：确认客户端、数据库驱动和调用链都是真异步。
- 查看搜索结果时核对文档 URL 中的版本，不复制多年前博客代码。

### 12.4 网络与数据默认不可信

- 所有外部 HTTP 请求设置超时、大小限制和状态检查。
- 数据模型限制字符串长度、列表元素数和值域。
- HTML 抓取遵守规则并防 SSRF。
- 迁移脚本和自动生成 SQL 必须人工审查。
- 密码与令牌只用成熟高层库，不自行发明算法。

### 12.5 导入和命名坑

- 不要把自己的文件命名为 `requests.py`、`pydantic.py`、`pytest.py`、`sqlalchemy.py` 或 `jwt.py`，否则可能遮蔽安装包。
- PyPI 包名与导入名可能不同：`beautifulsoup4` 对应 `from bs4 import ...`，`pyjwt` 对应 `import jwt`。
- 遇到“已安装但无法导入”先检查 `python -m pip --version` 和 `python -c "import sys; print(sys.executable)"` 是否指向同一环境。
