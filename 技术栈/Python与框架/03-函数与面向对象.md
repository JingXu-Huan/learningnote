## 1. 函数是第一等对象

函数可以赋值给变量、存入容器、作为参数传递，也可以从另一个函数返回。

```python
def add(left: int, right: int) -> int:
    return left + right


operation = add
print(operation(2, 3))

operations = {
    "+": add,
    "max": max,
}
print(operations["+"](10, 20))
```

高阶函数接收函数或返回函数：

```python
from collections.abc import Callable, Iterable


def transform(
    values: Iterable[int],
    operation: Callable[[int], int],
) -> list[int]:
    return [operation(value) for value in values]


result = transform([1, 2, 3], lambda value: value * 2)
```

`lambda` 只能包含一个表达式，适合短小的键函数或回调。逻辑稍复杂、需要文档或复用时，使用普通 `def`。

## 2. 定义函数与返回值

### 2.1 基本结构

```python
def calculate_discount(price: float, rate: float) -> float:
    """根据折扣率计算优惠后的价格。"""
    if price < 0:
        raise ValueError("price 不能为负数")
    if not 0 <= rate <= 1:
        raise ValueError("rate 必须在 0~1 之间")

    return price * (1 - rate)
```

一个良好的函数通常具备：

- 名称说明动作，参数和返回值含义稳定。
- 核心职责单一，副作用明确。
- 对重要前置条件尽早校验。
- 文档字符串解释用途、边界或不直观的约束。
- 类型提示表达静态接口，但关键业务校验仍在运行时完成。

### 2.2 `return`

`return` 立即结束当前函数。没有显式 `return`，或只写 `return`，都会返回 `None`。

```python
def find_user(user_id: int) -> dict[str, object] | None:
    if user_id <= 0:
        return None

    return {"id": user_id, "name": "Alice"}
```

不要让同一个函数在相似成功路径上返回完全不同的形状，例如有时返回列表、有时返回字符串。调用方会难以正确处理。

### 2.3 多返回值实际是元组

```python
def divide_with_remainder(number: int, divisor: int) -> tuple[int, int]:
    quotient, remainder = divmod(number, divisor)
    return quotient, remainder


quotient, remainder = divide_with_remainder(17, 5)
```

返回字段较多或业务含义复杂时，使用 `NamedTuple`、`dataclass` 或专门的结果类型，比依赖位置更清晰。

### 2.4 纯函数与副作用

纯函数只由输入决定输出，不修改外部状态，通常更容易测试：

```python
def normalize_name(name: str) -> str:
    return name.strip().casefold()
```

写文件、发送请求、修改传入对象、更新全局变量和打印输出都是副作用。副作用不是错误，但应集中在边界层并从函数名或文档中体现。

## 3. 参数系统

### 3.1 位置参数与关键字参数

```python
def create_user(name: str, age: int, active: bool = True) -> dict[str, object]:
    return {"name": name, "age": age, "active": active}


create_user("Alice", 20)
create_user(name="Alice", age=20, active=False)
create_user("Alice", age=20)
```

关键字参数提高调用处可读性，也降低参数顺序记忆成本。一旦在调用中出现关键字参数，后面不能再放普通位置参数。

### 3.2 默认参数在定义时求值

```python
def connect(host: str, port: int = 5432) -> str:
    return f"{host}:{port}"
```

默认值只在函数定义时计算一次。因此不可使用会被修改的列表、字典、集合等作为默认值：

```python
def append_log(message: str, logs: list[str] | None = None) -> list[str]:
    if logs is None:
        logs = []

    logs.append(message)
    return logs
```

`None` 是这里的哨兵。如果 `None` 本身也是合法业务值，可使用唯一对象：

```python
_MISSING = object()


def load(key: str, default: object = _MISSING) -> object:
    ...
```

### 3.3 仅限位置参数 `/`

斜杠前的参数只能按位置传递：

```python
def ratio(numerator: float, denominator: float, /) -> float:
    return numerator / denominator


ratio(10, 4)
```

适用场景：参数名称只是实现细节、API 需兼容未来改名，或模仿某些内置函数接口。业务函数不必为了“高级”而滥用。

### 3.4 仅限关键字参数 `*`

星号后的参数必须写参数名：

```python
def fetch_data(
    url: str,
    *,
    timeout: float = 5.0,
    verify_ssl: bool = True,
) -> bytes:
    ...


fetch_data("https://example.com", timeout=10.0, verify_ssl=False)
```

布尔开关、单位不明显的数值和可选配置很适合仅限关键字参数，能避免 `fetch_data(url, 10, False)` 这种难读调用。

### 3.5 任意数量位置参数 `*args`

```python
def average(*values: float) -> float:
    if not values:
        raise ValueError("至少需要一个值")
    return sum(values) / len(values)


average(10, 20, 30)
```

函数内部的 `args` 是元组。名称只是惯例，可以改名，但通常保持 `args` 便于理解。

### 3.6 任意数量关键字参数 `**kwargs`

```python
def build_profile(name: str, **attributes: object) -> dict[str, object]:
    return {"name": name, **attributes}


profile = build_profile("Alice", city="Zhengzhou", active=True)
```

函数内部的 `kwargs` 是字典。公开 API 若只接受少量已知配置，最好显式声明参数，让拼写错误被及时发现；不要把所有配置都藏进 `**kwargs`。

### 3.7 参数顺序总览

```python
def example(
    positional_only,
    /,
    positional_or_keyword,
    *args,
    keyword_only,
    **kwargs,
):
    ...
```

顺序为：仅限位置参数 → 可位置或关键字参数 → 可变位置参数 → 仅限关键字参数 → 可变关键字参数。

### 3.8 调用时解包

```python
def locate(x: int, y: int, *, label: str) -> str:
    return f"{label}: ({x}, {y})"


coordinates = (10, 20)
options = {"label": "起点"}
result = locate(*coordinates, **options)
```

解包后的参数必须满足目标签名；重复传同一参数会抛出 `TypeError`。

### 3.9 参数传递模型

Python 传递的是“对象引用的值”。函数可以重新绑定自己的局部参数名，也可以修改传入的可变对象：

```python
def rebind(values: list[int]) -> None:
    values = [100]  # 只重新绑定局部名称，不影响调用方


def mutate(values: list[int]) -> None:
    values.append(100)  # 修改共享列表，调用方可见
```

接口是否原地修改输入应明确约定。常见命名如 `sort()` 暗示原地操作，而 `sorted()` 返回新对象。

## 4. 作用域与名称解析

Python 查找名称遵循 LEGB：

1. **Local**：当前函数局部作用域。
2. **Enclosing**：外层闭包函数作用域。
3. **Global**：当前模块全局作用域。
4. **Built-in**：内置名称作用域。

```python
message = "global"


def outer() -> None:
    message = "enclosing"

    def inner() -> None:
        message = "local"
        print(message)

    inner()
```

### 4.1 赋值使名称成为局部名称

```python
count = 0


def increase() -> None:
    # print(count)  # UnboundLocalError
    count = count + 1
```

只要函数体中对 `count` 赋值，编译器就把它视为局部名称；赋值右侧读取时它尚未绑定。

### 4.2 `global`

```python
count = 0


def increase() -> None:
    global count
    count += 1
```

`global` 允许在函数中重新绑定模块级名称，但会制造隐藏依赖和测试干扰。业务状态更适合显式传参、返回，或封装进对象。

### 4.3 `nonlocal`

```python
def make_counter():
    count = 0

    def increase() -> int:
        nonlocal count
        count += 1
        return count

    return increase
```

`nonlocal` 重新绑定最近一层已有的外层函数变量，不会创建模块级变量。

### 4.4 作用域不是代码块级

`if`、`for`、`while` 和 `with` 不会创建普通局部作用域：

```python
if True:
    result = 42

print(result)
```

推导式在 Python 3 中有自己的隐式作用域，其循环变量不会泄漏到外部。

## 5. 闭包

内部函数引用外层函数变量，并在外层函数结束后继续保留这些绑定，就形成闭包。

```python
from collections.abc import Callable


def make_multiplier(factor: int) -> Callable[[int], int]:
    def multiply(value: int) -> int:
        return value * factor

    return multiply


double = make_multiplier(2)
triple = make_multiplier(3)
print(double(10), triple(10))
```

闭包适合：

- 创建带少量配置的回调。
- 隐藏小规模状态。
- 实现装饰器。

状态复杂、需要多个操作或可观测生命周期时，类通常更清晰。

### 5.1 延迟绑定

闭包按名称查找外层变量，不会自动保存创建当时的值：

```python
functions = [lambda: index for index in range(3)]
print([function() for function in functions])  # [2, 2, 2]
```

可用默认参数在每轮固定当前对象：

```python
functions = [lambda index=index: index for index in range(3)]
```

更复杂逻辑可用工厂函数，通常比技巧性 `lambda` 更容易读懂。

## 6. 装饰器

装饰器接收可调用对象并返回可调用对象，用于在不修改核心函数的前提下增加横切能力，如日志、缓存、鉴权、重试和耗时统计。

### 6.1 基本装饰器

```python
from collections.abc import Callable
from functools import wraps
from typing import Any, TypeVar

R = TypeVar("R")


def log_call(function: Callable[..., R]) -> Callable[..., R]:
    @wraps(function)
    def wrapper(*args: Any, **kwargs: Any) -> R:
        print(f"调用 {function.__name__}")
        return function(*args, **kwargs)

    return wrapper


@log_call
def add(left: int, right: int) -> int:
    return left + right
```

装饰语法：

```python
@log_call
def add(left: int, right: int) -> int:
    return left + right
```

等价于：

```python
add = log_call(add)
```

`functools.wraps()` 会保留原函数的名称、文档、注解及 `__wrapped__`，对调试、文档生成和框架反射很重要。

### 6.2 保留完整参数签名

Python 3.10+ 可用 `ParamSpec` 更准确地描述装饰器：

```python
from collections.abc import Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")


def trace(function: Callable[P, R]) -> Callable[P, R]:
    @wraps(function)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        print(function.__qualname__)
        return function(*args, **kwargs)

    return wrapper
```

### 6.3 带参数的装饰器

```python
from collections.abc import Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")


def repeat(times: int):
    if times < 1:
        raise ValueError("times 必须大于 0")

    def decorate(function: Callable[P, R]) -> Callable[P, R]:
        @wraps(function)
        def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
            result: R
            for _ in range(times):
                result = function(*args, **kwargs)
            return result

        return wrapper

    return decorate


@repeat(times=3)
def greet(name: str) -> str:
    message = f"你好，{name}"
    print(message)
    return message
```

带参数装饰器有三层：接收配置 → 接收被装饰函数 → 接收函数调用参数。

### 6.4 多个装饰器的顺序

```python
@outer
@inner
def target():
    ...
```

等价于 `target = outer(inner(target))`。装饰时从下向上应用，调用时先进入最外层包装器。

### 6.5 优先使用标准装饰器

常见内置/标准库装饰器：

- `@property`：把无参方法暴露为受控属性。
- `@classmethod`：接收类对象，常用于替代构造器。
- `@staticmethod`：放在类命名空间中的无绑定函数。
- `@functools.cache` / `@functools.lru_cache`：缓存纯函数结果。
- `@dataclass`：生成数据类样板方法。
- `@contextlib.contextmanager`：用生成器构造上下文管理器。

## 7. 迭代器与可迭代对象

### 7.1 三个概念

| 概念 | 核心协议 | 说明 |
| --- | --- | --- |
| 可迭代对象 `Iterable` | `__iter__()` 可返回迭代器 | 可被 `for` 遍历，如列表、字典、字符串 |
| 迭代器 `Iterator` | `__iter__()` 返回自身，`__next__()` 返回下一个值 | 有当前位置，通常只能向前消费一次 |
| 生成器 `Generator` | 由含 `yield` 的函数或生成器表达式创建 | 自动实现迭代器协议 |

`for` 循环大致执行：

```python
iterator = iter(iterable)

while True:
    try:
        item = next(iterator)
    except StopIteration:
        break
    else:
        process(item)
```

实际代码不要手写这种循环，示例用于理解协议。

### 7.2 自定义可迭代对象

```python
from collections.abc import Iterator


class Countdown:
    def __init__(self, start: int) -> None:
        if start < 0:
            raise ValueError("start 不能为负数")
        self.start = start

    def __iter__(self) -> Iterator[int]:
        current = self.start
        while current > 0:
            yield current
            current -= 1
```

每次调用 `iter(countdown)` 都创建新生成器，因此该对象可以重复遍历。

### 7.3 自定义迭代器

```python
from collections.abc import Iterator


class CountdownIterator(Iterator[int]):
    def __init__(self, start: int) -> None:
        self.current = start

    def __next__(self) -> int:
        if self.current <= 0:
            raise StopIteration

        value = self.current
        self.current -= 1
        return value
```

迭代器带消费状态，一旦耗尽，再次遍历通常不会重新开始。需要重用时让容器的 `__iter__()` 每次返回新迭代器。

### 7.4 `iter(callable, sentinel)`

`iter()` 的双参数形式会重复调用无参函数，直到返回哨兵值：

```python
from functools import partial


with open("data.bin", "rb") as file:
    for chunk in iter(partial(file.read, 8192), b""):
        process(chunk)
```

这适合分块读取，避免一次性把整个文件加载到内存。

## 8. 生成器

### 8.1 `yield` 按需产生值

```python
from collections.abc import Iterator


def fibonacci(limit: int) -> Iterator[int]:
    left, right = 0, 1
    while left <= limit:
        yield left
        left, right = right, left + right
```

调用生成器函数不会立即执行函数体，而是返回生成器对象。每次 `next()` 从上次暂停的 `yield` 后继续，直到函数结束并抛出 `StopIteration`。

### 8.2 惰性流水线

```python
numbers = (int(line) for line in lines if line.strip())
positive = (number for number in numbers if number > 0)
total = sum(positive)
```

优势：

- 只在需要时计算。
- 可处理很大甚至无限的数据流。
- 将读取、转换、筛选与聚合拆为阶段。

代价：

- 通常只能消费一次。
- 错误可能推迟到迭代时才出现。
- 无法直接通过下标随机访问。
- 生成器链过深会增加调试难度。

### 8.3 `yield from`

```python
from collections.abc import Iterable, Iterator


def flatten(groups: Iterable[Iterable[int]]) -> Iterator[int]:
    for group in groups:
        yield from group
```

`yield from iterable` 把子可迭代对象的元素逐个转交给调用方，比手写内层循环更直接。

### 8.4 生成器清理

生成器可包含 `try/finally`，在正常耗尽、显式 `close()` 或回收时尝试清理。但外部资源的生命周期应尽量由 `with` 明确管理，不要依赖垃圾回收时机。

```python
def stream():
    resource = acquire()
    try:
        yield from resource
    finally:
        resource.close()
```

## 9. 类型提示 `typing`

### 9.1 基础注解

```python
def calculate_total(prices: list[float], tax_rate: float = 0.06) -> float:
    return sum(prices) * (1 + tax_rate)


user_id: int = 1001
tags: set[str] = {"python", "backend"}
coordinates: tuple[float, float] = (34.75, 113.62)
```

Python 3.9+ 直接使用 `list[int]`、`dict[str, int]` 等内置泛型，不必使用旧式 `typing.List`、`typing.Dict`。

### 9.2 联合类型与可空值

Python 3.10+ 使用 `|`：

```python
def find_name(user_id: int) -> str | None:
    ...


def parse_identifier(raw: str | int) -> int:
    return int(raw)
```

`str | None` 表示值可以是字符串或 `None`。不要因为“类型可空”就忽略运行时的 `None` 分支。

### 9.3 抽象容器类型

参数尽量接收所需能力的最小接口，返回值则可以给出具体类型：

```python
from collections.abc import Iterable, Mapping, Sequence


def total(values: Iterable[int]) -> int:
    return sum(values)


def first(values: Sequence[str]) -> str:
    return values[0]


def read_timeout(config: Mapping[str, float]) -> float:
    return config.get("timeout", 5.0)
```

- 只遍历：`Iterable[T]`。
- 需要长度和索引：`Sequence[T]`。
- 只读键值映射：`Mapping[K, V]`。
- 明确要求可修改时才用 `list[T]`、`dict[K, V]` 或对应可变抽象类型。

### 9.4 `Any` 与 `object`

```python
from typing import Any

dynamic: Any = external_value
unknown: object = external_value
```

- `Any` 基本关闭该值周围的静态类型检查，便利但会传播不安全。
- `object` 表示“任意对象”，使用前仍需通过 `isinstance()` 等方式缩小类型。

在 JSON、动态框架边界可能短暂使用 `Any`，应尽早解析为明确模型。

### 9.5 `Literal` 与类型别名

```python
from typing import Literal, TypeAlias

OrderStatus: TypeAlias = Literal["pending", "paid", "cancelled"]


def update_status(status: OrderStatus) -> None:
    ...
```

Python 3.12+ 推荐用 `type OrderStatus = ...` 声明新式类型别名；本系列为兼容 3.10，示例使用 `TypeAlias`。

运行时需要有限常量和值语义时，枚举往往比 `Literal` 更合适。

### 9.6 `TypedDict`

```python
from typing import TypedDict


class RequiredUserPayload(TypedDict):
    id: int
    name: str


class UserPayload(RequiredUserPayload, total=False):
    email: str


def serialize_user(user: UserPayload) -> str:
    ...
```

`TypedDict` 仅为类型检查器描述字典形状，运行时值仍是普通 `dict`，不会自动校验输入。上例用继承加 `total=False` 在 Python 3.10 中表达单个可选键；Python 3.11+ 也可直接使用 `NotRequired[str]`。

### 9.7 `Callable`

```python
from collections.abc import Callable

Validator = Callable[[str], bool]


def filter_names(names: list[str], validator: Validator) -> list[str]:
    return [name for name in names if validator(name)]
```

复杂回调（含重载、关键字参数或多个方法）可用 `Protocol` 描述，通常比巨大的 `Callable` 更可读。

### 9.8 泛型与 `TypeVar`

```python
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")


def first_or_none(values: Sequence[T]) -> T | None:
    return values[0] if values else None
```

`TypeVar` 表达输入与输出之间的类型关系。把返回类型写成 `object | None` 会丢失这种信息。

Python 3.12+ 支持 `def first_or_none[T](...)` 新式类型参数语法，但它不兼容 3.10。

### 9.9 类型缩小

```python
def normalize(value: str | bytes) -> str:
    if isinstance(value, bytes):
        return value.decode("utf-8")
    return value.strip()
```

类型检查器可根据 `isinstance()`、`is None`、模式匹配和显式判断缩小联合类型。不要随意用 `typing.cast()` 绕过真实的不确定性；`cast()` 只告诉检查器，不做运行时转换。

### 9.10 前向引用

类定义中引用尚未完成的类型，可使用字符串：

```python
class Node:
    def __init__(self, value: int, next_node: "Node | None" = None) -> None:
        self.value = value
        self.next_node = next_node
```

也可在模块顶部使用 `from __future__ import annotations` 延迟注解求值。该导入必须位于模块开头的文档字符串之后、其他普通导入之前。

## 10. 类与对象基础

### 10.1 定义类与创建实例

```python
class BankAccount:
    """一个最小银行账户示例。"""

    currency = "CNY"

    def __init__(self, owner: str, balance: float = 0.0) -> None:
        if balance < 0:
            raise ValueError("初始余额不能为负数")
        self.owner = owner
        self.balance = balance

    def deposit(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("存款金额必须大于 0")
        self.balance += amount

    def withdraw(self, amount: float) -> bool:
        if amount <= 0 or amount > self.balance:
            return False
        self.balance -= amount
        return True


account = BankAccount("Alice", 100.0)
account.deposit(50.0)
```

- 类是创建实例的对象。
- 实例属性通常在 `__init__()` 中建立。
- 实例方法第一个参数按惯例命名为 `self`，调用 `account.deposit(50)` 时由 Python 自动绑定实例。
- `__init__()` 初始化已经由 `__new__()` 创建的实例，必须返回 `None`。

### 10.2 实例属性与类属性

```python
class User:
    category = "member"  # 类属性，所有实例可见

    def __init__(self, name: str) -> None:
        self.name = name  # 实例属性，每个实例独立
```

实例查找 `user.category` 时，先看实例命名空间，再看类及其父类。给 `user.category` 赋值会创建/覆盖实例属性，通常不会修改类属性。

类属性适合常量或刻意共享的状态，不要把可变列表当作每个实例的默认容器。

### 10.3 方法绑定

```python
account.deposit(50.0)
BankAccount.deposit(account, 50.0)
```

两种调用在本质上相关：通过实例取方法时，函数会绑定实例形成 bound method。

## 11. 封装、属性与方法

### 11.1 Python 的“私有”约定

- `_name`：约定为内部实现，外部不应依赖。
- `__name`：触发名称改写，主要避免子类意外覆盖，并非安全边界。
- `name`：公开接口。

```python
class TokenStore:
    def __init__(self) -> None:
        self._tokens: dict[str, str] = {}
```

Python 更强调约定、清晰接口和测试，而不是绝对隐藏。

### 11.2 `property`

```python
class Temperature:
    def __init__(self, celsius: float) -> None:
        self.celsius = celsius

    @property
    def celsius(self) -> float:
        return self._celsius

    @celsius.setter
    def celsius(self, value: float) -> None:
        if value < -273.15:
            raise ValueError("温度不能低于绝对零度")
        self._celsius = value

    @property
    def fahrenheit(self) -> float:
        return self._celsius * 9 / 5 + 32
```

调用方继续使用 `temperature.celsius`，类可在内部校验或计算。属性访问应保持轻量、可预期；网络请求、数据库查询等昂贵副作用应使用显式方法名。

### 11.3 实例方法、类方法与静态方法

```python
class Money:
    def __init__(self, amount: int, currency: str) -> None:
        self.amount = amount
        self.currency = currency

    def format(self) -> str:
        return f"{self.amount} {self.currency}"

    @classmethod
    def from_text(cls, text: str) -> "Money":
        amount_text, currency = text.split()
        return cls(int(amount_text), currency)

    @staticmethod
    def is_supported(currency: str) -> bool:
        return currency in {"CNY", "USD", "EUR"}
```

- 实例方法需要实例状态。
- 类方法接收 `cls`，适合替代构造器，并对继承友好。
- 静态方法既不需要实例也不需要类，仅因概念归属放入类中；若没有强归属，模块级函数往往更简单。

### 11.4 `__slots__`

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y
```

`__slots__` 可限制常见实例属性并减少大量小对象的部分内存开销，但会影响动态属性、弱引用、多继承和序列化等行为。先测量再使用，不要把它当作访问控制。

## 12. 继承、组合与 MRO

### 12.1 基础继承

```python
class Notification:
    def send(self, message: str) -> None:
        raise NotImplementedError


class EmailNotification(Notification):
    def __init__(self, address: str) -> None:
        self.address = address

    def send(self, message: str) -> None:
        print(f"发送邮件到 {self.address}: {message}")
```

子类继承父类接口并可覆盖方法。继承表达“is-a”关系：子类对象应该能替代父类对象，而不破坏调用方预期。

### 12.2 `super()`

```python
class AuditedEmailNotification(EmailNotification):
    def __init__(self, address: str, auditor: str) -> None:
        super().__init__(address)
        self.auditor = auditor

    def send(self, message: str) -> None:
        print(f"审计人：{self.auditor}")
        super().send(message)
```

`super()` 表示沿方法解析顺序（MRO）查找下一个实现，不只是“直接父类”。这对协作式多继承非常重要。

### 12.3 方法解析顺序 MRO

```python
print(AuditedEmailNotification.mro())
```

多继承使用 C3 线性化计算顺序。设计协作式多继承时，各实现应兼容调用签名并按约定调用 `super()`；否则初始化链容易断裂。

Mixin 应职责小、无独立实例化意义，并在名称上体现能力：

```python
class JsonSerializableMixin:
    def to_json(self) -> str:
        ...
```

### 12.4 组合优于深继承

组合表达“has-a”关系，把变化点放入协作对象：

```python
from typing import Protocol


class Sender(Protocol):
    def send(self, message: str) -> None:
        ...


class AlertService:
    def __init__(self, sender: Sender) -> None:
        self.sender = sender

    def alert(self, message: str) -> None:
        self.sender.send(message)
```

组合通常更容易替换实现、独立测试，也避免为了复用少量代码建立不自然的继承层级。

## 13. 抽象基类、鸭子类型与 `Protocol`

### 13.1 鸭子类型

“如果对象能完成所需操作，就可以使用它”，调用方关注能力而非具体类：

```python
def publish(sender, message: str) -> None:
    sender.send(message)
```

这很灵活，但缺少类型提示时，接口约束只能依赖文档和测试。

### 13.2 抽象基类 ABC

```python
from abc import ABC, abstractmethod


class Repository(ABC):
    @abstractmethod
    def get(self, item_id: int) -> object | None:
        raise NotImplementedError


class MemoryRepository(Repository):
    def __init__(self) -> None:
        self._items: dict[int, object] = {}

    def get(self, item_id: int) -> object | None:
        return self._items.get(item_id)
```

含未实现抽象方法的类不能正常实例化。ABC 适合需要运行时名义关系、共享实现或统一注册机制的框架边界。

### 13.3 `Protocol` 结构化类型

```python
from typing import Protocol


class Repository(Protocol):
    def get(self, item_id: int) -> object | None:
        ...


class UserService:
    def __init__(self, repository: Repository) -> None:
        self.repository = repository
```

实现类无需显式继承 `Repository`；只要提供兼容的 `get()`，静态类型检查器就可认可。这是静态鸭子类型，适合依赖倒置和测试替身。

### 13.4 可运行时检查的协议

```python
from typing import Protocol, runtime_checkable


@runtime_checkable
class Closable(Protocol):
    def close(self) -> None:
        ...


if isinstance(resource, Closable):
    resource.close()
```

运行时协议检查主要确认属性是否存在，不会完整验证方法签名或类型，且可能比普通 `isinstance()` 慢。不要把它当作数据校验框架。

### 13.5 如何选择

| 场景 | 选择 |
| --- | --- |
| 只需要一个简单操作，动态代码 | 鸭子类型 + 测试 |
| 需要静态检查，第三方类不能改 | `Protocol` |
| 需要运行时禁止不完整实现 | `ABC` |
| 复用实现且确实是 is-a 关系 | 继承 |
| 替换策略、驱动、仓储、客户端 | 组合 + `Protocol` |

## 14. `dataclass` 数据类

数据类根据字段注解生成 `__init__()`、`__repr__()`、`__eq__()` 等样板代码，适合“主要承载数据，但仍需要少量行为”的类型。

### 14.1 基本用法

```python
from dataclasses import dataclass


@dataclass
class User:
    id: int
    name: str
    active: bool = True


alice = User(id=1, name="Alice")
print(alice)
```

字段顺序影响构造函数参数顺序：无默认值字段必须位于有默认值字段之前。

### 14.2 `default_factory`

```python
from dataclasses import dataclass, field


@dataclass
class Order:
    id: int
    items: list[str] = field(default_factory=list)
    metadata: dict[str, str] = field(default_factory=dict)
```

每个实例会调用工厂获得独立容器。数据类会拒绝一部分明显的可变默认值，但正确做法仍是显式 `default_factory`。

### 14.3 派生字段与 `__post_init__()`

```python
from dataclasses import dataclass, field


@dataclass
class Rectangle:
    width: float
    height: float
    area: float = field(init=False)

    def __post_init__(self) -> None:
        if self.width <= 0 or self.height <= 0:
            raise ValueError("边长必须大于 0")
        self.area = self.width * self.height
```

生成的 `__init__()` 会调用 `__post_init__()`。它适合字段间校验与轻量派生值，不应塞入数据库请求等昂贵副作用。

### 14.4 冻结、排序与槽

```python
from dataclasses import dataclass


@dataclass(frozen=True, order=True, slots=True)
class Coordinate:
    latitude: float
    longitude: float
```

- `frozen=True` 阻止常规字段重新赋值，但不自动冻结字段引用的可变对象，也不是安全边界。
- `order=True` 根据字段顺序生成比较方法，只有字段顺序确实代表业务排序时才启用。
- `slots=True` 自 Python 3.10 起可用，可减少部分实例内存并限制动态属性。

### 14.5 字段控制

```python
from dataclasses import dataclass, field


@dataclass
class Account:
    username: str
    password_hash: str = field(repr=False, compare=False)
```

敏感字段不应出现在 `repr` 中。但 `repr=False` 只是降低意外打印风险，不替代日志脱敏、访问控制与密钥管理。

### 14.6 `asdict()` 的边界

```python
from dataclasses import asdict

payload = asdict(alice)
```

`asdict()` 会递归处理嵌套数据类，并深度复制其他内容，可能带来额外成本。它也不会自动完成日期、枚举等 JSON 序列化规则；API 层应使用明确的序列化模型。

### 14.7 何时不用数据类

- 对象生命周期主要由行为和外部资源构成，而不是字段。
- 需要复杂验证、别名、解析或 API Schema 时，后续 FastAPI 章节中的 Pydantic 模型更合适。
- 只是临时返回两三个值，普通元组或 `NamedTuple` 已足够。

## 15. 常见魔术方法

双下划线方法定义对象如何参与 Python 语法和内置协议。只实现业务真正需要的协议，不要为了“完整”批量生成。

### 15.1 字符串表示

```python
class Product:
    def __init__(self, sku: str, name: str) -> None:
        self.sku = sku
        self.name = name

    def __repr__(self) -> str:
        return f"Product(sku={self.sku!r}, name={self.name!r})"

    def __str__(self) -> str:
        return f"{self.name} ({self.sku})"
```

- `__repr__()` 面向开发者，应明确且尽量无歧义。
- `__str__()` 面向用户，可更友好；未定义时会回退到 `__repr__()`。
- 不要在表示中泄漏密码、令牌等敏感信息。

### 15.2 相等与哈希

```python
class UserId:
    def __init__(self, value: int) -> None:
        self.value = value

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, UserId):
            return NotImplemented
        return self.value == other.value

    def __hash__(self) -> int:
        return hash(self.value)
```

不支持与另一类型比较时返回 `NotImplemented`，让 Python 尝试反向比较或得出合适结果。若对象参与哈希，其相等性依据必须在生命周期内保持稳定。

### 15.3 容器协议

```python
from collections.abc import Iterator


class Team:
    def __init__(self, members: list[str]) -> None:
        self._members = list(members)

    def __len__(self) -> int:
        return len(self._members)

    def __iter__(self) -> Iterator[str]:
        return iter(self._members)

    def __contains__(self, member: object) -> bool:
        return member in self._members
```

实现后可使用 `len(team)`、`for member in team`、`"Alice" in team`。是否还要实现 `__getitem__()` 取决于该对象是否真的具有序列语义。

### 15.4 可调用对象

```python
class Threshold:
    def __init__(self, minimum: int) -> None:
        self.minimum = minimum

    def __call__(self, value: int) -> bool:
        return value >= self.minimum


is_adult = Threshold(18)
print(is_adult(20))
```

可调用对象适合既需要配置/状态，又要作为回调传递的场景。

### 15.5 属性访问与谨慎使用

`__getattr__()`、`__getattribute__()`、`__setattr__()` 可以拦截属性访问，但很容易引发无限递归、隐藏拼写错误并影响工具分析。框架开发外优先使用普通属性和 `property`。

### 15.6 其他常见协议

| 方法 | 触发方式 | 用途 |
| --- | --- | --- |
| `__bool__()` | `bool(obj)`、条件判断 | 定义真值 |
| `__getitem__()` | `obj[key]` | 索引或键访问 |
| `__setitem__()` | `obj[key] = value` | 键/索引赋值 |
| `__enter__()` / `__exit__()` | `with obj` | 同步上下文管理 |
| `__aiter__()` / `__anext__()` | `async for` | 异步迭代 |
| `__aenter__()` / `__aexit__()` | `async with` | 异步上下文管理 |

## 16. 上下文管理器

上下文管理器保证“进入—使用—退出”成对执行，适合文件、锁、连接、事务和临时环境。

### 16.1 `with` 管理资源

```python
with open("data.txt", "r", encoding="utf-8") as file:
    content = file.read()
```

无论代码块正常结束还是抛出异常，都会执行退出逻辑，因此比手动 `open()` / `close()` 更可靠。

### 16.2 类实现上下文协议

```python
from types import TracebackType


class Timer:
    def __enter__(self) -> "Timer":
        from time import perf_counter

        self._start = perf_counter()
        self.elapsed = 0.0
        return self

    def __exit__(
        self,
        exc_type: type[BaseException] | None,
        exc_value: BaseException | None,
        traceback: TracebackType | None,
    ) -> bool:
        from time import perf_counter

        self.elapsed = perf_counter() - self._start
        print(f"耗时：{self.elapsed:.6f} 秒")
        return False


with Timer() as timer:
    sum(range(1_000_000))
```

`__exit__()` 返回真值会抑制异常。除非上下文管理器明确负责处理该异常，否则返回 `False` 或 `None` 让异常继续传播。

### 16.3 `@contextmanager`

```python
from collections.abc import Iterator
from contextlib import contextmanager


@contextmanager
def managed_resource() -> Iterator["Resource"]:
    resource = acquire_resource()
    try:
        yield resource
    finally:
        resource.close()
```

`yield` 前是进入逻辑，产出的值绑定到 `as` 后名称，`finally` 中是退出逻辑。生成器式上下文管理器必须恰好 `yield` 一次。

### 16.4 多个上下文

```python
with (
    open("source.txt", encoding="utf-8") as source,
    open("target.txt", "w", encoding="utf-8") as target,
):
    target.write(source.read())
```

进入顺序从左到右，退出顺序从右到左。动态数量的上下文可使用 `contextlib.ExitStack`。

## 17. 常见坑

### 17.1 可变默认参数跨调用共享

```python
# 错误
def collect(item, bucket=[]):
    bucket.append(item)
    return bucket
```

使用 `None` 哨兵并在函数内创建新容器。只有刻意实现缓存且有清晰说明时，才应依赖定义时求值行为。

### 17.2 默认参数捕获的是定义时对象

```python
timeout = 3


def request(value: int = timeout) -> int:
    return value


timeout = 10
print(request())  # 3
```

若默认值应随配置变化，在函数体内读取配置或显式传入。

### 17.3 闭包延迟绑定

循环创建闭包时，所有函数可能读取最终循环值。使用工厂函数或默认参数固定每轮值。

### 17.4 忘记 `@wraps`

没有 `@wraps` 的装饰器会让被装饰函数看起来都叫 `wrapper`，还会丢失文档与注解，可能破坏 FastAPI 等依赖函数签名/注解的框架。

### 17.5 生成器只能消费一次

```python
numbers = (number for number in range(3))
print(list(numbers))  # [0, 1, 2]
print(list(numbers))  # []
```

若需重复遍历，保存可重建生成器的工厂、使用可重复迭代对象，或在数据规模可控时物化为列表。

### 17.6 `yield` 让整个函数成为生成器函数

即使 `yield` 位于永远不执行的分支，调用函数仍返回生成器对象，而不是直接执行并返回普通值。

### 17.7 类属性中的可变对象被所有实例共享

```python
class BadCart:
    items: list[str] = []
```

若每个实例需要独立列表，应在 `__init__()` 中赋值，或在数据类中使用 `default_factory=list`。

### 17.8 `__init__()` 不能返回对象

`__init__()` 必须返回 `None`。需要控制创建过程可了解 `__new__()`；需要多个构造入口通常优先使用 `@classmethod`。

### 17.9 过度继承

为了复用几行代码建立多层继承，会让状态来源、覆盖顺序与 MRO 难以追踪。优先提取函数、组合协作对象或小型 Mixin。

### 17.10 相等与哈希不一致

定义 `__eq__()` 后，如果对象仍可变，通常不应强行实现 `__hash__()`。否则对象进入集合后改变哈希依据，会再也无法按预期找到。

### 17.11 类型提示不等于运行时校验

```python
def square(value: int) -> int:
    return value * value


square("a")  # 注解本身不会阻止调用，运行到乘法时才按实际语义处理
```

外部请求、环境变量、文件和数据库数据必须在系统边界解析与校验。

### 17.12 用 `type(x) is T` 阻断子类

大多数类型判断使用 `isinstance(x, T)`，它尊重继承与抽象基类。只有业务必须精确排除子类时才使用 `type(x) is T`。

### 17.13 属性中隐藏昂贵操作

`user.profile` 通常让人预期是轻量访问。若它会访问网络或数据库，应使用 `load_profile()`、异步方法或显式仓储调用。

## 18. 设计建议

### 18.1 函数还是类

| 情况 | 优先选择 |
| --- | --- |
| 无状态输入到输出转换 | 普通函数 |
| 一组函数共享少量固定配置 | 闭包或可调用对象 |
| 有多个相关操作与持续状态 | 类 |
| 主要承载数据并需要比较/表示 | `dataclass` |
| 需要替换外部实现 | 组合 + `Protocol` |

### 18.2 接口小而明确

```python
class UserReader(Protocol):
    def get_by_id(self, user_id: int) -> "User | None":
        ...
```

与其让业务服务依赖拥有几十个方法的“万能仓储”，不如依赖它真正需要的最小协议，测试替身也更简单。

### 18.3 把 I/O 与业务规则分开

```python
def calculate_level(score: int) -> str:
    if not 0 <= score <= 100:
        raise ValueError("score 超出范围")
    if score >= 90:
        return "A"
    if score >= 60:
        return "B"
    return "C"
```

读取 HTTP 请求、查询数据库和打印响应属于边界；评分规则保持纯函数，能快速、稳定地测试。

### 18.4 异常表达失败，返回值表达正常分支

- 输入不满足契约、资源不存在且调用方要求必须存在：抛出明确异常。
- “可能查不到”是正常业务分支：返回 `T | None`，并在调用方处理。
- 不要混用 `None`、`False`、空列表和异常表示同一种失败。

具体异常设计、模块组织与工程规范见下一章。

### 参考实现：分页生成器

```python
from collections.abc import Iterable, Iterator
from typing import TypeVar

T = TypeVar("T")


def paginate(items: Iterable[T], page_size: int) -> Iterator[list[T]]:
    if page_size <= 0:
        raise ValueError("page_size 必须大于 0")

    page: list[T] = []
    for item in items:
        page.append(item)
        if len(page) == page_size:
            yield page
            page = []

    if page:
        yield page


for current_page in paginate(range(7), page_size=3):
    print(current_page)
```
