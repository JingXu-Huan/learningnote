## 模块与包

### 三个基本概念

- **模块（module）**：通常就是一个 `.py` 文件。
- **包（package）**：包含多个模块的目录。传统包含有 `__init__.py`；现代 Python 也支持命名空间包，但普通项目保留 `__init__.py` 更直观。
- **对象**：模块中定义的变量、函数和类。导入本质上是把对象名称绑定到当前命名空间。

例如：

```text
shop/
├── __init__.py
├── pricing.py
└── services/
    ├── __init__.py
    └── order.py
```

`shop.pricing` 和 `shop.services.order` 都是可导入的模块。

### 创建和使用模块

```python
# shop/pricing.py
TAX_RATE = 0.13


def total_price(price: float, quantity: int = 1) -> float:
    return round(price * quantity * (1 + TAX_RATE), 2)
```

```python
# main.py
from shop.pricing import total_price

print(total_price(10, quantity=3))
```

推荐把导入放在文件顶部，通常按“标准库、第三方库、本地包”分组。不要使用 `from module import *`，它会隐藏名称来源并制造覆盖风险。

### `__name__` 与程序入口

模块被直接执行时，`__name__ == "__main__"`；被其他模块导入时，`__name__` 是完整模块名。

```python
def main() -> None:
    print("程序启动")


if __name__ == "__main__":
    main()
```

入口保护有两个作用：导入时不执行脚本逻辑；入口函数可以被测试。包内模块建议从项目根目录用 `-m` 执行：

```powershell
python -m shop.services.order
```

这比进入子目录后运行 `python order.py` 更不容易产生导入路径问题。

### `__init__.py` 应该放什么

`__init__.py` 会在包首次导入时执行，可以用于暴露稳定的公共 API：

```python
# shop/__init__.py
from .pricing import total_price

__all__ = ["total_price"]
```

不要在其中连接数据库、发送网络请求或执行耗时初始化。导入应该快速且副作用尽可能少，否则测试、脚本和多进程启动都会变得不可预测。

## 导入系统

### 绝对导入与相对导入

```python
# 绝对导入：来源清晰，跨包时优先
from shop.pricing import total_price

# 相对导入：适合包内部关系稳定的相邻模块
from ..pricing import total_price
```

相对导入中的一个点表示当前包，两个点表示上一级包。直接执行包内文件时没有正确的包上下文，相对导入可能失败，因此配合 `python -m 完整模块名` 使用。

### Python 到哪里找模块

导入时会查询 `sys.path`，其内容大致来自：

1. 程序入口所在位置；
2. `PYTHONPATH`（不建议项目依赖它）；
3. 当前虚拟环境的标准库与 `site-packages`；
4. 安装或注册的其他路径。

```python
import sys

for item in sys.path:
    print(item)
```

遇到 `ModuleNotFoundError` 时，先确认当前解释器、当前工作目录、执行方式和包是否安装，不要第一反应就在代码中 `sys.path.append(...)`。

### 导入只初始化一次

同一解释器进程内，一个模块通常只执行一次，之后从 `sys.modules` 缓存复用。因此“修改模块全局变量”会影响本进程中后续使用者；并发和测试中尤其要避免把可变业务状态放到模块全局。

### 循环导入

若 `a.py` 在顶层导入 `b.py`，而 `b.py` 又在顶层导入 `a.py`，其中一个模块会处于“尚未初始化完整”的状态。

更好的解决顺序是：

1. 把双方共享的类型或函数提取到第三个模块；
2. 重新划分职责，让依赖方向单向；
3. 仅用于类型注解时使用 `TYPE_CHECKING`；
4. 最后才考虑把导入移动到函数内部。

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from shop.services.order import Order


def print_order(order: "Order") -> None:
    print(order)
```

### 名称遮蔽

不要把文件命名为 `json.py`、`typing.py`、`fastapi.py`、`sqlalchemy.py` 等已有模块名，否则 `import` 可能导入自己的文件。变量也尽量不要命名为 `list`、`str`、`id`、`sum`，以免遮蔽内置对象。

## 异常处理

### 异常不是返回值

异常用于表达“当前操作无法按约定完成”，并沿调用栈向上传播。正常的业务分支通常用返回值；无法恢复或需要上层决定的问题才抛异常。

```python
def parse_age(raw: str) -> int:
    try:
        age = int(raw)
    except ValueError as exc:
        raise ValueError("年龄必须是整数") from exc

    if not 0 <= age <= 150:
        raise ValueError("年龄超出合理范围")
    return age
```

`raise ... from exc` 保留了原始原因，traceback 会展示完整因果链。

### `try` 的完整结构

```python
try:
    value = int(user_input)
except ValueError:
    print("输入不是整数")
else:
    print(f"解析成功：{value}")
finally:
    print("无论成功失败都会执行")
```

- `try`：只包住可能失败的最小范围；
- `except`：处理明确知道如何恢复的异常；
- `else`：没有异常时执行，避免把后续代码误纳入捕获范围；
- `finally`：无论如何都要做的清理。资源管理通常优先使用 `with`。

### 捕获具体异常

```python
try:
    config = load_config(path)
except FileNotFoundError:
    config = default_config()
except PermissionError as exc:
    logger.error("无权读取配置：%s", exc)
    raise
```

不要写没有说明的 `except: pass`。裸 `except` 还会捕获 `KeyboardInterrupt` 和 `SystemExit`，导致程序难以正常退出。确实需要在系统边界记录未知错误时，可捕获 `Exception`，记录 traceback 后重新抛出或转换：

```python
try:
    run_job()
except Exception:
    logger.exception("任务执行失败")
    raise
```

### 自定义异常

为业务层建立一个异常根类，上层可以统一捕获，同时保留更具体的类型。

```python
class ShopError(Exception):
    """商城领域异常的基类。"""


class ProductNotFoundError(ShopError):
    def __init__(self, product_id: int) -> None:
        self.product_id = product_id
        super().__init__(f"商品不存在：{product_id}")


class InsufficientStockError(ShopError):
    pass
```

不要让底层数据库异常一路泄漏到 HTTP 响应。repository 可以把存储细节转成领域异常，API 层再把领域异常映射为状态码和稳定的错误结构。

### EAFP 与 LBYL

- **EAFP**：先执行，失败后捕获异常；符合 Python 风格，也能避免“检查后状态又变化”的竞态。
- **LBYL**：先检查再执行；适合检查便宜、失败常见且没有竞态的纯内存场景。

```python
# EAFP：字典查找只做一次
try:
    role = user["role"]
except KeyError:
    role = "guest"

# 更简单时直接使用 API 提供的默认值
role = user.get("role", "guest")
```

异常不是普通循环控制工具；如果失败是高频且可预期的，优先找更直接的 API。

### 多个并发异常

Python 3.11+ 提供 `ExceptionGroup` 和 `except*`，用于一个并发操作产生多个互不相关的失败：

```python
try:
    raise ExceptionGroup(
        "批量任务失败",
        [ValueError("数据错误"), TimeoutError("请求超时")],
    )
except* ValueError as group:
    print(f"数据类错误：{len(group.exceptions)} 个")
except* TimeoutError as group:
    print(f"超时类错误：{len(group.exceptions)} 个")
```

日常代码不必主动包装所有异常；理解它主要是为了阅读 `asyncio.TaskGroup` 等并发代码的 traceback。

## 上下文管理器

上下文管理器把“获取资源—使用资源—保证释放”封装起来，进入 `with` 时调用 `__enter__`，退出时调用 `__exit__`。即使中途抛异常，也会执行退出逻辑。

```python
from pathlib import Path

path = Path("data.txt")
with path.open("r", encoding="utf-8") as file:
    content = file.read()
```

可以用类实现：

```python
class Timer:
    def __enter__(self) -> "Timer":
        from time import perf_counter

        self._start = perf_counter()
        return self

    def __exit__(self, exc_type, exc_value, traceback) -> bool:
        from time import perf_counter

        self.elapsed = perf_counter() - self._start
        return False  # 不吞掉 with 内的异常


with Timer() as timer:
    sum(range(100_000))

print(timer.elapsed)
```

简单场景可使用 `contextlib.contextmanager`：

```python
from collections.abc import Iterator
from contextlib import contextmanager


@contextmanager
def transaction(connection) -> Iterator[None]:
    try:
        yield
        connection.commit()
    except Exception:
        connection.rollback()
        raise
```

异步资源使用 `async with`，对应 `__aenter__` / `__aexit__`。数据库会话、HTTP 客户端和锁都常用这种形式。

## 文件与目录

### 优先使用 `pathlib`

`Path` 比手工拼接字符串更跨平台：

```python
from pathlib import Path

base_dir = Path(__file__).resolve().parent
data_dir = base_dir / "data"
data_dir.mkdir(parents=True, exist_ok=True)

for path in data_dir.glob("*.json"):
    print(path.name, path.stat().st_size)
```

常用操作：

| 操作 | 写法 |
| --- | --- |
| 判断存在 | `path.exists()` |
| 判断文件/目录 | `path.is_file()` / `path.is_dir()` |
| 创建目录 | `path.mkdir(parents=True, exist_ok=True)` |
| 读取文本 | `path.read_text(encoding="utf-8")` |
| 写入文本 | `path.write_text(text, encoding="utf-8")` |
| 遍历当前目录 | `path.iterdir()` |
| 递归匹配 | `path.rglob("*.py")` |
| 改名或移动 | `path.replace(target)` / `path.rename(target)` |
| 删除文件 | `path.unlink()` |

删除、覆盖和递归移动前必须验证最终路径。不要把未经校验的用户输入直接拼进文件路径，需防止 `../` 路径穿越。

### 文本模式与二进制模式

```python
from pathlib import Path

text_path = Path("note.txt")
with text_path.open("w", encoding="utf-8", newline="") as file:
    file.write("第一行\n第二行\n")

image_path = Path("avatar.png")
with image_path.open("rb") as file:
    header = file.read(8)
```

常见模式：

- `r`：读取，文件必须存在；
- `w`：写入，存在时会截断；
- `a`：追加；
- `x`：仅新建，存在时失败；
- `b`：二进制；`+`：同时读写。

文本文件明确指定 `encoding="utf-8"`，避免不同操作系统默认编码不同。协议定义了换行格式时再明确设置 `newline`。

### 大文件要流式处理

```python
from pathlib import Path

with Path("access.log").open("r", encoding="utf-8") as file:
    for line_number, line in enumerate(file, start=1):
        if "ERROR" in line:
            print(line_number, line.rstrip())
```

文件对象本身就是迭代器。不要对未知大小文件直接 `read()` 或 `readlines()`，否则可能耗尽内存。二进制复制可以按块读取：

```python
def copy_binary(source: Path, target: Path, chunk_size: int = 1024 * 1024) -> None:
    with source.open("rb") as src, target.open("wb") as dst:
        while chunk := src.read(chunk_size):
            dst.write(chunk)
```

### 降低写一半的风险

重要配置可先写同目录临时文件，成功刷新后再替换目标。`Path.replace()` 在同一文件系统中通常提供原子替换语义，但持久化保证仍取决于操作系统和文件系统。

```python
import json
from pathlib import Path


def save_json(path: Path, data: object) -> None:
    temporary = path.with_suffix(path.suffix + ".tmp")
    temporary.write_text(
        json.dumps(data, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )
    temporary.replace(path)
```

并发写同一文件还需要锁或更合适的数据库。原子替换只能防止“半个文件”，不能解决多个写入者互相覆盖。

### 序列化边界

- JSON 适合跨语言数据，只原生支持有限类型；日期和 `Decimal` 需要明确编码策略。
- CSV 是表格文本，不保存可靠类型；读取后仍需校验。
- `pickle` 能还原 Python 对象，但加载恶意数据可执行任意代码，绝不能反序列化不可信内容。

标准库的具体 API 见 [05-常用内置函数与标准库](./05-常用内置函数与标准库.md)。

## 虚拟环境与依赖

### 为什么每个项目都要隔离

两个项目可能依赖同一个库的不同版本。虚拟环境为项目提供独立的解释器入口和 `site-packages`，但不复制完整 Python 安装。

Windows PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install httpx
python -m pip show httpx
python -m pip list
deactivate
```

macOS / Linux：

```shell
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

检查当前解释器：

```python
import sys

print(sys.executable)
print(sys.version)
```

### 记录依赖

小型应用可以从 `requirements.txt` 起步：

```text
fastapi>=0.100,<1.0
sqlalchemy>=2.0,<3.0
```

```powershell
python -m pip install -r requirements.txt
python -m pip freeze > requirements.lock.txt
```

概念上要区分：

- **直接依赖**：项目主动选择的库；
- **传递依赖**：直接依赖内部使用的库；
- **版本约束**：允许的范围；
- **锁定结果**：某次解析得到的完整、可复现版本集合。

`pip freeze` 会列出环境中的全部已安装包，不适合直接代表“项目主动依赖”。提交依赖前应在干净环境验证，避免把全局工具混进去。

### `pyproject.toml`

现代 Python 项目通常用 `pyproject.toml` 描述项目元数据、依赖和工具配置：

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "task-api"
version = "0.1.0"
requires-python = ">=3.10"
dependencies = [
  "fastapi>=0.100,<1.0",
  "uvicorn[standard]>=0.20,<1.0",
]

[project.optional-dependencies]
dev = [
  "pytest>=8,<10",
  "ruff>=0.8,<1.0",
]
```

这里的构建后端只是示例，应用项目不一定需要发布成 PyPI 包。`pip-tools`、Poetry、PDM、uv 等工具可提供依赖解析与锁文件；团队只选一套，并在 README 和 CI 中保持一致。不要在同一项目混用多套锁文件。

### 安装当前项目

可安装项目常用可编辑模式：

```powershell
python -m pip install -e ".[dev]"
```

它让导入遵循安装后的包结构，同时源码修改立即生效。比修改 `PYTHONPATH` 或复制代码更可靠。

## 项目结构与配置

### 一个可维护的普通项目

```text
task-api/
├── pyproject.toml
├── README.md
├── .env.example
├── src/
│   └── task_api/
│       ├── __init__.py
│       ├── main.py
│       ├── config.py
│       ├── domain/
│       ├── services/
│       └── adapters/
└── tests/
    ├── conftest.py
    └── test_services.py
```

`src` 布局可以防止测试意外从仓库根目录导入尚未安装的源码。对简单学习脚本不必机械套用；当项目开始有测试、依赖和发布流程时再采用。

### 分层依据是变化原因

- `domain`：业务概念和规则，不依赖 Web 框架；
- `services`：组织用例；
- `adapters`：数据库、HTTP、文件等外部实现；
- `main`：组装依赖并启动应用。

不要为了“看起来专业”把每个函数拆成一层。分层的价值是隔离变化和便于测试；如果一个项目只有三个简单路由，按功能组织的几个模块已经足够。

### 配置来自环境

代码中保存安全的默认值，环境差异通过环境变量注入，密钥不能提交到 Git。

```python
import os

database_url = os.environ["DATABASE_URL"]
debug = os.getenv("DEBUG", "false").lower() == "true"
```

对于 FastAPI 项目，更适合用 Pydantic Settings 集中校验，见第 06 和第 09 章。仓库中提交 `.env.example` 说明变量名，但只放假值：

```dotenv
APP_ENV=development
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/task_db
JWT_SECRET=replace-with-a-random-secret
```

实际 `.env` 应加入 `.gitignore`。生产环境通常由部署平台或密钥服务注入，不依赖镜像内的 `.env` 文件。

### `__pycache__` 与缓存

Python 可能生成 `.pyc` 字节码缓存，它不是源码，也不是加密产物。常见忽略项：

```gitignore
.venv/
__pycache__/
*.py[cod]
.pytest_cache/
.ruff_cache/
.mypy_cache/
.env
dist/
build/
```

## 日志、调试与质量工具

### 用日志描述事件

```python
import logging

logger = logging.getLogger(__name__)


def create_order(order_id: str, user_id: int) -> None:
    logger.info("creating order", extra={"order_id": order_id, "user_id": user_id})
```

应用入口统一配置 handler、格式和级别，库模块只获取 logger。常用级别：

- `DEBUG`：开发诊断细节；
- `INFO`：正常关键业务事件；
- `WARNING`：可恢复但值得注意；
- `ERROR`：当前操作失败；
- `CRITICAL`：系统无法继续提供核心能力。

不要记录密码、访问令牌、身份证号等敏感信息。异常处理器中用 `logger.exception(...)` 自动附带 traceback；高频循环避免无意义的逐条日志。

### 阅读 traceback

从最后一行确认异常类型和消息，再沿调用栈由下向上寻找“自己代码的第一处异常现场”。根因不一定在最顶部，也不一定在最终报错行；结合输入和状态判断。

常用调试手段：

```python
breakpoint()  # 进入内置 pdb
```

在调试器中可查看变量、单步进入和继续运行。IDE 断点更方便，但理解 traceback 和最小复现比盲目单步更重要。

### 最小复现

排错时逐步移除与问题无关的框架、网络和数据库部分，直到只剩最短失败示例。然后固定：

- Python 与依赖版本；
- 操作系统和执行命令；
- 最小输入数据；
- 完整 traceback；
- 期望行为与实际行为。

### 质量工具的职责

| 工具 | 解决的问题 |
| --- | --- |
| Ruff | 代码风格、常见错误和导入排序，也可格式化 |
| mypy / Pyright | 静态类型检查 |
| pytest | 自动化测试、fixture 和参数化 |
| coverage.py | 测试执行覆盖范围 |
| pre-commit | 提交前统一运行检查 |

类型检查和测试互补：类型检查发现接口不一致，测试验证运行时行为。覆盖率只表示“代码被执行过”，不代表断言有效，也不应为了数字给无价值代码写测试。

一个精简配置示例：

```toml
[tool.ruff]
target-version = "py310"
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP"]

[tool.pytest.ini_options]
testpaths = ["tests"]
addopts = "-q"

[tool.mypy]
python_version = "3.10"
warn_return_any = true
disallow_untyped_defs = true
```

工具规则要循序启用。第一次给旧项目加检查时，先建立可执行基线，再分批修复，不要在功能提交中混入全仓库无关格式化。

## 常见问题

### 为什么明明安装了库，还是提示找不到

通常是“安装使用的 pip”和“运行使用的 python”不属于同一环境。检查：

```powershell
python -c "import sys; print(sys.executable)"
python -m pip --version
python -m pip show package-name
```

### 为什么包内相对导入失败

很可能直接执行了包内文件。回到项目根目录，使用：

```powershell
python -m package.module
```

### 为什么捕获异常后还是难以定位

检查是否丢失了异常链或日志 traceback。转换异常时使用 `raise NewError(...) from exc`；仅记录时使用 `logger.exception`；无法恢复时不要吞掉异常。

### `return` 可以写在 `finally` 吗

语法上可以，但通常不应这样做。它可能覆盖 `try` 中的返回值或正在传播的异常，让严重故障静默消失。

### 为什么 Windows 能读的文本在服务器乱码

代码依赖了系统默认编码。读写文本时显式使用 UTF-8，并确认外部文件本身的真实编码。编码声明不能把 GBK 文件自动变成 UTF-8。

### 为什么修改了全局配置会影响其他测试

模块在进程内共享且通常只初始化一次。把可变状态封装成对象，通过参数或依赖注入传入；测试中避免依赖用例执行顺序。

## 练习

### 练习一：文本统计 CLI

编写 `python -m textstat 文件路径`：

1. 统计行数、非空行数、单词数和字符数；
2. 文件不存在、无权限、编码错误时输出清晰消息；
3. 大文件逐行读取；
4. 业务计算函数不直接 `print`，入口负责展示；
5. 为统计函数编写至少三个测试。

### 练习二：安全配置加载器

从 JSON 读取应用配置，要求：

- 使用 `Path` 和 UTF-8；
- 校验必填键和端口范围；
- 把 JSON 解析错误转换成自定义 `ConfigError`，保留异常链；
- 支持环境变量覆盖，但不要把密钥打印到日志；
- 写入时先写临时文件再替换。

### 练习三：拆分包

把一个单文件记账脚本拆为：

```text
ledger/
├── __init__.py
├── __main__.py
├── models.py
├── services.py
├── storage.py
└── cli.py
```

保证 `python -m ledger` 能启动；`services.py` 不依赖 CLI；`storage.py` 只负责持久化；导入模块时没有输出或文件写入副作用。
