## 使用方法

每个知识点至少经过四层检验：

1. **识别**：看到代码知道用了什么语法或机制；
2. **解释**：能说明它解决什么问题、有什么边界；
3. **编写**：离开示例能自己实现；
4. **取舍**：面对两个方案能结合场景说明为什么选其中一个。

复习时给每个问题标记：

- A：能准确解释，并能写出最小示例；
- B：知道结论，但解释不完整；
- C：只见过关键词；
- D：完全陌生。

优先处理 C / D，然后用代码验证 B。不要背诵大段标准答案，面试官更关心你能否从机制推导行为。

## 递进式实战

### 项目一：命令行记账本

目标：巩固语法、数据结构、文件、异常与模块。

功能要求：

- 添加收入/支出，字段包含 ID、类别、金额、说明和时间；
- 按月份、类别筛选，统计收支与结余；
- 使用 `Decimal` 表示金额，不能用二进制浮点数直接累计；
- 数据保存为 UTF-8 JSON；写入失败时不能破坏已有文件；
- 用自定义异常区分输入错误与存储错误；
- 使用 `argparse` 或 Typer 提供 CLI；
- 业务函数有类型注解和测试。

验收问题：

- 如果两个进程同时写文件会怎样？
- JSON 如何表示 `Decimal` 和带时区时间？
- 哪部分可在未来替换成数据库而不影响业务规则？

### 项目二：日志分析器

目标：巩固迭代器、生成器、标准库与性能意识。

功能要求：

- 流式读取 GB 级访问日志，不一次装入内存；
- 解析 IP、路径、状态码、耗时和时间戳；
- 输出状态码分布、慢请求 Top N 和访问最多的路径；
- 损坏行记录行号并跳过，超过错误阈值则终止；
- 支持 gzip 文件；
- 用 `heapq` 维护 Top N，而不是排序全部记录；
- 用参数化测试覆盖正常行、边界行和非法行。

验收问题：

- 时间复杂度和空间复杂度是多少？
- 正则表达式编译应放在哪里？
- 如果要并行处理多个文件，线程和进程如何选择？

### 项目三：异步聚合服务

目标：巩固 HTTPX、`asyncio`、超时、并发上限与降级。

功能要求：

- 并发请求三个外部服务并聚合响应；
- 复用一个 `httpx.AsyncClient`，设置连接与读取超时；
- 用 `Semaphore` 控制最大并发数；
- 一个非核心服务失败时返回降级结果；核心服务失败时整体失败；
- 正确传播取消，不使用无限重试；
- 对可重试错误采用有限次数、指数退避和随机抖动；
- 记录请求 ID、上游耗时和结果，不记录令牌。

验收问题：

- `asyncio.gather()` 与 `TaskGroup` 的失败语义有什么差异？
- 为什么不能为每个请求临时创建一个 HTTP 客户端？
- 重试一个非幂等 POST 有什么风险？

### 项目四：任务管理 API

目标：串起 FastAPI、Pydantic、SQLAlchemy、认证、测试和部署。

基础验收：

- 用户注册、登录，密码只保存安全哈希；
- JWT 包含最少声明、短过期时间，并验证签名和过期时间；
- 每个用户只能访问自己的任务；
- 任务支持创建、详情、修改、删除、分页、状态筛选；
- 请求模型、响应模型、ORM 模型分离；
- 数据库操作处于清晰事务边界；
- 统一错误结构，不能把 SQL、堆栈或密钥返回给客户端；
- 有迁移、测试、健康检查、结构化日志和部署说明。

进阶验收：

- 乐观锁或版本号防止并发覆盖；
- 幂等键防止重复创建；
- cursor 分页适应持续写入的数据集；
- Redis 缓存带失效策略；
- 后台任务可重试且不会重复产生副作用；
- 指标区分请求量、错误率和延迟分位数。

完整骨架见 [09-FastAPI项目实战](./09-FastAPI项目实战.md)。

## Python 基础高频问题

### Python 是动态类型还是弱类型

Python 是**动态类型、强类型**语言。动态类型表示变量名不固定绑定某一类型，对象在运行时带有类型；强类型表示不会随意把不兼容类型隐式混合，例如 `"1" + 1` 会抛 `TypeError`。

### 变量保存的是什么

更准确地说，名称绑定到对象，而不是盒子里存一份值。赋值 `b = a` 通常只是让两个名称引用同一个对象，不会自动复制对象。

```python
a = [1, 2]
b = a
b.append(3)
assert a == [1, 2, 3]
```

### `==` 与 `is` 的区别

- `==` 比较值是否相等，可由 `__eq__` 定义；
- `is` 比较是否为同一对象。

`None` 是单例语义，应使用 `value is None`。不要依赖小整数或短字符串的驻留现象写 `is` 比较。

### 真值规则有哪些

`None`、`False`、数值零、空字符串和空容器通常为假，其他对象通常为真。自定义类可用 `__bool__` 或 `__len__` 定义真值。

`value or default` 会把所有假值都替换掉；若只想替换 `None`，应明确判断：

```python
result = default if value is None else value
```

### `and` / `or` 返回布尔值吗

不一定。它们短路求值并返回最后求值的操作数：

```python
name = provided_name or "anonymous"
```

这很方便，但要注意 `0`、空字符串等合法假值。

### 为什么浮点数会有误差

许多十进制小数无法用有限的二进制浮点精确表示。科学计算用容差比较；金额等需要十进制规则的场景用 `Decimal`，而且应从字符串构造：

```python
from decimal import Decimal

amount = Decimal("0.10")
```

### `pass`、`continue`、`break`、`return` 的区别

- `pass`：什么都不做，占位；
- `continue`：跳到下一次循环；
- `break`：结束当前循环；
- `return`：结束当前函数，并可返回值。

循环的 `else` 在循环正常结束时执行，被 `break` 打断时不执行，适合表达“遍历后仍未找到”。

### 赋值表达式 `:=` 什么时候使用

它在表达式中绑定结果，适合避免重复计算，例如按块读取。若让条件难读，就拆成普通赋值。

```python
while chunk := file.read(8192):
    consume(chunk)
```

### `match` 是简单 switch 吗

不只是。结构化模式匹配可以按值、序列、映射和类的结构解构，并支持守卫条件。模式从上到下匹配，因此具体分支应放在宽泛分支前。

## 数据结构高频问题

### `list` 与 `tuple` 如何选择

- `list` 可变，适合持续增删的同类元素集合；
- `tuple` 不可变，适合表达固定结构或只读序列，可作为字典键的前提是其中元素也都可哈希。

不要仅因为“tuple 更快”就替换所有 list；语义清晰比微小性能差异更重要。

### 什么是可哈希对象

对象在生命周期内哈希值稳定，并且相等对象具有相同哈希值，才适合作为 `dict` 键或 `set` 元素。常见不可变基础类型可哈希；`list`、`dict`、`set` 默认不可哈希。

自定义类若实现 `__eq__` 和 `__hash__`，必须保持“相等则哈希相等”。参与哈希的字段不应在对象进入集合后改变。

### 字典为什么平均查找是 O(1)

字典使用哈希表，通过键的哈希值定位槽位。碰撞、扩容和极端输入会影响常数或最坏情况，所以 O(1) 是平均复杂度，不是任何情况下只执行一步。

### 字典是否有顺序

现代 Python 语言规范保证字典保留**插入顺序**，但它不是按键排序结构。更新已有键不改变位置；删除后重新插入通常出现在末尾。

### 浅拷贝与深拷贝

- 浅拷贝创建新的外层容器，内部仍引用原对象；
- 深拷贝递归复制，成本更高，也不一定适合文件句柄、锁、数据库连接等资源对象。

```python
from copy import deepcopy

original = [[1], [2]]
shallow = original.copy()
deep = deepcopy(original)
```

优先根据数据模型明确构造新对象，不要把 `deepcopy` 当成所有状态隔离问题的快捷答案。

### `set` 适合什么场景

去重、快速成员判断和集合运算。集合本身无索引语义，不应依赖其迭代顺序。若既要去重又保留首次出现顺序，可利用字典：

```python
unique = list(dict.fromkeys(items))
```

### 列表推导式和生成器表达式有何区别

列表推导式立即创建完整列表；生成器表达式按需产出，通常更省内存，但只能消费一次。需要多次遍历、索引或立刻知道全部结果时用列表；流式管道用生成器。

### 为什么不要边遍历列表边删除

删除会移动后续索引，可能跳过元素。可以构建新列表，或在明确场景下倒序遍历索引：

```python
active = [user for user in users if user.enabled]
```

### 队列应该用 list 吗

列表尾部 `append` / `pop` 是摊销 O(1)，但头部 `pop(0)` 是 O(n)。双端队列使用 `collections.deque`，优先 `append` 和 `popleft`。

### 排序和 Top N 如何选择

- 全量有序：`sorted`，通常 O(n log n)；
- 只要最小/最大 N 个：`heapq.nsmallest` / `nlargest`；
- 数据持续进入且维护候选集合：固定大小堆；
- 数据已经有序并频繁二分定位：`bisect`。

## 函数、对象与类型系统

### 为什么可变默认参数危险

默认参数在函数定义时求值一次，多个调用会共享同一对象。

```python
def add_item(item: str, items: list[str] | None = None) -> list[str]:
    if items is None:
        items = []
    items.append(item)
    return items
```

同理，默认参数不要直接创建当前时间、随机数或连接对象；需要每次计算时在函数体中创建。

### `*args` 与 `**kwargs` 是什么

函数定义中，`*args` 收集额外位置参数为 tuple，`**kwargs` 收集额外关键字参数为 dict；函数调用中，`*` 展开可迭代对象，`**` 展开映射。

它们不应成为模糊 API 的借口。公共函数尽量显式声明参数，便于类型检查、IDE 提示和错误发现。

### 位置专用与关键字专用参数

```python
def connect(host: str, /, *, timeout: float = 5.0) -> None:
    ...
```

`/` 前只能按位置传入，`*` 后只能按关键字传入。关键字专用参数能让布尔值和多个同类型参数更易读。

### 闭包为什么会晚绑定

闭包捕获名称，而不是定义当时的值。循环结束后，所有函数可能读取同一个最终值：

```python
functions = [lambda value=i: value for i in range(3)]
assert [function() for function in functions] == [0, 1, 2]
```

默认参数在定义时求值，因此这里用于固定每次的 `i`。

### 装饰器的本质

装饰器接收一个可调用对象并返回另一个可调用对象，常用于横切逻辑。用 `functools.wraps` 保留原函数元数据：

```python
from collections.abc import Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")


def logged(function: Callable[P, R]) -> Callable[P, R]:
    @wraps(function)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        print(function.__name__)
        return function(*args, **kwargs)

    return wrapper
```

### 迭代器与生成器的关系

可迭代对象能返回迭代器；迭代器实现 `__next__` 并保存遍历状态；包含 `yield` 的生成器函数调用后返回生成器迭代器。生成器暂停时保留局部状态，结束时抛出 `StopIteration` 给迭代协议处理。

### 实例属性与类属性

实例属性属于单个对象；类属性由类共享。把可变容器放在类属性上会被所有实例共享，除非这就是设计意图。

```python
class User:
    species = "human"  # 类属性

    def __init__(self, name: str) -> None:
        self.name = name  # 实例属性
```

### `@staticmethod`、`@classmethod` 与实例方法

- 实例方法接收 `self`，操作实例状态；
- 类方法接收 `cls`，常作多态友好的备用构造器；
- 静态方法不自动接收实例或类，只是与该类概念相关的函数。

若函数与类状态完全无关，模块级函数往往更简单。

### 组合与继承如何选择

继承表达稳定的“是一个”关系，并依赖父类契约；组合表达“拥有/使用一个”关系，更容易替换组件。后端业务通常优先组合和依赖注入，继承适用于框架扩展点或明确的多态体系。

### `dataclass`、Pydantic 模型、ORM 模型有什么区别

- `dataclass`：减少普通数据对象样板代码，不自动承担外部输入校验；
- Pydantic 模型：解析和校验不可信边界数据，生成 schema；
- ORM 模型：描述数据库映射和持久化关系。

小项目可以适度复用，但复杂项目分离三者能防止数据库字段、API 契约和领域规则互相绑死。

### 类型注解会自动阻止错误类型吗

普通 Python 运行时通常不会强制注解。注解主要服务静态检查器、IDE、文档和框架。Pydantic 等库会主动读取注解并执行运行时校验，但那是库的行为。

### `Protocol` 有什么价值

`Protocol` 用结构化类型表达“只要提供这些方法就符合契约”，无需显式继承，适合依赖倒置和测试替身。

```python
from typing import Protocol


class UserRepository(Protocol):
    def get(self, user_id: int) -> "User | None": ...
```

业务服务依赖这个能力接口，而不是依赖具体 SQLAlchemy repository。

## 运行时、并发与异步

### CPython 如何管理内存

CPython 主要使用引用计数，对象引用数归零时通常立即回收；循环垃圾收集器补充处理引用环。`del name` 删除的是名称绑定，不保证对象立刻或一定被销毁，因为其他引用可能仍存在。

资源释放不要依赖对象析构时机，文件、锁、连接应使用 `with` / `async with`。

### GIL 是什么，不是什么

在常见的默认 CPython 构建中，GIL 使同一进程内通常只有一个线程执行 Python 字节码。它不等于“线程完全不能并发”：线程在网络、磁盘等待和许多释放 GIL 的扩展中仍有价值；它也不自动让复合操作线程安全。

CPU 密集纯 Python 计算通常考虑多进程、原生扩展或任务系统；I/O 密集任务可选择线程或异步。

### 线程、进程、协程如何选择

| 场景 | 常见选择 | 主要代价 |
| --- | --- | --- |
| 少量阻塞 I/O、已有同步库 | 线程池 | 线程切换、共享状态同步 |
| CPU 密集纯 Python | 进程池 | 启动、序列化、进程间通信 |
| 大量网络 I/O、异步生态 | `asyncio` | 调用链需异步，不能阻塞事件循环 |
| 独立、可重试的长任务 | 外部任务队列 | 基础设施与一致性设计 |

选择依据是瓶颈和依赖库，不是“异步一定更快”。

### 协程、Task、Future 的区别

- 调用 `async def` 得到协程对象，它尚未自动完成；
- `Task` 把协程安排到事件循环中并跟踪结果；
- `Future` 是将来会得到结果的低层占位抽象，Task 是其常见高层实现。

### `await` 会阻塞吗

`await` 会暂停当前协程，让事件循环运行其他可执行任务；但如果被调用代码内部执行阻塞 I/O 或长时间 CPU 计算，整个事件循环仍会被阻塞。

### `gather` 与 `TaskGroup` 如何选择

`gather` 适合把一组结果按输入顺序收集；失败与取消需要理解参数和调用方式。Python 3.11+ 的 `TaskGroup` 提供结构化并发：一个子任务失败会取消其余子任务，退出时可能抛 `ExceptionGroup`，更适合“同生共死”的相关任务。

### 为什么要传播取消

取消是协程生命周期的一部分。捕获宽泛异常后吞掉取消，可能导致请求已断开但后台仍消耗资源。需要清理时用 `try/finally`，清理后继续传播；不要无条件把取消转换成普通成功。

### `AsyncSession` 能在多个任务间共享吗

不应把同一个 SQLAlchemy `AsyncSession` 并发用于多个 task。它代表有状态的事务单元；通常每个请求/任务创建一个会话，并用 `async with` 管理。

### 如何把阻塞函数接入异步代码

短期可以 `await asyncio.to_thread(blocking_call, ...)` 把阻塞 I/O 放到线程。但这不会让 CPU 密集代码变快，也不能修复本身线程不安全的库。更好的长期方案是使用原生异步客户端或隔离服务。

## FastAPI 与 Web 后端

### ASGI 与 WSGI 的核心区别

WSGI 主要描述同步请求/响应调用；ASGI 支持异步调用和 HTTP、WebSocket、生命周期等事件。FastAPI 是 ASGI 应用，Uvicorn 等 ASGI server 负责网络协议与应用之间的转换。

### FastAPI 为什么能自动生成文档

它读取路径操作、类型注解和 Pydantic 模型，构建 OpenAPI schema，再由 Swagger UI / ReDoc 展示。自动文档不代表接口设计自动正确；仍要明确状态码、错误模型、认证和兼容策略。

### `async def` 和普通 `def` 路由如何选

- 调用原生异步 I/O 时用 `async def` 并 `await`；
- 使用无法替换的阻塞库时可用普通 `def`，FastAPI 会在线程池执行；
- CPU 密集工作不要长期占用请求 worker，应放到进程、任务队列或专用计算服务。

最危险的是在 `async def` 中直接调用阻塞网络、文件或数据库 API。

### 依赖注入解决什么问题

路径函数声明自己需要的能力，FastAPI 负责解析依赖图、执行依赖和清理 `yield` 资源。典型用途包括数据库会话、当前用户、权限、分页参数和共享客户端。

依赖不是 service locator；业务层仍应通过明确参数表达依赖。测试可用 `app.dependency_overrides` 替换边界实现，结束后记得清除。

### 请求模型和响应模型为什么要分离

创建请求不应允许客户端传数据库 ID、密码哈希、所有者 ID 等服务端字段；响应也不能意外暴露内部字段。分离后每个边界更小、更稳定，并可针对更新定义所有字段可选的模型。

### Pydantic 的“校验”是严格拒绝吗

Pydantic 默认可能执行合理类型转换，例如某些字符串转数字。安全或协议要求严格时应使用严格类型/严格模式，并在测试中明确可接受输入。验证成功只表示结构满足模型，不等于业务规则和权限已经满足。

### 为什么响应模型也是安全边界

FastAPI 会按响应模型序列化和过滤输出。即使业务对象多出 `password_hash`，正确的响应模型也不应包含它。但不要只靠过滤补救混乱设计，service 返回的 DTO 也应尽量最小化。

### middleware 与 dependency 如何选择

- middleware 适合几乎所有请求都要执行的协议级逻辑，如请求 ID、耗时、统一安全头；
- dependency 能拿到路由参数和认证上下文，适合权限、会话和业务前置条件；
- exception handler 负责异常到响应的集中映射。

### BackgroundTasks 适合重任务吗

它适合响应后执行的小型、同进程任务。进程崩溃会丢失任务，也没有天然重试和跨机器调度。耗时长、必须成功或需要可靠重试的任务应交给持久化任务队列。

### JWT 是加密的吗

常见签名 JWT 只保证内容未被篡改，并不加密 payload，任何拿到 token 的人都可解码内容。不要放密码或敏感隐私；必须校验签名算法、`exp`、主体和需要的 issuer / audience，密钥来自安全配置。

### CORS 是后端认证吗

不是。CORS 是浏览器执行的跨源访问策略，不阻止非浏览器客户端直接请求 API。服务端仍必须做认证和授权。带凭证时不能随意把允许源配置为任意来源。

### 401 与 403 的区别

- 401：缺少或无法验证身份，通常配合 `WWW-Authenticate`；
- 403：身份已知，但无权执行该操作。

是否用 404 隐藏资源存在性取决于威胁模型和 API 约定，但同一系统应保持一致。

## 数据库与事务

### ORM 是否意味着不需要懂 SQL

不是。ORM 负责对象映射和语句构建，性能、索引、连接、事务隔离和查询计划仍由数据库机制决定。能阅读 ORM 生成的 SQL 是后端基本能力。

### SQLAlchemy Session 是连接吗

Session 是工作单元和对象状态管理边界，按需从连接池获取连接并管理事务；它不等同于一条永久数据库连接。Session 有状态，不应作为进程全局单例或在并发任务间共享。

### `flush` 与 `commit` 的区别

- `flush` 把当前变更发给数据库，使生成 ID、约束等可见，但事务尚未提交，仍可回滚；
- `commit` 提交事务，使变更对其他事务按隔离规则可见。

请求内到处 `commit` 会破坏一个业务用例的原子性。通常由 service / unit of work 决定事务边界。

### 什么是 N+1 查询

先查 N 个父对象，随后访问每个对象的懒加载关系又执行一次查询，总计 1+N 次。解决方案包括按访问模式使用 `selectinload`、`joinedload`、显式 join 或聚合查询；不是把所有关系永久改成急加载。

### 为什么需要索引

索引可减少查询扫描，但会占空间并增加写入维护成本。应根据真实过滤、连接和排序模式设计复合索引，并用执行计划验证；“每个字段都加索引”不是优化。

### 事务隔离解决什么

并发事务可能出现脏读、不可重复读、幻读或写覆盖。数据库隔离级别、行锁、乐观锁和业务幂等各解决不同问题。先明确要保护的不变量，再选机制。

### 乐观锁如何工作

表中增加 `version`，更新时条件包含旧版本：

```sql
UPDATE task
SET title = :title, version = version + 1
WHERE id = :id AND version = :old_version;
```

影响行数为零表示数据已被其他请求修改，应用可返回冲突并让客户端重新读取。它适合冲突较少的场景。

### offset 与 cursor 分页

- offset 简单、可跳页，但深分页成本高；持续插入时可能重复或遗漏；
- cursor 基于稳定、唯一的排序键继续查询，性能和一致性通常更好，但不能轻易跳到任意页。

cursor 常用 `(created_at, id)` 作为复合游标，必须保证排序确定。

### 数据库迁移为什么不能只用 `create_all`

`create_all` 适合首次创建缺失表，不记录有序 schema 演进，也不会可靠完成列重命名、数据回填等变更。团队项目使用 Alembic 生成并审查迁移，先备份、再部署兼容变更、最后清理旧结构。

## 测试、部署与安全

### 单元测试与集成测试的边界

- 单元测试隔离外部系统，快速验证业务分支；
- 集成测试使用真实或高度接近真实的数据库、HTTP 边界，验证组件契约；
- 端到端测试覆盖已部署系统的关键用户流程。

测试金字塔不是固定比例。数据库行为高度关键时，适量真实数据库集成测试比大量 ORM mock 更有价值。

### fixture 解决什么问题

fixture 负责测试的准备、共享与清理，并通过依赖声明组合。fixture 应尽量小、清晰，资源清理放在 `yield` 后；不要让全局 autouse fixture 隐式改变所有测试，除非确有全局不变量。

### mock 应该放在哪里

mock 系统边界和不稳定协作者，不要把被测实现的每个内部调用都 mock。应在“被测模块查找名称的位置”打补丁，而不是只看原对象定义位置。过度 mock 会让重构困难，并可能出现测试通过但真实集成失败。

### 覆盖率 100% 是否表示没有 Bug

不表示。覆盖率只说明哪些代码被执行，未评价输入空间、断言质量、并发行为和外部契约。优先覆盖高风险规则、错误分支和过去出现过的回归。

### 健康检查应该检查什么

- liveness：进程是否活着，失败时平台可重启；不应依赖大量外部系统；
- readiness：当前实例是否准备接收流量，可检查关键依赖；
- startup：慢启动应用是否已完成初始化。

把所有上游都塞进 liveness 会在一个依赖故障时引发整个服务反复重启。

### 多 worker 会共享内存吗

通常每个 worker 是独立进程，模块全局缓存和锁不跨进程共享。需要共享的一致状态应放数据库、Redis 等外部系统；内存缓存只能视为单实例局部优化。

### 密钥应该放在哪里

本地可用未提交的 `.env`；测试使用假密钥；生产由平台环境变量、secret store 或挂载密钥注入。日志、traceback、镜像层、Git 历史和前端代码都不应包含生产密钥。

### 密码应如何保存

使用专门的密码哈希算法（如当前推荐配置的 Argon2），通过成熟库生成带盐哈希并验证。不能保存明文，不能用普通快速哈希（SHA-256）代替密码哈希，也不要自己设计加密方案。

### 什么是幂等

相同操作执行一次和多次产生等价最终效果。GET、PUT、DELETE 在 HTTP 语义上应设计为幂等；POST 默认不保证。支付、下单等重试场景可使用客户端幂等键、数据库唯一约束和原子事务防重。

### 重试有哪些前提

只重试暂时性错误和安全操作，设置最大次数、总体超时、指数退避和抖动。认证失败、参数错误通常不应重试。多层同时重试会放大流量，应明确由哪一层负责。

### 日志、指标、追踪分别回答什么

- 日志：某个离散事件发生了什么；
- 指标：系统总体是否健康、趋势如何；
- 分布式追踪：一次请求跨组件经过了哪里、耗时在哪里。

三者应通过 request ID / trace ID 关联，同时控制敏感数据和标签基数。

## 编码题

### 题一：稳定去重

保持首次出现顺序去重：

```python
from collections.abc import Hashable, Iterable
from typing import TypeVar

T = TypeVar("T", bound=Hashable)


def unique(items: Iterable[T]) -> list[T]:
    return list(dict.fromkeys(items))
```

追问：若元素不可哈希怎么办？可以用相等比较维护结果列表，但最坏复杂度变为 O(n²)；也可以要求调用者提供可哈希键函数。

### 题二：按键分组

```python
from collections import defaultdict
from collections.abc import Callable, Iterable
from typing import TypeVar

T = TypeVar("T")
K = TypeVar("K")


def group_by(items: Iterable[T], key: Callable[[T], K]) -> dict[K, list[T]]:
    groups: defaultdict[K, list[T]] = defaultdict(list)
    for item in items:
        groups[key(item)].append(item)
    return dict(groups)
```

追问：为什么最后转成普通 dict？它让返回契约更普通，避免调用者读取不存在键时意外修改结果。

### 题三：批处理生成器

```python
from collections.abc import Iterable, Iterator
from itertools import islice
from typing import TypeVar

T = TypeVar("T")


def batched(items: Iterable[T], size: int) -> Iterator[tuple[T, ...]]:
    if size < 1:
        raise ValueError("size 必须大于 0")

    iterator = iter(items)
    while batch := tuple(islice(iterator, size)):
        yield batch
```

新版本标准库已有 `itertools.batched`，这道题重点是理解迭代器，而不是重复造轮子。

### 题四：带 TTL 的缓存

要求自己实现一个只用于单进程学习的缓存：

- key 对应 value 和到期的单调时钟时间；
- 读取过期项时删除；
- 设置最大容量；
- 明确线程安全策略；
- 测试中注入时钟，不能真的 `sleep`。

讨论点：生产环境为什么可能选择 Redis；缓存穿透、击穿、雪崩分别是什么；多 worker 下本地缓存为何不一致。

### 题五：受限异步并发

```python
import asyncio
from collections.abc import Awaitable, Callable, Iterable
from typing import TypeVar

T = TypeVar("T")
R = TypeVar("R")


async def map_limited(
    function: Callable[[T], Awaitable[R]],
    items: Iterable[T],
    limit: int,
) -> list[R]:
    if limit < 1:
        raise ValueError("limit 必须大于 0")

    semaphore = asyncio.Semaphore(limit)

    async def run(item: T) -> R:
        async with semaphore:
            return await function(item)

    return await asyncio.gather(*(run(item) for item in items))
```

追问：如果 `items` 是百万级流，以上代码仍会一次创建百万个协程；应改成固定数量 worker 消费 `asyncio.Queue`，并设计取消和错误传播。

### 题六：LRU 缓存

先解释需求再编码：容量、更新是否提升热度、未命中返回什么、是否允许 `None`、线程是否安全。标准库已有 `functools.lru_cache`；面试手写通常使用 dict + 双向链表实现平均 O(1) get / put。

### 题七：API 分页响应

设计一个泛型分页模型，包含 `items`、`total`、`limit`、`offset`，并回答：

- `total` 是否每次都值得计算；
- `limit` 的最大值在哪里校验；
- 排序不稳定会怎样；
- 何时改成 cursor 分页。

### 题八：转账事务

伪代码实现 A 向 B 转账，必须保证余额不为负和总金额守恒。讨论行锁顺序、防死锁、事务隔离、幂等键、Decimal、审计流水，以及为什么“先查余额再分别更新”可能出现并发写覆盖。

## 故障排查题

### 场景一：本地正常，服务器 `ModuleNotFoundError`

排查顺序：

1. 输出 `sys.executable` 和 Python 版本；
2. 用 `python -m pip show` 确认包安装在同一环境；
3. 确认工作目录、启动模块和包结构；
4. 检查依赖文件是否完整、平台是否支持；
5. 检查是否有同名文件遮蔽真正模块。

不要用随手修改 `sys.path` 掩盖部署结构问题。

### 场景二：FastAPI 并发一高，所有请求都变慢

可能原因：

- `async def` 路由中使用同步 HTTP / 数据库客户端；
- CPU 密集计算占满事件循环；
- 数据库连接池太小或查询慢；
- 没有超时，上游请求长期占用资源；
- 每次请求创建新客户端，失去连接池；
- 日志 handler 或文件操作同步阻塞；
- 下游容量已达上限，盲目增加 worker 只会放大压力。

用延迟分段、连接池指标、慢查询和 event-loop lag 找证据，不要先猜框架性能差。

### 场景三：偶发 `MissingGreenlet`

SQLAlchemy 异步 ORM 常见原因是序列化响应时触发懒加载，I/O 发生在预期异步上下文之外。显式设计加载策略，在 session 有效期内预加载所需关系，避免把带未加载属性的 ORM 对象无约束地交给响应序列化。

### 场景四：测试单独运行通过，全量运行失败

通常存在共享可变状态、未清理 dependency override、环境变量泄漏、数据库事务未回滚、固定端口冲突或依赖执行顺序。随机化测试顺序、缩小失败组合，并确保 fixture 对资源有对称清理。

### 场景五：JWT 解码正常却出现越权

签名有效只证明 token 由可信密钥签发且未被修改，不代表当前用户有权访问目标资源。每次资源操作还要验证 owner / role / scope；不能直接相信请求体里的 `user_id`。

### 场景六：部署迁移后旧实例报错

数据库变更没有向前/向后兼容。采用 expand-contract：先增加兼容结构，部署同时兼容新旧 schema 的代码，回填数据，切换读写，最后在所有旧实例退出后删除旧结构。

### 场景七：内存持续增长

检查：无界缓存、队列消费者跟不上、未关闭响应/客户端/会话、任务被永久保存、日志缓冲、加载大文件、ORM identity map 生命周期过长。使用指标和内存分析确认“仍被谁引用”，不要把手动 `gc.collect()` 当根治方案。

### 场景八：重试导致重复订单

客户端超时不代表服务端没有成功。创建请求要有幂等键和数据库唯一约束，在同一事务内记录键与结果；再次收到相同键时返回原结果。只在客户端增加重试会扩大重复副作用。

- [ ] 能举例说明一个真实难点、排查证据、方案取舍和最终结果。
- [ ] 能指出当前方案在流量扩大后的瓶颈，而不是声称“高并发”。
- [ ] 能展示测试、迁移和部署说明，而不只展示接口截图。
