## 😎关于`ArrayList`

* 注意 `new` 出的 `arrayList` 的默认容量并不是10，`arrayList` 初始化的容量是0；

* 只有我们调用`add`方法时，才会创建一个长度为`10`的数组`elementDate`；

* 每次`add`时 ，指针`size`++;

* 当`size`大于数组长度时，触发扩容操作 `grow()`；

* 扩容后的新数组长度是原数组的1.5倍，这样做是为了性能和内存的平衡；

* 注意 `arrayList`不是线程安全的；

* `arrayList`的插入删除的性能很差，最坏的情况下，时间复杂度是`O(n)`;

* 因此，在使用`arrayList`时，要避免经常在数组的中间位置插入删除元素。

* 如需经常做此操作，建议使用`LinkedList`。

* 详细的扩容操作：

  ```java
  扩容逻辑在 grow(int minCapacity) 方法里：
  先算新容量 = 旧容量 + 旧容量 >> 1（即 1.5 倍）。
  如果新容量依旧小于你需要的最小容量 minCapacity，就会直接把新容量提升到 minCapacity。
  如果超过了 MAX_ARRAY_SIZE（Integer.MAX_VALUE - 8），就会调用 hugeCapacity 兜底。
  ```
  
* 有哪些接口可以使用`ArrayList`?

  ```java
  List<E>
  //最主要的接口，定义了有序集合（顺序存储、允许重复）的操作，比如：
  add(E e);
  remove(Object o);
  get(int index);
  set(int index, E element);
  size();
  ```

  
## ❤️关于HashMap

* **底层结构**：数组 + 链表 + 红黑树（JDK 1.8+）

* **哈希计算**：
  ```java
  // 扰动函数：高16位与低16位异或，减少碰撞
  static final int hash(Object key) {
      int h;
      return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
  }
  // 数组下标 = hash & (table.length - 1)  等价于 hash % length（但位运算更快）
  ```

* **put 流程**：
  ```java
  1. 计算 key 的 hash 值
  2. 如果 table 为空或长度为 0 → 先 resize() 初始化
  3. 计算下标 i = hash & (n - 1)
  4. 如果 table[i] 为 null → 直接创建新节点
  5. 如果 table[i] 不为 null：
     a. key 相同（equals）→ 覆盖 value
     b. 如果是 TreeNode →走红黑树插入
     c. 否则遍历链表，尾插法插入（JDK 1.8 改进，1.7 是头插法）
     d. 链表长度 >= 8 → 转红黑树（treeifyBin）
  6. size++ → 如果 size > threshold → resize() 扩容
  ```

* **扩容逻辑**：
  ```java
  1. 新容量 = 旧容量 * 2（始终为 2 的幂）
  2. 新阈值 = 新容量 * 负载因子（默认 0.75）
  3. 遍历旧 table 的每个桶：
     - 单节点：hash & 新容量 == 0 → 留在原位，否则移到 原位 + 旧容量 的位置
     - 链表：按 hash & 旧容量 拆分为两条链（低位链和高位链）
     - 红黑树：同样拆分，如果拆分后长度 <= 6 → 退化为链表
  ```

* **关键参数**：
  | 参数 | 默认值 | 说明 |
  |------|--------|------|
  | 初始容量 | 16 | 必须是 2 的幂 |
  | 负载因子 | 0.75 | 越大省内存但碰撞多，越小碰撞少但浪费空间 |
  | 树化阈值 | 8 | 链表长度 >= 8 时转红黑树 |
  | 退化阈值 | 6 | 红黑树节点 <= 6 时退化为链表 |
  | 最大容量 | 2^30 | 超过不再扩容 |

* **为什么选 8 作为树化阈值？**
  理想情况下，hash 值随机分布时，链表长度符合泊松分布。长度达到 8 的概率约为 0.00000006，极其罕见。选 8 是在时间和空间之间的折中。

* **线程安全问题**：
  - HashMap 不是线程安全的
  - JDK 1.7 头插法在并发 resize 时可能导致**死循环**（环形链表）
  - JDK 1.8 改为尾插法解决了死循环问题，但仍非线程安全
  - 多线程场景请使用 `ConcurrentHashMap`
