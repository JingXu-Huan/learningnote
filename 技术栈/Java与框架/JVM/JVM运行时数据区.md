## 一、先看总览

| 区域 | 是否线程共享 | 主要内容 | 常见说明 |
| --- | ---: | --- | --- |
| 程序计数器（PC Register） | 否 | 当前 Java 字节码指令位置 | 执行 native 方法时值未规定 |
| Java 虚拟机栈 | 否 | 一个个栈帧 | 常见 StackOverflowError |
| 本地方法栈 | 否 | native / JNI 调用支持 | 具体实现可不同 |
| 堆（Heap） | 是 | 类实例、数组 | GC 主要管理的对象区域 |
| 方法区（Method Area） | 是 | 类结构、运行时常量池、方法相关信息 | JVM 规范中的逻辑概念 |

另外，直接内存、Code Cache、JIT 相关数据、线程本地 / native 内存也会占用进程地址空间，但它们不应被简单画成“Java 堆的一部分”。

## 二、线程私有区域

### 1️⃣ 程序计数器

程序计数器可以理解为“当前线程下一条要执行的 Java 字节码指令位置”。

- 每个线程各有一个；
- 线程切换后能恢复到自己的执行位置；
- 当正在执行 native 方法时，JVM 规范不规定其值。

### 2️⃣ Java 虚拟机栈

每个 Java 线程创建时，会有一个 Java 虚拟机栈。每次调用 Java 方法，就会创建一个**栈帧**；方法正常返回或异常退出后，栈帧被销毁。

栈帧通常包含：

- 局部变量表；
- 操作数栈；
- 动态链接；
- 方法返回信息。

常见异常：

- 递归太深、栈帧太大：StackOverflowError；
- 无法申请足够栈空间：OutOfMemoryError。

### 3️⃣ 本地方法栈

本地方法栈用于支持 native 方法。不同 JVM 对它的实现可能不同，某些实现会把它与虚拟机栈合并。

------

## 三、线程共享区域

### 1️⃣ 堆（Heap）

按 JVM 规范，类实例和数组在堆上分配。堆由所有线程共享，通常是自动内存管理和 GC 的核心区域。

注意两点：

1. “对象逻辑上在堆”是规范层的表述；
2. 具体 JVM 可能利用 TLAB、逃逸分析、标量替换甚至消除分配。因此“每个对象在机器上都实际占一块堆内存”并不严谨。

### 2️⃣ 方法区（Method Area）

方法区是 JVM 规范定义的逻辑区域，用于存放每个类或接口的结构信息，例如：

- 运行时常量池；
- 字段与方法信息；
- 方法字节码等。

运行时常量池是每个类 / 接口对应常量池在运行时的表示，逻辑上属于方法区。

## 四、一次方法调用发生了什么

用下面的简化代码串起来看：

~~~java
public static void main(String[] args) {
    User user = new User();
    work(user);
}
~~~

1. **类加载**：User、当前类等相关类的信息进入方法区的逻辑范畴；
2. **进入 main**：当前线程的虚拟机栈压入 main() 栈帧，PC 指向正在执行的字节码；
3. **new User()**：对象实例逻辑上在堆中；main() 的局部变量表保存一个引用；
4. **调用 work(user)**：压入新的 work() 栈帧，成为当前栈顶帧；
5. **方法返回**：work() 栈帧弹出，控制权回到 main()；
6. **对象是否可回收**：不由“某个栈帧弹出”单独决定，而由从 GC Roots 出发的可达性决定。

可以把“引用在栈帧中、对象逻辑在堆中”理解为最常见的学习模型，但不要把它误读成“对象永远不能被优化到其他形式”。

## 五、方法区、永久代与 Metaspace

这三个词最容易被混为一谈：

| 名称 | 所属层次 | 正确理解 |
| --- | --- | --- |
| 方法区 | JVM 规范 | 逻辑概念 |
| 永久代（PermGen） | 旧版 HotSpot 实现 | 曾用于实现方法区的一种方案 |
| Metaspace | JDK 8+ HotSpot 实现 | 主要承载类元数据，使用本地内存 |

因此下面的等式都不严谨：

- 方法区 = 永久代；
- 方法区 = Metaspace；
- 静态变量都在 Metaspace。

JDK 8 移除了永久代，HotSpot 改用 Metaspace 承载类元数据。实际排障时，应该结合 JVM 版本、启动参数和监控信息判断，而不是只凭旧版教材中的内存图。

## 六、堆、栈与对象引用的正确关系

一个常见误解是：

> 栈里存对象，堆里只存成员变量。

更准确的表述是：

- 栈帧中的局部变量表可以放基本类型值，也可以放**对象引用**；
- 引用指向的对象实例，按 JVM 规范逻辑上属于堆；
- 成员变量属于对象的一部分，随对象存储；
- 具体机器级布局和 JVM 优化属于实现细节。

因此，下面的局部变量 user 本身更像一个“引用入口”：

~~~java
User user = new User();
~~~

GC 会从活动线程栈帧中的 user 等引用开始追踪。只要还能沿着引用链找到对象，它通常就仍可达。

## 七、常见异常与误区

### StackOverflowError 一定是内存泄漏吗？

不一定。最常见原因是无限递归、递归层数过深或单个栈帧过大。它首先是“线程栈空间耗尽”的信号。

### Java heap space 就是 JVM 整个进程内存满了吗？

不完全是。它表示 Java 堆无法满足分配；进程还可能使用 Metaspace、Direct Memory、Code Cache、线程栈和其他 native 内存。

### 栈帧弹出后，对象立刻被 GC 吗？

不保证。对象是否可回收由可达性决定，GC 的实际运行时机也由 JVM 与收集器决定。

### Method Area 是不是永久代？

不是。方法区是规范概念；永久代是已被 JDK 8 移除的旧版 HotSpot 实现；Metaspace 是现今 HotSpot 中与类元数据相关的本地内存实现。

### 一句话总结

> JVM 运行时数据区里，PC、虚拟机栈和本地方法栈偏向线程私有；堆和方法区属于线程共享。方法区是规范抽象，Metaspace 是 HotSpot 的实现细节。
