JMM：完整的重点是同步关系，不是“区域列表”

JMM 不规定 JVM 堆、栈或 CPU Cache 的物理结构。它规定线程间读写的合法可见性、排序约束和 happens-before 关系；下图用安全发布和丢失更新两个典型问题覆盖三个核心维度。

JLS 第 17 章
关键边界：“主内存 / 工作内存”仅是 JMM 抽象，不能分别等同 JVM 堆 / 虚拟机栈，也不能当成 CPU Cache 的实物图。

安全发布协议：线程 A 先写普通变量 data = 42，再写 volatile ready = true；线程 B 先读到 ready == true，随后读取 data。JMM 通过程序顺序、volatile 规则及传递性建立可推理的结果。

线程 A（执行 publish）

data = 42普通写：仅靠这一句不保证 B 立即可见
ready = truevolatile 写：发布边界

JMM 中的同步顺序

程序顺序：data 写 → ready 写
volatile：ready 写 → 后续 ready 读
传递性：发布前 data 写对 B 可见

线程 B（执行 consume）

if (ready)先进行 volatile 读
use(data)读到发布前写入的 42

原子性反例：volatile count++ 仍会丢失更新

A read 0→B read 0→A write 1→B write 1→ final 1

需要复合原子性时：锁或 AtomicInteger

CAS / lock→串行化更新→ final 2

当前场景：绿色边框 = 从 GC Roots 可达；红色 = 不可达；对象移动表示 evacuation（复制/转移），不是普通内存拷贝 API。

本步检查点

  • 方法区是 JVM 规范的逻辑概念。
  • JDK 8+ HotSpot 的 Metaspace 使用 native memory。
  • 不要把永久代、方法区、Metaspace 当作三个同义词。
总原则：JVMS 明确把运行时数据区定义为抽象机器的一部分，但并不规定这些区域的物理内存布局，也不规定垃圾收集算法。页面中所有 Eden / Survivor / Region / Metaspace 内容都明确标成 HotSpot 实现层或教学模型。
