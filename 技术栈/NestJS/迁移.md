# Java / Spring Boot + Vue → NestJS + Go 快速迁移指南

> 目标：已有 **Java / Spring Boot + Vue** 基础，在短时间内迁移到 **NestJS + Go** 技术栈。  
> 核心思路不是“重新学一遍后端”，而是：
>
> **复用已有的后端工程思维，只补语言差异、运行时差异和框架 API。**

---

# 1. 明确迁移所需的技术基础

本指南面向具有以下技术基础的开发者：

```text
前端：
Vue

后端：
Java
Spring Boot
Spring MVC
Spring Security
MyBatis / MyBatis-Plus
MySQL
Redis
RocketMQ
XXL-Job
```

目标技术栈主要包括：

```text
NestJS
Go
```

所以真正需要迁移的是后端部分。

本指南假设读者已有 Vue 使用经验，因此不安排 React 与 Vue 之间的前端迁移。

后端迁移可以拆成两条路线：

```text
Java / Spring Boot
        │
        ├────────────→ TypeScript → Node.js → NestJS
        │
        └────────────→ Go → HTTP → DB → Redis → 并发
```

其中：

- **NestJS 属于“框架迁移”**
- **Go 属于“语言 + 运行模型迁移”**

因此 NestJS 的迁移速度会明显快于 Go。

# 2. NestJS 到底是什么？

## 2.1 一句话理解 NestJS

NestJS 是一个运行在 **Node.js** 上的后端框架，主要使用：

```text
TypeScript
```

开发。

可以把它粗略理解为：

> **Node.js / TypeScript 生态里的 Spring Boot。**

它并不是 JavaScript 的某种新语言，而是一个后端 Web 框架。

整个关系是：

```text
TypeScript
    ↓
JavaScript
    ↓
Node.js
    ↓
NestJS
```

对应 Java：

```text
Java
    ↓
JVM
    ↓
Spring Boot
```

所以学习 NestJS 之前，需要先理解三件东西：

```text
TypeScript
Node.js
NestJS
```

# 3. TypeScript 是什么？

TypeScript 可以简单理解为：

> JavaScript + 类型系统。

例如 Java：

```java
public User getUser(Long id) {
    return userService.getById(id);
}
```

TypeScript：

```typescript
getUser(id: number): User {
  return this.userService.getById(id);
}
```

如果已经习惯 Java，TypeScript 的类型反而比较容易接受。

例如：

```typescript
interface User {
  id: number;
  name: string;
  age: number;
}
```

和 Java：

```java
public class User {

    private Long id;

    private String name;

    private Integer age;
}
```

思想非常接近。

NestJS 最吸引 Java / Spring 开发者的一点，就是它的工程结构和 Spring 非常接近。

```text

│   └── User.java
├── dto
│   └── CreateUserDTO.java
└── config
```

可以看到整体思路并没有发生根本变化。

# 8. Spring Boot → NestJS 核心概念迁移

## Controller

Spring：

```java
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping("/{id}")
    public User getUser(@PathVariable Long id) {
        return userService.getUser(id);
    }
}
```

NestJS：

```typescript
@Controller('users')
export class UserController {

  constructor(
    private readonly userService: UserService,
  ) {}

  @Get(':id')
  getUser(@Param('id') id: string) {
    return this.userService.getUser(id);
  }
}
```

基本是镜像关系。

Spring：

```java
@Service
public class UserService {
}
```

```typescript
@Injectable()
export class UserService {
}
```

NestJS 中通常称这些对象为：

```text
Provider
```

```text
Service
Repository
Factory
Helper
```

都可以作为 Provider 注册到 NestJS 的依赖注入容器。

# 10. Spring DI → NestJS DI

Spring：

```java
@Service
public class OrderService {

    private final UserService userService;

    public OrderService(UserService userService) {
        this.userService = userService;
    }
}
```

NestJS：

```typescript
@Injectable()
export class OrderService {

  constructor(
    private readonly userService: UserService,
  ) {}

}
```

核心思想完全一致：

```text
对象不要自己 new
        ↓
交给 IoC Container 创建
        ↓
通过构造器注入依赖
```

已有的 Spring IoC / DI 思维可以作为理解 NestJS 依赖注入的基础。

# 11. NestJS Module 是什么？

这是 NestJS 一个非常重要的概念。

例如：

```typescript
@Module({
  controllers: [UserController],
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

它负责描述：

```text
这个模块有哪些 Controller
这个模块有哪些 Provider
这个模块暴露哪些 Provider
这个模块依赖哪些其他 Module
```

例如：

```text
UserModule
OrderModule
AuthModule
RedisModule
PaymentModule
```

最终：

```typescript
@Module({
  imports: [
    UserModule,
    OrderModule,
    AuthModule,
  ],
})
export class AppModule {}
```

可以把 NestJS Module 理解成：

> **显式声明某一业务模块的依赖关系和 Bean 边界。**

Spring Boot 中虽然没有完全一模一样的业务 Module 概念，但：

```text
@Configuration
@ComponentScan
Bean 注册
包结构
ApplicationContext
```

承担了一部分相似职责。

# 15. NestJS Pipe 是什么？

Pipe 主要负责：

```text
参数校验
参数转换
```

Spring：

```java
@PostMapping
public void create(
    @Valid @RequestBody CreateUserDTO dto
) {

}
```

NestJS：

```typescript
@Post()
create(
  @Body() dto: CreateUserDto,
) {

}
```

```typescript
export class CreateUserDto {

  @IsString()
  username: string;

  @IsInt()
  age: number;

```

```typescript
ValidationPipe
```


# 16. NestJS Exception Filter

Spring 通常：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public Result<?> handle(Exception e) {
        ...
    }
}
```

NestJS：

```typescript
@Catch()
export class GlobalExceptionFilter
  implements ExceptionFilter {

  catch(exception: unknown, host: ArgumentsHost) {

  }
}
```

对应：

```text
@RestControllerAdvice
@ExceptionHandler
        ↓
Exception Filter
```

所以异常处理模式基本可以直接迁移。

# 17. NestJS Interceptor

Spring：

```java
HandlerInterceptor
```



```typescript
@Injectable()
```

# 25. Go 最大的语言差异：错误处理

Java：

```java
try {
    userService.create(user);
} catch (Exception e) {
    ...
}
```

Go 更常见：

```go
user, err := userService.Create()

if err != nil {
    return err
}
```

也就是说 Go 大量使用：

```text
显式错误返回
```

而不是：

```text
Exception
try/catch
```

这是 Java 开发者必须快速适应的地方之一。

# 26. Go 的 interface

Java：

```java
public interface UserService {

    User getUser(Long id);

}
```

Go：

```go
type UserService interface {
    GetUser(id int64) (*User, error)
}
```

但是 Go 有一个很重要的区别：

> **不需要显式写 implements。**

只要方法满足接口：

```go
type UserServiceImpl struct {
}
```

实现：

```go
func (s *UserServiceImpl) GetUser(
    id int64,
) (*User, error) {

}
```

就自动满足：

```go
UserService
```

接口。

# 32. Go Goroutine

Java：

```java

    sendMessage();

```

```go

```

这里：

```text

```

会启动一个：

```text

```

可以粗略理解为：

> 一种非常轻量级的并发执行单元。

但不能简单等价成：

```text
goroutine = Java Thread
```

# 33. Go Channel

Java 并发中经常有：

```text
BlockingQueue
Future
CompletableFuture
线程通信
```

Go 中一个核心工具是：

```text
channel
```

例如：

```go
ch := make(chan int)

go func() {
    ch <- 10
}()

value := <-ch
```

核心思想是：

```text
goroutine
    ↓
channel
    ↓
goroutine
```

# 39. 迁移方案的依据

该方案面向已有后端开发经验的读者，学习任务并非：

```text
从零学习后端开发
```

而是：

```text
已有后端知识
        ↓
映射到新的语言和框架
```

比如：

```text
HTTP
REST
Controller
Service
DTO
DI
Redis
MySQL
事务
缓存
MQ
权限
参数校验
异常处理
```

这些概念不会因为：

```text
Java → TypeScript → Go
```

发生本质变化。

变化的是：

```text
语言语法
框架 API
运行时模型
工程规范
```

学习过程中不必先完整通读：

```text
《NestJS 从入门到精通》
《Go 从入门到精通》
```

而是：

```text
已有概念
    ↓
寻找对应实现
    ↓
立即写 Demo
    ↓
放进完整项目
```

通过这种方式提高迁移速度。

# 40. 面试中的迁移方案说明

说明 Java / Spring 向 NestJS + Go 的迁移方案时，可以按以下顺序组织内容：

1. **已有基础**：说明实际掌握的 Vue、Java、Spring Boot 及后端工程经验，不把教程中的示例能力当作个人经历。
2. **NestJS 路径**：补齐 TypeScript、Node.js 异步模型和包管理，再建立 Controller、Provider、DI、Pipe、Exception Filter、Guard 与 Interceptor 的对应关系。
3. **NestJS 实践**：第一周通过小型项目练习登录鉴权、DTO 校验、MySQL、Redis 缓存、全局异常处理和 Swagger，并以实际运行结果验收。
4. **Go 路径**：先学习 struct、interface、error、slice、map，再练习 HTTP、MySQL、Redis，重点补齐 goroutine、channel、Context 与 Mutex。
5. **阶段目标**：以能够开发 NestJS 常见业务接口、阅读 Go 项目调用链并完成基础需求为目标，后续结合项目继续深入；不承诺两周精通两门技术。

重点是区分可复用的后端知识与必须补齐的语言、运行时和框架差异，并提供可验证的实践成果。

# 41. 最重要的迁移原则

最后整个学习路线可以浓缩成：

```text
NestJS：

Spring经验
   ↓
TypeScript
   ↓
Node.js
   ↓
NestJS
   ↓
完整 CRUD 项目
```

以及：

```text
Go：

Java后端经验
   ↓
Go语法
   ↓
HTTP
   ↓
MySQL / Redis
   ↓
goroutine / channel
   ↓
Context
   ↓
完整业务项目
```

迁移能力应通过可复用知识、差异分析、学习路径和项目成果体现，而不是通过“已经掌握新技术”的笼统表述证明。

对于实习岗位，清楚说明当前能力边界，并展示实际完成的接口、测试和项目调用链，比承诺短期精通更有说服力。
