4.那这个其实就是穿透对吧？那你打算怎么防？你布隆过滤器放哪一层？你布隆过滤器误判了咋办？误判了是不是得兜底查库？那数据库就又被打爆了呀

```
布隆过滤器放在最前面的那一层，也就是接受到请求就马上进入过滤器

```

5.一个热点数据刚好失效，被几万请求同时打到数据库，这时候你会锁住那个key吗？那锁的粒度是多大？`Redis`锁？本地锁？锁超时了咋办

```
锁住那个key.
锁的粒度是 那个短链key。
	当热点数据失效时，我们采用的是逻辑过期，发现数据过期之后，让一个线程尝试获取redis分布式锁，获取锁成功的线程去查询数据库并且重建缓存，失败的线程则返回旧数据。
	关于锁超时问题：可以采用看门狗机制，对正在执行业务的线程进行续期，保证线程不会在执行过程中锁被释放。
	如果当前线程崩溃，可以引入重试机制，当重试次数过多，说明数据库状态不好，或者是代码逻辑存在问题。此时停止重试，以免数据库崩溃。所有的请求都返回旧数据，让人工接入处理，排查数据库或者是其他问题。
采用redis分布式锁
```

9为什么InnoDB选择B+树作为索引？

```
B+ 树节点内可以存放更多键值（非叶节点只存索引键），IO次数更少。
叶子节点通过链表连接，支持范围查询。
树高低、稳定，更适合磁盘存储结构。
```

22.谈谈线程池工作的流程

```
1. 提交任务到线程池
2. 如果当前运行线程数 < corePoolSize → 创建核心线程执行任务
3. 如果当前运行线程数 >= corePoolSize → 将任务放入阻塞队列
4. 如果阻塞队列已满 且 当前线程数 < maximumPoolSize → 创建非核心线程执行任务
5. 如果当前线程数 == maximumPoolSize 且队列也满 → 执行拒绝策略（AbortPolicy/DiscardPolicy/DiscardOldestPolicy/CallerRunsPolicy）
6. 任务执行完毕后，线程不会销毁，而是去队列取下一个任务
7. 非核心线程空闲超过 keepAliveTime 后会被回收
```
