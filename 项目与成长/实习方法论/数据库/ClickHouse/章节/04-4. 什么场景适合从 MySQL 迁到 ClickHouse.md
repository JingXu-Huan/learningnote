# 4. 什么场景适合从 MySQL 迁到 ClickHouse

## 适合迁移的场景

- 每天都要跑统计报表
- 大量 `GROUP BY`、`COUNT`、`SUM`、`AVG`
- 时间范围查询很多，比如近 7 天、近 30 天、按小时统计
- 埋点、日志、传感器、设备数据量很大
- MySQL 已经开始因为分析 SQL 太重而拖慢业务

## 不适合直接迁移的场景

- 订单支付核心链路
- 账户余额变更
- 秒杀扣库存
- 需要强事务一致性的业务
- 大量单条更新 / 删除

所以最推荐的迁移姿势是：

- **保留 MySQL 作为主业务库**
- **新增 ClickHouse 作为分析库**
