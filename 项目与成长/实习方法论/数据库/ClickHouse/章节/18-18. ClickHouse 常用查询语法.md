# 18. ClickHouse 常用查询语法

以下示例使用 `device_metric` 表：

```sql
-- device_id String, temperature Float32, humidity Float32, create_time DateTime
```

## 18.1 一条查询的常见骨架

```sql
SELECT
    device_id,
    count() AS report_count,
    round(avg(temperature), 2) AS avg_temperature
FROM device_metric
PREWHERE create_time >= now() - INTERVAL 7 DAY
WHERE temperature >= 0
GROUP BY device_id
HAVING report_count >= 10
ORDER BY avg_temperature DESC
LIMIT 20;
```

可以按这个顺序理解：`FROM` 取数据，`PREWHERE`/`WHERE` 过滤明细，`GROUP BY` 分组，`HAVING` 过滤分组结果，最后用 `ORDER BY` 和 `LIMIT` 整理输出。

## 18.2 明细查询与条件筛选

```sql
SELECT device_id, temperature, create_time
FROM device_metric
WHERE device_id IN ('water-001', 'water-002')
  AND create_time >= toDateTime('2026-07-20 00:00:00')
  AND temperature BETWEEN 20 AND 30
ORDER BY create_time DESC
LIMIT 100;
```

- 空值判断使用 `IS NULL`、`IS NOT NULL`，不要写 `= NULL`。
- 字符串模糊匹配可使用 `LIKE '%water%'`；正则匹配使用 `match(device_id, '^water-\\d+$')`。
- 不需要所有列时，避免写 `SELECT *`，列式存储下只读取实际需要的列更省资源。

## 18.3 `WHERE` 与 `PREWHERE`

`WHERE` 是标准过滤条件。对于 MergeTree 大表，如果先用分区、排序键中的少数列筛选，可以显式写 `PREWHERE`：

```sql
SELECT device_id, temperature, create_time
FROM device_metric
PREWHERE device_id = 'water-001'
     AND create_time >= now() - INTERVAL 1 DAY
WHERE temperature > 30;
```

`PREWHERE` 会先读取用于筛选的列，命中后再读取 `temperature` 等其他列，适合“先过滤掉大量行”的场景。很多简单查询 ClickHouse 会自动下推；不确定时先写普通 `WHERE`，再用 `EXPLAIN indexes = 1` 验证。

## 18.4 聚合、条件聚合与去重计数

```sql
SELECT
    toDate(create_time) AS dt,
    count() AS report_count,
    countIf(temperature >= 30) AS hot_count,
    round(avg(temperature), 2) AS avg_temperature,
    max(temperature) AS max_temperature,
    uniqExact(device_id) AS device_count
FROM device_metric
WHERE create_time >= now() - INTERVAL 7 DAY
GROUP BY dt
ORDER BY dt;
```

- `count()` 统计行数；`count(column)` 不统计该列为 `NULL` 的行。
- `countIf`、`sumIf`、`avgIf` 用于条件聚合。
- `uniqExact` 是精确去重；数据量很大且允许近似时可考虑 `uniq` 或 `uniqCombined64`。
- `GROUP BY` 后的过滤用 `HAVING`，例如 `HAVING report_count > 100`。

## 18.5 时间分桶

```sql
SELECT
    toStartOfHour(create_time) AS hour,
    count() AS report_count,
    avg(temperature) AS avg_temperature
FROM device_metric
WHERE create_time >= now() - INTERVAL 24 HOUR
GROUP BY hour
ORDER BY hour;
```

常用函数：`toDate()`（按天）、`toStartOfHour()`（按小时）、`toStartOfDay()`、`toStartOfMonth()`、`toYYYYMM()`（年月分区键常用）。

## 18.6 排序、分页与每组 Top N

```sql
-- 普通分页：适合小偏移量；深分页依然会越来越慢
SELECT *
FROM device_metric
ORDER BY create_time DESC
LIMIT 20 OFFSET 0;

-- 每个设备取最新 3 条记录
SELECT *
FROM device_metric
ORDER BY create_time DESC
LIMIT 3 BY device_id;
```

分析场景优先按时间或主键范围翻页，例如在下一页加入 `create_time < 上一页最后一条时间`，避免很大的 `OFFSET`。

## 18.7 JOIN 与子查询

```sql
SELECT
    m.device_id,
    d.device_name,
    avg(m.temperature) AS avg_temperature
FROM device_metric AS m
LEFT JOIN device_dim AS d ON m.device_id = d.device_id
WHERE m.create_time >= now() - INTERVAL 1 DAY
GROUP BY m.device_id, d.device_name;
```

ClickHouse 支持 `INNER`、`LEFT`、`RIGHT`、`FULL`、`CROSS` 等 JOIN。大表关联通常比单表聚合更贵：维表放右侧、只选择必要字段，并优先考虑宽表、字典（Dictionary）或预聚合结果。

```sql
WITH recent_metric AS
(
    SELECT *
    FROM device_metric
    WHERE create_time >= now() - INTERVAL 1 DAY
)
SELECT device_id, max(temperature) AS max_temperature
FROM recent_metric
GROUP BY device_id;
```

## 18.8 窗口函数

```sql
SELECT
    device_id,
    create_time,
    temperature,
    row_number() OVER (
        PARTITION BY device_id
        ORDER BY create_time DESC
    ) AS rn,
    lagInFrame(temperature, 1, NULL) OVER (
        PARTITION BY device_id
        ORDER BY create_time
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS previous_temperature
FROM device_metric;
```

常用窗口函数有 `row_number()`、`rank()`、`dense_rank()`、`sum() OVER (...)`。窗口计算需要排序，数据量大时应先用时间范围缩小输入。

## 18.9 排查查询是否利用了表结构

```sql
EXPLAIN indexes = 1
SELECT device_id, avg(temperature)
FROM device_metric
WHERE device_id = 'water-001'
  AND create_time >= now() - INTERVAL 7 DAY
GROUP BY device_id;
```

重点看查询条件是否贴合 `PARTITION BY` 与 `ORDER BY`：对于本表，按 `device_id` 加时间范围查询通常比只按 `temperature` 筛选更容易跳过无关数据。
