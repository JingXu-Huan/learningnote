# 统计每天客服导出订单的数量，支持每日零点重置
## `SQL`方案基本原理：
1. `SQL`脚本的基本结构：

   ```sql
   create table export_record
   (
       customer_id bigint not null,
       export_date         date   not null,
       export_no           int    not null
   )
   ```

   聊一下字段的作用：

   `customer_id` 表示当前用户的身份。

   `export_date` 表示当前导出记录的导出时间。

   `export_no` 表示用户的导出记录的导出编号。

   ------
2. 查询语句怎么写？

   ```SQL
   select coalesce(max(export_no), 0)
   from export_record
   where customer_id = #{customerId}
     and export_date = #{exportDateText}
   ```
   
   >  也就是根据当前用户ID和今天的日期，去数据库匹配到当前可见的最新编号。
   >
   >  如果有多条，需要取 `max(export_no,0)` 。
   >
	>  `coalesce(max(export_no), 0)` 里的 0 是为了处理**查询结果为 NULL 的情况**（即该用户当天还没有任何记录）。
	>
	>  由于日期每天都是不一样的，所以带上日期**天然支持**零点归零。
	
	------
3. 新增语句怎么写？

​	先查询最大的编号，得到一个`num`。

​	下一个编号就是`num+1`。

​	然后写入即可。

> 需要注意这里的并发问题。查询和写入并不是原子操作，如果业务允许两个用户同时在线导出，**考虑分布式🔒和数据库唯一索引兜底。**

​	唯一索引的建立：

```sql
constraint uk_user_date_no
    unique (customer_id, export_date, export_no)
```


4. 如何优化查询性能？

   > 考虑联合索引。

   ```sql
   create index idx_user_date
       on night_issue_export_record (customer_service_id, export_date);
   ```

   

## 思考:如何按照任意分钟重置？

#### 方案一：Redis 计数器（推荐）

```java
// key = export_no:{customerId}:{时间窗口}
String key = "export_no:" + customerId + ":" + getTimeWindow(minutes);
Long no = redisTemplate.opsForValue().increment(key);
// 设置过期时间为窗口时长+缓冲
redisTemplate.expire(key, minutes + 1, TimeUnit.MINUTES);
```

```java
private String getTimeWindow(int minutes) {
    LocalDateTime now = LocalDateTime.now();
    // 按分钟对齐，比如每30分钟一个窗口
    int slot = now.getMinute() / minutes;
    return now.format(DateTimeFormatter.ofPattern("yyyyMMddHH")) + slot;
}
```

**优点**：原子操作，天然解决并发，性能高。 **缺点**：Redis 挂了序号丢失，需要持久化兜底。
