# 五、第二步：选择合适的分片键

一个较好的分片键通常具备以下特征。

## 1. 查询覆盖率高

核心 SQL 应尽可能携带分片键。

如果 90% 的订单查询都携带 `user_id`，那么 `user_id` 通常比 `create_time` 更适合作为分库键。

## 2. 数据分布均匀

以下字段容易造成数据倾斜：

* 国家；
* 城市；
* 订单状态；
* 用户等级；
* 商品类别；
* 布尔状态。

例如按照订单状态分片：

```text
待支付订单：5%
已支付订单：80%
已取消订单：15%
```

不同分片的数据量会严重不均匀。

## 3. 字段尽量不可变

修改普通字段只需要执行一次 `UPDATE`。

修改分片键可能意味着：

1. 从原分片删除数据；
2. 将数据写入新分片；
3. 同步关联表；
4. 处理并发修改；
5. 保证事务一致性。

因此，应将分片键视为业务数据的定位属性，原则上不允许修改。

## 4. 能够降低跨库操作

属于同一个业务聚合的数据，应尽量位于同一个数据库分片。

例如：

```text
订单
订单明细
订单支付记录
订单操作记录
```

可以统一按照 `user_id` 或订单所属用户进行分库，使订单创建、明细写入和状态修改尽可能在单库事务中完成。
