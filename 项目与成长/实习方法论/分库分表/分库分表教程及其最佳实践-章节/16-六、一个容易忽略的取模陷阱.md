# 六、一个容易忽略的取模陷阱

假设系统有 2 个库，每个库 4 张表，设计如下：

```text
数据库：user_id % 2
数据表：user_id % 4
```

看起来一共有 8 个数据节点，但实际上：

```text
user_id % 4 = 0 → user_id % 2 一定等于 0
user_id % 4 = 1 → user_id % 2 一定等于 1
user_id % 4 = 2 → user_id % 2 一定等于 0
user_id % 4 = 3 → user_id % 2 一定等于 1
```

因此只有以下节点会被使用：

```text
ds_0.t_order_0
ds_0.t_order_2
ds_1.t_order_1
ds_1.t_order_3
```

另外 4 个节点永远没有数据。

这就是分库算法和分表算法之间的**相关性问题**。

可选解决方式包括：

* 分库、分表使用不同的字段；
* 先计算统一的逻辑分片编号，再映射到库和表；
* 使用自定义分片算法；
* 引入虚拟分片槽，物理节点只负责承载若干槽位。

本文示例采用：

```text
user_id  分库
order_id 分表
```

这样可以避免简单取模产生的数据节点空置问题。
