# 总结

做好分库分表，关键不在于配置多少数据库和多少张表，而在于以下几点：

1. **先分析访问模式，再选择分片键。**
2. **让核心 SQL 尽可能携带完整分片键。**
3. **保证分片均匀，同时处理热点数据。**
4. **相关业务表尽量落在同一数据库分片。**
5. **谨慎使用跨库 JOIN 和分布式事务。**
6. **提前设计全局 ID、数据迁移和扩容方案。**
7. **不仅测试查询结果，还要检查真实路由范围。**
8. **建立分片级监控、对账和故障恢复能力。**

ShardingSphere 可以帮助应用完成 SQL 解析、路由、改写、执行和结果归并，也可以提供绑定表、广播表、分布式事务和多种内置分片算法。

但是，中间件只能执行已经确定的分片规则。

**真正决定分库分表项目成败的，仍然是业务访问模式、分片键设计、数据模型和长期扩容方案。**
