# 二十二、扩容为什么比第一次分片更难

假设原来使用：

```text
order_id % 4
```

后来扩容为：

```text
order_id % 8
```

大量数据的目标表会发生变化。

例如：

```text
10005 % 4 = 1
10005 % 8 = 5
```

原来位于 `t_order_1`，扩容后应位于 `t_order_5`。

这意味着不能只增加 4 张新表，还必须重新迁移旧数据。

因此，第一次设计时就要考虑未来扩容。

常见方案包括：

## 1. 预留足够的逻辑分片

初期创建较多逻辑表，但将多个逻辑表放在同一物理实例中。

未来扩容时，将部分逻辑表迁移到新实例，而不改变表级路由算法。

## 2. 虚拟槽位

先计算固定数量的虚拟槽：

```text
slot = hash(sharding_key) % 1024
```

再维护：

```text
slot → 数据库节点
```

扩容时只迁移部分槽位。

## 3. 一致性哈希

适用于动态节点，但实现、数据均衡和故障恢复更加复杂。

## 4. 通过迁移工具重新分片

在新旧规则之间完成：

* 全量迁移；
* 增量同步；
* 数据校验；
* 流量切换。

无论采用哪种方案，都要在第一次分片时保留扩容路径。
