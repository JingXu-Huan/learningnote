# 微服务是怎么知道它的配置在`nacos`并且拉取的呢😢

涉及到`Spring`的启动...

* 引入依赖：

  ```xml
  <dependency>
      <groupId>com.alibaba.cloud</groupId>
      <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
      <version>最新兼容版</version>
  </dependency>
  ```

​	这个依赖会在 Spring Boot 启动时自动加载一个**配置监听器组件**：

> 它会根据配置文件里的 `Nacos` 地址、命名空间等信息，**自动去 `Nacos` 拉取配置**。

Spring Boot 启动分两步：

1. **加载 bootstrap 环境**（最早阶段）
2. **加载 application 环境**

> 因为 `Nacos` 的配置可能影响整个应用（比如数据库连接、端口号），所以它必须在最早阶段加载。

在 `bootstrap.yml` 中，通常会这样写：

```yml
spring:
  application:
    name: my-service  # 服务名，对应 Nacos 配置文件 dataId 前缀
  cloud:
    nacos:
      config:
        server-addr: localhost:8848  # Nacos 地址
        namespace: public            # 命名空间ID
        group: DEFAULT_GROUP         # 配置分组
        file-extension: yaml         # 远程配置文件格式
```

🧠 当应用启动时：

1. Spring 读取 `spring.cloud.nacos.config.*` 配置；
2. 加载 `NacosConfigBootstrapConfiguration`（来自上面的 `starter` 依赖）；
3. 自动向 `server-addr` 指定的 `Nacos` 发请求；
4. 去查找对应的配置文件：

```xml
dataId = spring.application.name + "." + file-extension
例如：my-service.yaml
```

然后拉取配置并注入到 Spring 环境中。✨

## 聊一聊`BootStrap`这个东西吧👌

“`Bootstrap`” 英文意思是“自启动/引导程序”。
 在这里它的作用就像一双“启动鞋带”👟——
 帮助 `SpringBoot` **先系好外部配置的鞋带**，再去跑主程序。

------

## ⚙️ 它主要做什么事？

### ✅ 1. 告诉程序配置中心在哪

比如 `Nacos`、`Apollo`、`Consul` 等。

```yml
spring:
  cloud:
    nacos:
      config:
        server-addr: 127.0.0.1:8848
        namespace: dev
```

这告诉 Spring Cloud：

> “去这个地址拉配置哦～拉完再启动。”

------

### ✅ 2. 设置应用名（配置文件匹配）

```yml
spring:
  application:
    name: user-service
```

这样 Spring Boot 就会自动去 `Nacos` 里找：

```
Data ID = user-service.yaml
```

------

### ✅ 3. 加载优先级高的公共配置

比如多个微服务共用的数据库配置、日志规则等，可以通过 `extension-configs` 拉取。

------

### ✅ 4. 保证配置中心的值能被 `application.yml` 使用

**因为它最早加载，所以在 `application.yml` 中可以用 `${}` 引用它的值。**

------

### 🧠 5. 加载顺序对比（关键点）

Spring 启动时的配置加载顺序如下：

```
1️⃣ bootstrap.yml（加载外部配置源信息，如 Nacos）
2️⃣ 从配置中心拉取远程配置（如 project.yaml）
3️⃣ application.yml（加载本地配置）
4️⃣ 环境变量 / 命令行参数（覆盖前面同名配置）
```

🪄 所以：

> 如果本地和 Nacos 都定义了同名配置项，
>  默认会使用 **Nacos（远程）** 的值。
