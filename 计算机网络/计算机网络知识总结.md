## 一、网络基础概念

### 1.1 计算机网络的定义

计算机网络是指将地理位置不同的、具有独立功能的多台计算机及其外部设备,通过通信线路连接起来,在网络操作系统、网络管理软件及网络通信协议的管理和协调下,实现资源共享和信息传递的计算机系统。

### 1.2 网络分类

#### 按覆盖范围分类

| 类型 | 覆盖范围 | 典型技术 | 速率 |
|------|----------|----------|------|
| **PAN** (个人域网) | 1~10m | 蓝牙、红外 | < 1Mbps |
| **LAN** (局域网) | 10m~10km | 以太网、Wi-Fi | 100Mbps ~ 10Gbps |
| **MAN** (城域网) | 10~100km | FDDI、ATM | < 100Mbps |
| **WAN** (广域网) | 100km以上 | MPLS、SDH | < 1Gbps |
| **Internet** | 全球 | TCP/IP 协议族 | 不限 |

#### 按拓扑结构分类

- **星型拓扑**: 中心节点故障会导致全网瘫痪
- **总线型**: 共享传输介质,效率低
- **环型**: 令牌环,单点故障影响大
- **树型**: 分层结构,扩展性好
- **网状型**: 可靠性高,成本高
- **混合型**: 实际网络常见组合形式

#### 按传输介质分类

- **有线网络**: 双绞线(网线)、同轴电缆、光纤
- **无线网络**: Wi-Fi、4G/5G、卫星、蓝牙、ZigBee

### 1.3 性能指标

- **带宽 (Bandwidth)**: 最高数据传输速率,单位 bps (bit per second)
- **吞吐量 (Throughput)**: 实际单位时间内传输的数据量
- **时延 (Latency/Delay)**: 数据从一端到另一端的时间
  - 发送时延 = 数据长度 / 发送速率
  - 传播时延 = 距离 / 传播速度
  - 排队时延: 在路由器中等待处理的时间
  - 处理时延: 路由器处理分组的时间
  - **总时延 = 发送时延 + 传播时延 + 排队时延 + 处理时延**
- **往返时间 RTT (Round-Trip Time)**: 数据从发送端到接收端再返回的时间
- **丢包率 (Packet Loss Rate)**: 丢失分组数 / 总分组数
- **利用率**: 信道被占用的程度,过高会产生较大时延

### 1.4 数据交换方式

1. **电路交换**: 建立专用通路,适合实时大量数据传输
2. **报文交换**: 存储转发,整个报文作为单位
3. **分组交换**: 将报文分割为多个分组,每个分组独立路由(Internet 采用)

## 二、网络参考模型

### 2.1 OSI 七层模型 (理论模型)

| 层 | 名称 | 主要功能 | 典型协议/设备 | 数据单位 |
|----|------|----------|---------------|----------|
| 7 | **应用层** | 为用户提供网络服务 | HTTP、FTP、SMTP、DNS | 报文(Message) |
| 6 | **表示层** | 数据表示、加密、压缩 | SSL/TLS、JPEG、ASCII | 报文 |
| 5 | **会话层** | 建立、管理、终止会话 | NetBIOS、RPC | 报文 |
| 4 | **传输层** | 端到端可靠传输、流量控制 | TCP、UDP | 段(Segment) |
| 3 | **网络层** | 路由选择、分组转发 | IP、ICMP、ARP、OSPF | 包(Packet) |
| 2 | **数据链路层** | 帧的封装、差错检测、流量控制 | Ethernet、PPP、HDLC | 帧(Frame) |
| 1 | **物理层** | 比特流传输 | 网线、光纤、集线器 | 比特(Bit) |

> **记忆口诀**: "**物数网传会表应**" 或 "**All People Seem To Need Data Processing**" (从下到上)

### 2.2 TCP/IP 四层模型 (实际模型)

| TCP/IP 层 | 对应 OSI 层 | 主要协议 |
|-----------|-------------|----------|
| **应用层** | 应用层、表示层、会话层 | HTTP、FTP、SMTP、DNS、Telnet |
| **传输层** | 传输层 | TCP、UDP |
| **网络层 (网际层)** | 网络层 | IP、ICMP、IGMP、ARP |
| **网络接口层** | 数据链路层、物理层 | Ethernet、PPP、ARP、帧中继 |

### 2.3 五层模型 (教学模型)

折中方案: 应用层、传输层、网络层、数据链路层、物理层

### 2.4 数据传输过程

发送端: 数据 → 应用层 → 传输层 → 网络层 → 数据链路层 → 物理层 (层层封装)
接收端: 物理层 → 数据链路层 → 网络层 → 传输层 → 应用层 → 数据 (层层解封装)

**封装过程**:
```
应用层数据  → [传输层头部 + 应用数据] = 段
段          → [网络层头部 + 段] = 包
包          → [数据链路层头部 + 包 + 尾部] = 帧
帧          → 物理层转换为比特流
```

## 三、物理层与数据链路层

### 3.1 物理层基础

- **信号**: 模拟信号、数字信号
- **编码方式**: NRZ、曼彻斯特编码、差分曼彻斯特编码
- **复用技术**: 时分复用(TDM)、频分复用(FDM)、波分复用(WDM)、码分复用(CDM)
- **传输介质**:
  - 双绞线(百兆: 1、2 发送,3、6 接收)
  - 同轴电缆(抗干扰性强)
  - 光纤(单模 vs 多模,传输距离远、速度快)

### 3.2 数据链路层

#### 3.2.1 主要功能

1. **封装成帧**: 添加帧头、帧尾,进行帧定界
2. **透明传输**: 处理数据中出现的特殊字符(字符填充/比特填充)
3. **差错检测**: CRC 校验、和校验
4. **流量控制**: 协调发送方与接收方速率

#### 3.2.2 MAC 地址

- 48 位(6 字节)的物理地址
- 格式: `XX-XX-XX-XX-XX-XX` 或 `XX:XX:XX:XX:XX:XX`
- 前 24 位为厂商代码(OUI),后 24 位为厂商分配
- 唯一标识网络接口卡(NIC)

#### 3.2.3 以太网 (Ethernet)

- 经典以太网: 10Mbps,总线型,CSMA/CD
- 快速以太网: 100Mbps
- 千兆以太网: 1Gbps
- 万兆以太网: 10Gbps
- 帧格式:

```
| 前导码(7B) | 帧开始定界符(1B) | 目的MAC(6B) | 源MAC(6B) | 类型(2B) | 数据(46-1500B) | FCS(4B) |
```

**MTU (Maximum Transmission Unit)**: 最大传输单元,通常 1500 字节

#### 3.2.4 CSMA/CD 协议 (载波监听多路访问/碰撞检测)

工作流程:
1. 监听信道: 空闲则发送,忙则等待
2. 边发送边监听: 检测到碰撞立即停止
3. 碰撞后: 发送人为干扰信号,采用**二进制指数退避算法**等待重传

#### 3.2.5 交换机的自学习算法

通过查看帧的源 MAC 地址,记录 MAC 地址与端口的对应关系,生成 MAC 地址表。

## 四、网络层

### 4.1 IP 地址

#### 4.1.1 IP 地址分类 (IPv4, 32 位)

| 类别 | 范围 | 默认子网掩码 | 用途 |
|------|------|--------------|------|
| A 类 | 1.0.0.0 ~ 126.255.255.255 | 255.0.0.0 (/8) | 大型网络 |
| B 类 | 128.0.0.0 ~ 191.255.255.255 | 255.255.0.0 (/16) | 中型网络 |
| C 类 | 192.0.0.0 ~ 223.255.255.255 | 255.255.255.0 (/24) | 小型网络 |
| D 类 | 224.0.0.0 ~ 239.255.255.255 | - | 组播 |
| E 类 | 240.0.0.0 ~ 255.255.255.255 | - | 保留 |

**特殊 IP 地址**:
- `127.0.0.1`: 本地回环地址
- `0.0.0.0`: 表示本机或默认路由
- `255.255.255.255`: 有限广播地址
- `169.254.x.x`: APIPA 自动分配地址
- `10.x.x.x`、`172.16.x.x ~ 172.31.x.x`、`192.168.x.x`: 私有地址

#### 4.1.2 CIDR (无类域间路由)

- 表示方法: `IP/前缀长度`,如 `192.168.1.0/24`
- 消除了传统分类的局限性,提高地址利用率

#### 4.1.3 子网划分

**例**: `192.168.1.0/26` 可划分:
- 子网掩码: 255.255.255.192
- 每个子网: 64 个地址
- 可用主机数: 62 个 (减去网络地址和广播地址)

#### 4.1.4 IPv6

- 128 位地址,16 字节,8 组 16 进制数
- 解决 IPv4 地址耗尽问题
- 简化头部、去除校验和、内置 IPSec
- 写法: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- 简写: `2001:db8:85a3::8a2e:370:7334`

### 4.2 IP 数据报格式

```
| 版本(4) | 头部长度(4) | 服务类型(8)  | 总长度(16)         |
| 标识(16)            | 标志(3) | 片偏移(13)         |
| TTL(8)  | 协议(8)    | 头部校验和(16)                  |
| 源 IP 地址(32)                                          |
| 目的 IP 地址(32)                                        |
| 选项(可变)                                              |
| 数据                                                    |
```

- **TTL (Time To Live)**: 生存时间,每经过一个路由器减 1,防止数据包无限循环
- **协议**: 6=TCP, 17=UDP, 1=ICMP
- **片偏移**: 分片后该片在原分组中的相对位置

### 4.3 ARP 协议 (地址解析协议)

- **作用**: 将 IP 地址解析为 MAC 地址
- **流程**:
  1. 检查 ARP 缓存,命中则返回 MAC
  2. 未命中则广播 ARP 请求(目的 MAC 为 FF:FF:FF:FF:FF:FF)
  3. 目标主机单播 ARP 响应
  4. 主机更新 ARP 缓存
- **ARP 欺骗**: 中间人攻击常用手段

### 4.4 ICMP 协议 (网际控制报文协议)

- 用于报告错误和异常
- 常见报文:
  - **Ping**: 类型 8(请求)/ 0(响应)
  - **Traceroute**: 利用 TTL 字段,发送 TTL=1、2、3…的包,收到 ICMP 超时报文确定路由
  - **目的不可达**: 类型 3

### 4.5 路由算法

#### 4.5.1 距离向量算法 (RIP)

- 每个路由器维护到目的网络的距离(跳数)
- 定期与邻居交换完整路由表
- **最大跳数 15**,16 跳视为不可达
- 收敛慢,易产生路由环路

#### 4.5.2 链路状态算法 (OSPF)

- 每台路由器拥有完整拓扑
- 通过**洪泛法**传播链路状态
- 采用 **Dijkstra** 最短路径算法
- 收敛快,适合大型网络
- 支持分层(区域)设计

#### 4.5.3 路径向量算法 (BGP)

- 用于自治系统(AS)之间的路由
- 路径属性中包含 AS 路径信息
- 防止环路、支持策略路由
- 当前 Internet 主干使用 BGP-4

### 4.6 NAT (网络地址转换)

- 解决 IPv4 地址不足
- 私有 IP ↔ 公有 IP 转换
- 类型: 静态 NAT、动态 NAT、PAT(端口地址转换,常用)

### 4.7 DHCP 协议

- 自动分配 IP 地址
- 四步过程: **Discover → Offer → Request → ACK (DORA)**
- 基于 UDP, 客户端端口 68,服务端端口 67

### 4.8 路由器与三层交换机

- **路由器**: 不同网络之间转发 IP 数据报
- **三层交换机**: 结合二层交换和三层路由,常用于 VLAN 间通信

## 五、传输层

### 5.1 端口号

- 16 位,范围 0~65535
- **知名端口 0~1023**: HTTP(80)、HTTPS(443)、FTP(21)、SSH(22)、DNS(53)、Telnet(23)、SMTP(25)、POP3(110)
- **注册端口 1024~49151**
- **动态/私有端口 49152~65535**

### 5.2 UDP (用户数据报协议)

#### 5.2.1 特点

- **无连接**
- 尽最大努力交付
- **面向报文** (不拆分、不合并)
- 没有拥塞控制
- 支持一对一、一对多、多对多通信
- 首部开销小,仅 **8 字节**

#### 5.2.2 首部格式

```
| 源端口(2B) | 目的端口(2B) |
| 长度(2B)   | 校验和(2B)   |
```

#### 5.2.3 适用场景

- 视频直播、实时游戏
- DNS 查询
- VoIP
- 简单网络管理(SNMP)

### 5.3 TCP (传输控制协议)

#### 5.3.1 特点

- **面向连接** (三次握手、四次挥手)
- **可靠传输** (确认、超时重传、序号、校验和)
- **面向字节流**
- **全双工通信**
- **流量控制** + **拥塞控制**

#### 5.3.2 TCP 首部 (20~60 字节)

```
| 源端口(2) | 目的端口(2)                |
| 序号 Seq(4)                            |
| 确认号 Ack(4)                          |
| 头部长度(4) | 保留(6) | URG/ACK/PSH/RST/SYN/FIN(6) | 窗口大小(2) |
| 校验和(2) | 紧急指针(2)               |
| 选项(可选)                             |
```

**重要标志位**:
- **URG**: 紧急指针有效
- **ACK**: 确认号有效
- **PSH**: 推送,接收方应尽快交付应用
- **RST**: 复位,异常关闭连接
- **SYN**: 同步,发起连接
- **FIN**: 终止,释放连接

#### 5.3.3 三次握手 (建立连接)

```
客户端                          服务端
  | ----------- SYN (seq=x) ----------> |
  |                                    |
  | <--- SYN+ACK (seq=y, ack=x+1) ----- |
  |                                    |
  | ----------- ACK (seq=x+1, ack=y+1) -> |
  |                                    |
[ESTABLISHED]                   [ESTABLISHED]
```

**为什么是三次而不是两次?**
- 防止已失效的连接请求突然传到服务器,造成资源浪费
- 双方都需要确认对方的收发能力

**为什么不是四次?**
- 服务端可以把 SYN 和 ACK 合并为一次发送

#### 5.3.4 四次挥手 (释放连接)

```
客户端                          服务端
  | ----------- FIN (seq=u) ----------> |
  |  [FIN_WAIT_1]                      |
  | <----------- ACK (ack=u+1) -------- |
  |  [FIN_WAIT_2]            [CLOSE_WAIT]|
  |                                    |
  | <----------- FIN (seq=v) ---------- |
  |               [LAST_ACK]            |
  | ----------- ACK (ack=v+1) --------> |
  |  [TIME_WAIT]                        |
  |                              [CLOSED]
```

**为什么是四次?**
- TCP 全双工,各方向都要单独关闭
- 服务端收到 FIN 后,可能还有数据要发送,所以 ACK 和 FIN 分开发

**为什么客户端要等待 2MSL (TIME_WAIT)?**
- 保证最后一个 ACK 能到达服务端
- 让本连接产生的所有报文从网络中消失(避免影响后续连接)

#### 5.3.5 可靠传输机制

1. **校验和**: 检测传输错误
2. **序号**: 每个字节都有唯一编号
3. **确认**: 累计确认 + 选择确认(SACK)
4. **超时重传**: RTO 动态计算
5. **快速重传**: 收到 3 个重复 ACK 立即重传
6. **冗余 ACK**: 用于触发快速重传

#### 5.3.6 流量控制 (滑动窗口)

- 接收方通过 ACK 中的窗口大小告知发送方接收能力
- 发送方维护**发送窗口**,确保已发送未确认的字节数 ≤ 接收方窗口
- 防止发送过快导致接收方缓冲区溢出

#### 5.3.7 拥塞控制

**四大机制**:

1. **慢启动 (Slow Start)**
   - 初始拥塞窗口 cwnd = 1 MSS
   - 每收到一个 ACK, cwnd += 1 MSS
   - 指数增长

2. **拥塞避免 (Congestion Avoidance)**
   - 当 cwnd ≥ 慢启动门限 ssthresh
   - 每经过一个 RTT, cwnd += 1 MSS
   - 线性增长

3. **快重传 (Fast Retransmit)**
   - 收到 3 个重复 ACK,立即重传

4. **快恢复 (Fast Recovery)**
   - ssthresh = cwnd / 2
   - cwnd = ssthresh
   - 直接进入拥塞避免

**经典问题**:

| 状态变化 | 触发条件 | ssthresh | cwnd |
|----------|----------|----------|------|
| 慢启动 → 拥塞避免 | cwnd ≥ ssthresh | 不变 | 加 1 |
| 慢启动 → 快重传 | 3 个重复 ACK | cwnd/2 | cwnd/2 + 3 |
| 拥塞避免 → 快恢复 | 3 个重复 ACK | cwnd/2 | cwnd/2 + 3 |
| 任意阶段 → 慢启动 | 超时 | cwnd/2 | 1 |

#### 5.3.8 TCP 粘包与拆包

- **原因**: TCP 是流式协议,无消息边界
- **解决方案**:
  1. 固定消息长度
  2. 消息结尾加分隔符(如 `\n`)
  3. 消息头中带长度字段
  4. 更复杂的协议(Protobuf、Thrift)

## 六、应用层

### 6.1 常见应用层协议对照表

| 协议 | 端口 | 传输层 | 用途 |
|------|------|--------|------|
| HTTP | 80 | TCP | 网页浏览 |
| HTTPS | 443 | TCP | 加密网页浏览 |
| FTP | 21(控制) / 20(数据) | TCP | 文件传输 |
| SSH | 22 | TCP | 安全远程登录 |
| Telnet | 23 | TCP | 远程登录(明文) |
| SMTP | 25 | TCP | 邮件发送 |
| POP3 | 110 | TCP | 邮件接收 |
| IMAP | 143 | TCP | 邮件访问 |
| DNS | 53 | UDP/TCP | 域名解析 |
| DHCP | 67/68 | UDP | 动态 IP 分配 |
| SNMP | 161/162 | UDP | 网络管理 |
| NTP | 123 | UDP | 时间同步 |
| TFTP | 69 | UDP | 简单文件传输 |

### 6.2 FTP 协议

- **主动模式 (PORT)**: 服务器从 20 端口主动连接客户端
- **被动模式 (PASV)**: 服务器开放随机端口等待客户端连接
- 两个连接: **控制连接**(21) + **数据连接**

### 6.3 邮件相关协议

- **SMTP**: 发送邮件 (推)
- **POP3**: 简单接收,下载后服务器可删除 (拉)
- **IMAP**: 支持服务器端管理,多设备同步 (拉)

### 6.4 SSH 与 Telnet

- **Telnet**: 明文传输,端口 23,安全性差
- **SSH**: 加密传输,端口 22,采用 RSA/DSA 非对称加密

### 6.5 WebSocket

- 基于 HTTP 升级机制的全双工通信协议
- 适用: 实时聊天、在线游戏、实时数据推送
- 握手: HTTP Upgrade: websocket

### 6.6 RPC (远程过程调用)

- 像调用本地方法一样调用远程服务
- 代表: gRPC、Thrift、Dubbo
- 通常基于 TCP

## 七、HTTP 与 HTTPS 详解

### 7.1 HTTP 概述

- **超文本传输协议** (HyperText Transfer Protocol)
- 基于 **请求-响应** 模型
- **无状态** (Cookie/Session 解决)
- 默认端口 80

### 7.2 HTTP 请求报文

```
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html
Accept-Language: zh-CN
Connection: keep-alive

[请求体]
```

### 7.3 HTTP 响应报文

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 1024
Date: ...
Server: Apache
Set-Cookie: ...

[响应体]
```

### 7.4 HTTP 方法

| 方法 | 描述 | 幂等 | 安全 |
|------|------|------|------|
| GET | 获取资源 | 是 | 是 |
| POST | 提交数据 | 否 | 否 |
| PUT | 更新资源(整体) | 是 | 否 |
| PATCH | 更新资源(部分) | 否 | 否 |
| DELETE | 删除资源 | 是 | 否 |
| HEAD | 获取头部信息 | 是 | 是 |
| OPTIONS | 查看服务器支持的方法 | 是 | 是 |

> **幂等**: 多次执行结果相同
> **安全**: 不修改服务器数据

### 7.5 HTTP 状态码

| 类别 | 范围 | 含义 |
|------|------|------|
| 1xx | 100~199 | 信息性,请求已接收 |
| 2xx | 200~299 | 成功 |
| 3xx | 300~399 | 重定向 |
| 4xx | 400~499 | 客户端错误 |
| 5xx | 500~599 | 服务器错误 |

**常见状态码**:
- **200 OK**: 请求成功
- **204 No Content**: 成功但无返回内容
- **301 Moved Permanently**: 永久重定向
- **302 Found**: 临时重定向
- **304 Not Modified**: 缓存未修改
- **400 Bad Request**: 请求语法错误
- **401 Unauthorized**: 未认证
- **403 Forbidden**: 禁止访问
- **404 Not Found**: 资源不存在
- **500 Internal Server Error**: 服务器内部错误
- **502 Bad Gateway**: 网关错误
- **503 Service Unavailable**: 服务不可用
- **504 Gateway Timeout**: 网关超时

### 7.6 HTTP 头部字段

#### 通用头部

- `Cache-Control`: 缓存控制
- `Connection`: 连接管理 (keep-alive / close)
- `Date`: 日期
- `Transfer-Encoding`: 传输编码 (chunked)

#### 请求头部

- `Host`: 主机名(必需,HTTP/1.1)
- `User-Agent`: 浏览器信息
- `Accept`: 可接受的媒体类型
- `Accept-Encoding`: 可接受的编码 (gzip, deflate)
- `Accept-Language`: 可接受的语言
- `Cookie`: 客户端 Cookie
- `Authorization`: 认证信息
- `Referer`: 来源页面
- `If-Modified-Since`: 条件请求
- `If-None-Match`: ETag 条件请求

#### 响应头部

- `Content-Type`: 响应体类型
- `Content-Length`: 响应体长度
- `Content-Encoding`: 响应体编码
- `Set-Cookie`: 设置 Cookie
- `Location`: 重定向地址
- `Server`: 服务器信息
- `ETag`: 资源标识
- `Last-Modified`: 最后修改时间
- `Expires`: 过期时间

### 7.7 HTTP/1.0 vs HTTP/1.1 vs HTTP/2 vs HTTP/3

#### HTTP/1.0
- 短连接: 每个请求/响应都建立新的 TCP 连接
- 支持 GET、HEAD、POST
- 无 Host 头部

#### HTTP/1.1 (主流)
- **长连接** (Connection: keep-alive)
- **管道化** (Pipelining,理论支持,实际很少用)
- 引入 `Host` 头部(支持虚拟主机)
- 增加 PUT、PATCH、DELETE、OPTIONS 等方法
- 引入 `Range` 范围请求、断点续传
- 引入 `Cache-Control`、`ETag` 等缓存机制
- **问题**: 队头阻塞、文本协议解析慢

#### HTTP/2
- **二进制分帧**: 将数据分割为更小的帧
- **多路复用**: 一个连接并行处理多个请求,解决队头阻塞
- **头部压缩 (HPACK)**
- **服务器推送 (Server Push)**
- **流优先级**
- 基于 TLS,默认 HTTPS

#### HTTP/3
- 基于 **QUIC** 协议 (UDP + 自实现可靠性)
- 解决 TCP 队头阻塞
- 内置 TLS 1.3
- 0-RTT 握手
- 连接迁移 (Connection ID,IP 变化不影响连接)

### 7.8 HTTPS

#### 7.8.1 原理

HTTP + SSL/TLS = HTTPS

#### 7.8.2 加密机制

**混合加密**:
- **非对称加密** (RSA、ECC): 加密对称密钥
- **对称加密** (AES、ChaCha20): 加密实际数据

#### 7.8.3 TLS 握手过程 (TLS 1.2)

```
Client                                 Server
  | -------- ClientHello -------------> |  (支持的协议版本、加密套件、随机数)
  |                                     |
  | <-------- ServerHello ------------- |  (确定的协议、套件、随机数、证书)
  |                                     |
  | 验证证书,生成 pre-master secret     |
  | 派生会话密钥                         |
  |                                     |
  | -------- ChangeCipherSpec --------> |
  | -------- Finished ----------------> |  (加密)
  |                                     |
  | <-------- ChangeCipherSpec -------- |
  | <-------- Finished ---------------- |
  |                                     |
  | <======= 加密通信开始 ===========>   |
```

#### 7.8.4 TLS 1.3 改进

- 握手从 2 RTT 减少到 **1 RTT** (0-RTT 模式可更快)
- 只支持前向保密的加密套件
- 移除了不安全的算法 (MD5、SHA-1、RC4 等)
- 加密更多握手消息

#### 7.8.5 数字证书

- 由 **CA (Certificate Authority)** 签发
- 包含: 域名、公钥、CA 签名、有效期等
- 验证链: 根 CA → 中间 CA → 域证书
- 证书类型: DV、OV、EV

#### 7.8.6 HTTPS 的优缺点

**优点**:
- 数据加密传输,防窃听
- 身份认证,防冒充
- 完整性校验,防篡改
- SEO 优势(搜索引擎偏好)

**缺点**:
- 握手耗时增加延迟
- 加解密消耗 CPU
- 证书费用
- 占用更多带宽

### 7.9 HTTP 缓存机制

#### 7.9.1 强制缓存

通过 `Cache-Control`、`Expires` 头部控制:
- `Cache-Control: max-age=3600`: 1 小时内使用缓存
- `Cache-Control: no-cache`: 需协商缓存
- `Cache-Control: no-store`: 不缓存

#### 7.9.2 协商缓存 (对比缓存)

- `Last-Modified` / `If-Modified-Since`
- `ETag` / `If-None-Match` (优先级更高)

**304 Not Modified**: 资源未修改,使用本地缓存

### 7.10 Cookie 与 Session

#### Cookie
- 浏览器端存储的小段数据
- 4KB 限制
- 可设置过期时间、HttpOnly、Secure、SameSite

#### Session
- 服务器端存储会话状态
- 通过 SessionID 标识(通常存在 Cookie 中)
- 分布式场景需要 Session 共享 (Redis)

#### Token (JWT)
- 无状态认证
- 三部分: Header.Payload.Signature
- 适合分布式、微服务

## 八、DNS 域名系统

### 8.1 作用

将**域名**解析为 **IP 地址** (正向解析),或反向解析。

### 8.2 域名结构

```
www.baidu.com.
   │    │   │  │
   │    │   │  └── 根域 (.)
   │    │   └───── 顶级域 (TLD): com
   │    └───────── 二级域: baidu
   └────────────── 主机名: www
```

**顶级域分类**:
- 通用顶级域 (gTLD): .com、.org、.net、.edu
- 国家顶级域 (ccTLD): .cn、.jp、.uk
- 新顶级域: .app、.dev、.io

### 8.3 DNS 服务器类型

1. **根域名服务器** (13 组,A~M)
2. **顶级域名服务器** (.com、.cn 等)
3. **权威域名服务器** (域名所属)
4. **本地域名服务器** (本地 ISP 提供)

### 8.4 域名解析过程

#### 递归查询 (Recursive Query)

客户端 → 本地 DNS → 全权代理解析并返回结果

#### 迭代查询 (Iterative Query)

```
客户端 → 本地 DNS → 根 DNS
                      ↓ 返回顶级域地址
                    顶级域 DNS
                      ↓ 返回权威域地址
                    权威域 DNS
                      ↓ 返回 IP
                    本地 DNS → 客户端
```

### 8.5 DNS 记录类型

| 类型 | 用途 |
|------|------|
| A | 域名 → IPv4 地址 |
| AAAA | 域名 → IPv6 地址 |
| CNAME | 别名 |
| MX | 邮件服务器 |
| NS | 域名服务器 |
| TXT | 文本记录(SPF、DKIM) |
| PTR | IP → 域名(反向解析) |
| SOA | 起始授权机构 |

### 8.6 DNS 优化

- **DNS 缓存** (浏览器、操作系统、本地 DNS)
- **DNS 预解析** `<link rel="dns-prefetch" href="//cdn.example.com">`
- **HttpDNS**: 绕过 Local DNS,防劫持
- **CDN 智能调度**

### 8.7 常见问题

- **DNS 劫持**: 返回错误 IP
- **DNS 污染**: 在 DNS 协议层注入错误响应
- **DNS 放大攻击**: 利用大响应发起 DDoS

## 九、网络安全

### 9.1 常见攻击方式

#### 9.1.1 XSS (跨站脚本攻击)
- 反射型、存储型、DOM 型
- 防御: 输入过滤、输出编码、CSP

#### 9.1.2 CSRF (跨站请求伪造)
- 利用用户身份发送恶意请求
- 防御: Token 验证、SameSite Cookie、Referer 检查

#### 9.1.3 SQL 注入
- 防御: 参数化查询、ORM、最小权限

#### 9.1.4 DDoS 攻击
- SYN Flood、UDP Flood、HTTP Flood
- 防御: 流量清洗、CDN、限流

#### 9.1.5 MITM (中间人攻击)
- 防御: HTTPS、证书校验

#### 9.1.6 ARP 欺骗
- 防御: 静态 ARP 绑定、ARP 防火墙

### 9.2 加密技术

#### 9.2.1 对称加密
- 加密、解密使用**同一密钥**
- 算法: AES、DES、3DES、ChaCha20
- 速度快,适合大量数据

#### 9.2.2 非对称加密
- 公钥加密,私钥解密(或反之)
- 算法: RSA、ECC、DH
- 速度慢,用于密钥交换、数字签名

#### 9.2.3 哈希算法
- 单向、不可逆、定长输出
- 算法: MD5(已不安全)、SHA-1(已不安全)、SHA-256、SHA-3
- 应用: 密码存储(加盐)、文件校验、数字签名

#### 9.2.4 数字签名
- 发送方: 私钥签名
- 接收方: 公钥验证
- 作用: 身份认证 + 完整性 + 不可否认

### 9.3 防火墙

- **包过滤防火墙**: 检查 IP、端口
- **状态检测防火墙**: 跟踪连接状态
- **应用层防火墙 (WAF)**: 检测 HTTP 内容

### 9.4 VPN

- **IPSec VPN**: 网络层加密
- **SSL VPN**: 应用层
- **PPTP、L2TP**: 已不推荐
- 协议: OpenVPN、WireGuard

## 十一、性能优化与高可用

### 11.1 CDN (内容分发网络)

- **原理**: 将内容缓存到离用户最近的边缘节点
- **加速类型**: 静态加速、动态加速、流媒体加速
- **关键技术**: 智能调度、缓存策略、回源机制

### 11.2 负载均衡

#### 11.2.1 四层负载均衡 (L4)
- 基于 IP + 端口
- 工作在传输层
- 性能高,功能简单
- 实现: LVS (DR/NAT/TUN)、HAProxy

#### 11.2.2 七层负载均衡 (L7)
- 基于 URL、Header、Cookie
- 工作在应用层
- 性能略低,功能丰富
- 实现: Nginx、HAProxy、Apache

#### 11.2.3 负载均衡算法

- **轮询 (Round Robin)**
- **加权轮询 (Weighted Round Robin)**
- **最少连接 (Least Connections)**
- **加权最少连接**
- **IP Hash (会话保持)**
- **一致性哈希**

### 11.3 高可用架构

- **主备模式**: Keepalived + VIP
- **集群模式**: 多节点同时提供服务
- **异地多活**: 多机房容灾
- **限流**: 令牌桶、漏桶、滑动窗口
- **熔断降级**: Sentinel、Hystrix
- **超时与重试**: 合理设置避免雪崩

### 11.4 连接池与池化技术

- 数据库连接池 (Druid、HikariCP)
- HTTP 连接池 (HttpClient)
- 线程池

### 11.5 长连接与短连接

| 对比 | 短连接 | 长连接 |
|------|--------|--------|
| 建立次数 | 每次请求都建立 | 复用连接 |
| 性能 | 差 | 好 |
| 资源占用 | 低 | 高 |
| 适用 | 低频请求 | 高频请求 |

**HTTP Keep-Alive**: HTTP/1.1 默认开启
**WebSocket**: 真正的长连接

```
   ↑
TIME_WAIT → CLOSE_WAIT ← LAST_ACK ← CLOSE_WAIT
```
