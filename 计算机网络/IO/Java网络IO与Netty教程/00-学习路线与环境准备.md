# 零、学习路线与环境准备

## 0.1 版本基线

本教程使用：

- JDK 21（LTS）；
- Maven 3.9+；
- Netty `4.1.136.Final`；
- JUnit 5.12.2。

截至 2026-08-03，Netty 官网同时提供 `4.2.16.Final`（新项目推荐）和 `4.1.136.Final`（稳定）。教程选择 4.1 是因为它仍广泛存在于 Spring、RPC 和消息中间件生态中，资料与兼容性更成熟；核心概念可以平滑迁移到 4.2。生产项目应结合依赖树和安全公告选择版本，不要机械复制教程版本。

## 0.2 三遍学习法

第一遍只运行示例，观察线程名、事件顺序和输入输出；第二遍自己删掉 Handler 重新写；第三遍故意制造半包、慢客户端、业务阻塞和异常长度，再解释现象。

```text
能运行
  -> 能画出事件流
     -> 能解释每个 API
        -> 能处理错误路径
           -> 能做取舍
```

Netty 专项建议在进入第六章前增加一小步：先读 [[00B-Netty从0到1案例式入门]] 开头的“接电话前台”故事，再读 [[00A-Netty新手术语与读代码指南]]。前者先建立直觉，后者再把人话对应到专业名词。

## 0.4 Maven 依赖

```xml
<properties>
    <maven.compiler.release>21</maven.compiler.release>
    <netty.version>4.1.136.Final</netty.version>
</properties>

<dependency>
    <groupId>io.netty</groupId>
    <artifactId>netty-all</artifactId>
    <version>${netty.version}</version>
</dependency>
```

生产项目通常按需引入 `netty-buffer`、`netty-transport`、`netty-handler` 等模块，教程用 `netty-all` 是为了降低初学配置成本。

## 0.7 知识问答

**问：为什么不直接学 Netty API？**

答：如果不理解 TCP 字节流、NIO 就绪事件和 Reactor，遇到粘包、部分写、EventLoop 阻塞时只能靠猜。Netty 消除了样板代码，但没有消除网络本身的约束。

**问：学 Netty 必须先读 Linux epoll 源码吗？**

答：不必。先掌握 `Channel + EventLoop + Pipeline`，再理解 Netty 的 NIO/Epoll transport 差异。过早下潜内核会增加认知负担。

**问：教程版本旧了怎么办？**

答：先看官网版本状态和安全公告，再检查目标框架的依赖管理；升级后运行编解码器、连接生命周期和压力测试。不要只改版本号。
