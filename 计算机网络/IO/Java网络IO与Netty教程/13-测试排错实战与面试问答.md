# 十三、测试、排错、实战与面试问答

> 白话翻译：本章教你不要凭感觉猜问题。先用一个假的小通道测试每个工位，再用日志观察“货物在哪一步没继续走”。

## 13.1 用 EmbeddedChannel 测试 Handler

`EmbeddedChannel` 不需要真实端口，可精确控制入站/出站消息。完整测试：`示例代码/src/test/java/note/io/netty/protocol/MessageCodecTest.java`。

```java
@Test
void shouldDecodeFrameArrivingInThreeParts() {
    EmbeddedChannel channel = new EmbeddedChannel(
            new LengthFieldBasedFrameDecoder(
                    1024 * 1024 + 16, 12, 4, 0, 0),
            new MessageDecoder());

    ByteBuf frame = encodedFrame(new Message(1, 42, "hello"));
    assertFalse(channel.writeInbound(
            frame.readRetainedSlice(3)));
    assertFalse(channel.writeInbound(
            frame.readRetainedSlice(8)));
    assertTrue(channel.writeInbound(
            frame.readRetainedSlice(frame.readableBytes())));
    frame.release();

    Message decoded = channel.readInbound();
    assertEquals(42, decoded.requestId());
    assertEquals("hello", decoded.body());
    assertFalse(channel.finishAndReleaseAll());
}
```

必须测试：

- 一个完整帧；
- 每个可能头部边界处拆分；
- 多帧合并输入；
- 空正文、中文、多字节 UTF-8；
- 负数/超大长度、错误 magic/版本/类型；
- 连接关闭时剩余半包；
- 编码器与解码器往返；
- 引用计数最终归零。

## 13.2 LoggingHandler 的位置决定你看见什么

```java
pipeline.addLast("wireLog", new LoggingHandler(LogLevel.DEBUG));
pipeline.addLast("frame", frameDecoder);
pipeline.addLast("codecLog", new BusinessMessageLogHandler());
```

`wireLog` 看到原始字节，适合协议排错但可能包含敏感数据；业务日志看到解码对象，适合 requestId 与状态。生产环境不要长期开启大流量十六进制转储。

## 13.3 常见故障速查

| 现象 | 优先检查 | 常见原因 |
| --- | --- | --- |
| 客户端连接但收不到响应 | flush、编码器方向、EventLoop | 只 write 未 flush；`ctx.write` 绕过编码器；Handler 阻塞 |
| CPU 单核拉满 | OP_WRITE/空转、异常循环 | 永久可写事件；解码器未消费字节却反复输出 |
| Direct Memory 增长 | refCnt、异步保存 ByteBuf | 漏 release；切片未 retain；出站失败路径未释放 |
| 偶发乱码/协议错位 | 帧边界、Charset、共享状态 | 先字符串解码再分帧；错误长度；共享解码器字段 |
| 连接定时断开 | IdleState、代理/NAT、GC | 心跳阈值过小；中间设备超时；长停顿 |
| 内存随慢客户端增长 | isWritable、队列上限 | 无背压；业务继续生产；水位只监控未限流 |
| `IllegalReferenceCountException` | 自动释放与 retain | SimpleHandler 中重复 release；异步使用未 retain |
| `UnsupportedOperationException` | 出站类型与编码器位置 | String/POJO 绕过相应 Encoder |

## 13.4 实战项目：渐进式聊天室

不要一次写完，按里程碑演进：

1. **Echo**：换行协议，能连接和回显。
2. **二进制协议**：接入第 10 章长度字段、requestId 和最大帧。
3. **登录状态**：用 Channel Attribute 保存用户身份，未登录只允许认证消息。
4. **会话管理**：使用 `ChannelGroup` 广播；同账号重复登录策略明确。
5. **心跳**：Ping/Pong 与最后有效业务时间。
6. **离线语义**：消息 ID、ACK、幂等去重；明确“送达连接”不等于“用户已读”。
7. **背压**：限制单连接请求、待写字节和广播扇出。
8. **安全**：TLS、认证失败限速、帧/字段限制、日志脱敏。
9. **测试**：EmbeddedChannel 协议测试、真实 Socket 集成测试、慢客户端测试。
10. **观测**：连接、延迟、错误、任务队列、不可写 Channel 和内存指标。

### 广播代码

```java
private static final ChannelGroup ONLINE =
        new DefaultChannelGroup(GlobalEventExecutor.INSTANCE);

@Override
public void channelActive(ChannelHandlerContext ctx) {
    ONLINE.add(ctx.channel());
}

private void broadcast(Message message) {
    ONLINE.writeAndFlush(message,
            channel -> channel.isActive() && channel.isWritable());
}
```

真实系统不能只跳过不可写连接：还要定义补偿、断开、降级或离线存储语义。

## 13.5 知识问答：高频面试题

**1. BIO、NIO、AIO 的核心区别？**

BIO 让线程等待 IO；NIO 用非阻塞 Channel 和 Selector 处理就绪事件；AIO 发起操作后消费完成结果。三者的 API、线程和通知模型不同。

**2. Netty 的 Reactor 模型如何落地？**

`NioEventLoop` 驱动 Selector 与任务队列；boss 接收连接，worker 管理子 Channel；事件经每条 Channel 的 Pipeline 传播。

**3. 一个 Channel 为什么通常绑定一个 EventLoop？**

保证连接级事件有序，减少锁和并发状态复杂度；一个 EventLoop 仍可管理多个 Channel。

**4. Netty 如何解决粘包拆包？**

不是“修复 TCP”，而是按应用协议用固定长度、分隔符、长度字段或自定义累积解码器恢复帧。

**5. ByteBuf 相比 ByteBuffer 的优势？**

双游标、池化、直接内存、动态容量、组合/切片视图和引用计数，更适合高性能网络生命周期。

**6. 为什么会发生内存泄漏？**

引用计数对象在被 Handler 消费、丢弃或异步保存后没有成对 release；或视图与父缓冲区生命周期处理错误。

**7. `ChannelInboundHandlerAdapter` 与 `SimpleChannelInboundHandler` 的释放差异？**

前者默认不自动释放；后者默认在处理完匹配类型后释放，继续传播需 retain。

**8. `ctx.write` 和 `channel.write` 的区别？**

前者从当前 Context 向前传播，后者从 Pipeline Tail 开始，经过的出站 Handler 范围不同。

**9. 为什么不能阻塞 EventLoop？**

同一 EventLoop 管理多条连接，阻塞会延迟它们的 IO、任务和定时器，形成队头阻塞。

**10. 如何处理耗时业务？**

使用有界业务执行器或真正的异步客户端；完成后回到连接执行器更新状态。必须带超时、拒绝、取消和过期结果处理。

**11. 什么是 Netty 背压？**

通过待写水位、`isWritable`、AUTO_READ、队列上限和上游流控，让生产速度服从消费能力；水位信号本身不是完整策略。

**12. `writeAndFlush` 成功代表什么？**

代表本地异步出站操作成功，不代表对端应用处理。业务确认需要协议 ACK。

**13. TCP keepalive 和 IdleStateHandler 的区别？**

前者是操作系统 TCP 探测，周期与能力受平台控制；后者是 Netty 应用层空闲事件，可配合业务 Ping/Pong。

**14. 零拷贝有哪些形式？**

`FileRegion/transferTo` 减少文件发送复制，`CompositeByteBuf` 避免合并复制，`slice/duplicate` 创建共享视图。它们解决的复制层次不同。

**15. 如何选择 Netty 线程数？**

以默认值建立基线，根据 CPU、EventLoop 忙碌度、任务延迟和真实负载压测；IO 线程与阻塞业务线程分开估算。

**16. 为什么解码器必须限制最大帧？**

防止恶意/错误长度导致无限累积、超大分配和拒绝服务。

**17. Netty 如何保证线程安全？**

它保证 Channel 操作被调度到对应 EventLoop 并提供有序事件，但不自动保证用户共享对象和跨 Channel 状态安全。

**18. 如何优雅关闭？**

停止接入，停止上游生产，等待在途请求到截止时间，关闭 Channel，最后 `shutdownGracefully` EventLoopGroup，并处理超时兜底。

**19. 如何定位 EventLoop 卡顿？**

结合线程栈、任务队列延迟、慢 Handler 埋点、GC 停顿和阻塞调用；不要只看网络吞吐。

**20. Netty 4.1 与 4.2 怎么选？**

新项目先看官网推荐和依赖生态；存量项目检查框架约束、安全公告和行为兼容，升级必须配合协议、连接、压力和内存测试。
