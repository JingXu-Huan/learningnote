当 Redis 的内存被占满时，它不会“爆炸”或“自动扩容”，而是根据配置好的**内存淘汰策略（Eviction Policy）**来决定该怎么办。
 换句话说，Redis 遇到内存不足时的反应，完全取决于你事先给它的指令。

我们来完整拆解这一过程。

------

### 一、前提：Redis 的内存限制

在配置文件中，Redis 通过 `maxmemory` 参数控制可使用的最大内存，例如：

```
maxmemory 512mb
```

这表示 Redis 最多只能用 512 MB 的内存（包括数据、缓冲区、元信息等）。

当内存使用量超过这个阈值时，Redis 就会触发“内存淘汰机制”。

------

### 二、Redis 内存满的两种情况

#### ① **没有设置 maxmemory**

Redis 默认可以无限使用内存，直到系统 OOM（Out Of Memory）。
 这时：

- 操作系统可能会直接 **杀掉 Redis 进程（OOM Killer）**
- 或 Redis 自己抛出 `OOM command not allowed` 错误

在生产环境中绝对不能不设上限！

------

#### ② **设置了 maxmemory**

这时 Redis 会按照 **内存淘汰策略** 处理。

------

### 三、Redis 的内存淘汰策略

通过配置：

```
maxmemory-policy <policy>
```

Redis 提供了 **8 种策略**（从 Redis 4.0 起）。

| 策略名称            | 说明                                                 |
| ------------------- | ---------------------------------------------------- |
| **noeviction**      | （默认）内存满时不再写入，直接报错。                 |
| **volatile-lru**    | 从设置了过期时间的 key 中，淘汰最久未使用的（LRU）。 |
| **volatile-lfu**    | 从设置了过期时间的 key 中，淘汰最少使用的（LFU）。   |
| **volatile-ttl**    | 从设置了过期时间的 key 中，优先淘汰 TTL 最短的。     |
| **volatile-random** | 从设置了过期时间的 key 中，随机淘汰。                |
| **allkeys-lru**     | 从所有 key 中，淘汰最久未使用的（LRU）。             |
| **allkeys-lfu**     | 从所有 key 中，淘汰最少使用的（LFU）。               |
| **allkeys-random**  | 从所有 key 中，随机淘汰。                            |

------

### 四、实际场景选择建议

| 应用场景             | 推荐策略                             |
| -------------------- | ------------------------------------ |
| 缓存系统（典型用途） | `allkeys-lru`（最常用）              |
| 热点数据访问频繁     | `allkeys-lfu`（新版本更精准）        |
| 数据需持久保存       | `noeviction`（防止误删）             |
| 临时会话缓存         | `volatile-ttl`（更快释放即将过期的） |

------

### 五、Redis 淘汰是如何执行的

Redis 不会在每次写入时都全表扫描，而是使用**采样淘汰**算法。

以 LRU 为例：

- Redis 随机采样若干个 key（默认 5 个）；
- 找出其中“最久未使用”的；
- 删除；
- 继续采样直到内存低于阈值。

因此，这个淘汰是“近似 LRU/LFU”，不是完美的精确算法。

------

### 六、常见错误与后果

| 情况                | 后果                                          |
| ------------------- | --------------------------------------------- |
| 没设 `maxmemory`    | Redis 会占满物理内存，被系统杀掉              |
| 用默认 `noeviction` | 缓存写入失败，报错：`OOM command not allowed` |
| 写入速率过快        | 即使开启 LRU，也可能频繁淘汰导致性能波动      |
| key 无 TTL          | `volatile-*` 策略无法生效（因为没过期时间）   |

------

### 七、总结一句话

> 当 Redis 内存满时，它不会神奇扩容，而是根据 `maxmemory-policy` 来“删旧腾新”或“拒绝写入”。
>  想稳定运行，必须：
>  **设内存上限、选合适淘汰策略、配合 TTL 管理生命周期。**
